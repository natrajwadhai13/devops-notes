# Module 18: Scheduling in Bash

Scheduling allows scripts to run **automatically** at a specified time or interval without manual intervention.

It is widely used for:

* Daily backups
* Log cleanup
* Health checks
* Database backups
* Report generation
* Monitoring
* Automated deployments

---

# Scheduling Tools

| Tool           | Purpose                    |
| -------------- | -------------------------- |
| `cron`         | Run recurring jobs         |
| `crontab`      | Manage cron jobs           |
| `at`           | Run a one-time job         |
| Automated Jobs | Real-world scheduled tasks |

---

# 1. cron

`cron` is a Linux service that runs scheduled jobs automatically.

It continuously checks the **crontab** file and executes commands at the scheduled time.

Check cron service

RHEL/CentOS

```bash
systemctl status crond
```

Ubuntu

```bash
systemctl status cron
```

Start cron service

RHEL/CentOS

```bash
sudo systemctl start crond
```

Ubuntu

```bash
sudo systemctl start cron
```

Enable on boot

```bash
sudo systemctl enable crond
```

Ubuntu

```bash
sudo systemctl enable cron
```

---

# Cron Time Format

```text
* * * * * command
│ │ │ │ │
│ │ │ │ └── Day of Week (0-7)
│ │ │ └──── Month (1-12)
│ │ └────── Day of Month (1-31)
│ └──────── Hour (0-23)
└────────── Minute (0-59)
```

---

# Cron Special Characters

| Symbol | Meaning         |
| ------ | --------------- |
| `*`    | Every value     |
| `,`    | Multiple values |
| `-`    | Range           |
| `/`    | Step value      |

Example

```bash
*/5 * * * * command
```

Runs every **5 minutes**.

# 2. crontab

`crontab` manages cron jobs for a user.

---

## Edit Cron Jobs

```bash
crontab -e
```

---

## List Cron Jobs

```bash
crontab -l
```

---

## Remove All Cron Jobs

```bash
crontab -r
```

⚠️ Deletes all scheduled jobs for the current user.

---

```text

```

```text

```

```text

/etc/cron.daily/
```

# Environment Variables in Cron

Cron runs with a minimal environment.

Always use:

* Absolute paths
* Full command paths

Good

```bash
/usr/bin/date
```

Better script

```bash
#!/bin/bash

PATH=/usr/local/bin:/usr/bin:/bin

date
```

# 3. at Command

`at` schedules a command to run **only once** at a specified time.

---

## Install (if needed)

RHEL/CentOS

```bash

```

Ubuntu

```bash

```

---

## Start Service

```bash
sudo systemctl start atd
```

---

## Schedule a Job

```bash
at 10:30 PM
```

Then type

```bash
echo "Backup Started"
```

Finish with

```text
Ctrl + D
```

---

```bash

```

---

## Run Tomorrow

```bash

```

---

## Run Next Week

```bash
at 9 AM next monday
```

---

## View Scheduled Jobs

```bash

```

---

## Remove Job

```bash

```

---

# Difference: cron vs at

| cron                          | at                            |
| ----------------------------- | ----------------------------- |
| Repeated execution            | One-time execution            |
| Uses crontab                  | Uses at queue                 |
| Background scheduling service | Background scheduling service |
| Best for recurring tasks      | Best for one-time tasks       |

# Complete Backup Script

```bash
#!/bin/bash

SOURCE="/home/user/data"

DEST="/backup"

DATE=$(date +%F)

cp -r "$SOURCE" "$DEST/backup_$DATE"

echo "Backup Completed"
```

Cron Entry

```bash
0 2 * * * /home/user/backup.sh >> backup.log 2>&1
```

# Best Practices

* Always use **absolute paths** in cron jobs.
* Redirect output to a log file for troubleshooting:

```bash
/script.sh >> script.log 2>&1
```

* Ensure scripts have execute permission:

```bash
chmod +x script.sh
```

* Test scripts manually before scheduling them.
* Use environment variables like `PATH` explicitly if your script depends on commands outside the default cron environment.
* Prefer cron for recurring tasks and `at` for one-time tasks.

# Interview Questions

### 1. What is cron?

A background scheduling service that executes recurring tasks automatically based on a defined schedule.

---

### 2. What is crontab?

`crontab` is the command used to create, edit, list, and remove a user's scheduled cron jobs.

---

### 3. What is the difference between `cron` and `crontab`?

| `cron`                    | `crontab`                        |
| ------------------------- | -------------------------------- |
| Background daemon/service | Command used to manage cron jobs |
| Executes scheduled jobs   | Creates and edits schedules      |

---

### 4. What is the difference between `cron` and `at`?

| `cron`                | `at`                      |
| --------------------- | ------------------------- |
| Recurring jobs        | One-time jobs             |
| Uses cron expressions | Uses a specific date/time |

---

### 5. How do you edit cron jobs?

```bash
crontab -e
```

---

### 6. How do you list all cron jobs?

```bash
crontab -l
```

---

### 7. How do you schedule a script to run every day at **2:00 AM**?

```bash
0 2 * * * /path/to/script.sh
```

---

### 8. Why should you use absolute paths in cron jobs?

Because cron runs with a minimal environment and may not have the same `PATH` variable as an interactive shell. Using absolute paths ensures the correct script and commands are executed.

---

### 9. Where are system-wide cron jobs typically stored?

* `/etc/crontab`
* `/etc/cron.hourly/`
* `/etc/cron.daily/`
* `/etc/cron.weekly/`
* `/etc/cron.monthly/`

> **Interview Tip:** The most frequently asked scheduling questions are:
>
> * Cron time format (`* * * * *`)
> * `cron` vs `crontab`
> * `cron` vs `at`
> * `crontab -e`, `-l`, `-r`
> * Why cron jobs fail (missing execute permission, missing shebang, relative paths, missing environment variables, incorrect permissions).
