# Module 12: Command Line Arguments

Command Line Arguments (CLI Arguments) are values passed to a shell script when it is executed.

Instead of asking the user for input using `read`, values can be supplied directly on the command line.

Example:

```bash
bash script.sh Linux Docker Kubernetes
```

Here:

* `script.sh` → Script name
* `Linux` → First argument
* `Docker` → Second argument
* `Kubernetes` → Third argument

---

# Positional Parameters

Positional parameters store command-line arguments.

| Variable | Description                 |
| -------- | --------------------------- |
| `$0`     | Script name                 |
| `$1`     | First argument              |
| `$2`     | Second argument             |
| `$3`     | Third argument              |
| `$4-$9`  | Fourth to Ninth argument    |
| `${10}`  | Tenth argument              |
| `$#`     | Total number of arguments   |
| `$*`     | All arguments as one string |
| `$@`     | All arguments separately    |

---

## Example

```bash
#!/bin/bash

echo "Script Name      : $0"
echo "First Argument   : $1"
echo "Second Argument  : $2"
echo "Third Argument   : $3"
```

Run

```bash
bash demo.sh Linux Docker Kubernetes
```

Output

```text
Script Name      : demo.sh
First Argument   : Linux
Second Argument  : Docker
Third Argument   : Kubernetes
```

# All Arguments

Using `$*`

```bash

```

Output

```text

```

---

Using `$@`

```bash

```

Output

```text
Linux Docker Kubernetes
```

---

# `$*` vs `$@`

Without quotes, both behave similarly.

```bash
echo $*
echo $@
```

---

With quotes, there is a difference.

### `$*`

```bash
for item in "$*"
do
    echo "$item"
done
```

Output

```text
Linux Docker Kubernetes
```

(All arguments become one string.)

---

### `$@`

```bash
for item in "$@"
do
    echo "$item"
done
```

Output

```text
Linux
Docker
Kubernetes
```

(Each argument remains separate.)

> **Best Practice:** Use **`"$@"`** when passing all arguments to another command or looping through them.

---

# Arguments Above 9

Use braces for arguments after `$9`.

```bash
#!/bin/bash

echo "${10}"
echo "${11}"
```

Run

```bash
bash demo.sh a b c d e f g h i j k
```

Output

```text
j
k
```

# shift Command

The `shift` command removes the first positional parameter and shifts the remaining arguments to the left.

Before shift

```text
$1 = Linux
$2 = Docker
$3 = Kubernetes
```

After `shift`

```text
$1 = Docker
$2 = Kubernetes
```

---

## Syntax

```bash
shift
```

or

```bash
shift N
```

Move multiple positions.

---

## Example

```bash
#!/bin/bash

echo "Before Shift"

echo "$1"
echo "$2"
echo "$3"

shift

echo

echo "After Shift"

echo "$1"
echo "$2"
```

Run

```bash
bash demo.sh Linux Docker Kubernetes
```

Output

```text
Before Shift

Linux
Docker
Kubernetes

After Shift

Docker
Kubernetes
```

---

## Process All Arguments Using shift

```bash
#!/bin/bash

while [ $# -gt 0 ]
do
    echo "$1"
    shift
done
```

Run

```bash
bash demo.sh Linux Docker Kubernetes
```

Output

```text
Linux
Docker
Kubernetes
```

# getopts

`getopts` is a built-in Bash command used to process command-line options.

It supports options like:

```text
-v
-f
-u
-p
-h
```

It is the recommended way to parse command-line options.

---

## Syntax

```bash
while getopts "options" option
do
    case $option in

        option)
            commands
            ;;

    esac
done
```

---

## Example

```bash
#!/bin/bash

while getopts "n:a:" opt
do

    case $opt in

        n)
            name=$OPTARG
            ;;

        a)
            age=$OPTARG
            ;;

    esac

done

echo "Name : $name"
echo "Age  : $age"
```

Run

```bash
bash demo.sh -n Natraj -a 32
```

Output

```text
Name : Natraj
Age  : 32
```

---

## Understanding `:`

```bash
"n:a:"
```

Means:

```text
-n requires a value
-a requires a value
```

Without `:`

```bash
"hv"
```

Means:

```text
-h
-v
```

No values required.

---

# Built-in Variables Used by getopts

| Variable | Description                       |
| -------- | --------------------------------- |
| `OPTARG` | Stores the option's value         |
| `OPTIND` | Index of the next argument        |
| `OPTERR` | Controls automatic error messages |

---

## Help Option Example

```bash
#!/bin/bash

while getopts "hn:" opt
do

    case $opt in

        h)
            echo "Usage: demo.sh -n NAME"
            exit 0
            ;;

        n)
            echo "Hello $OPTARG"
            ;;

    esac

done
```

Run

```bash
bash demo.sh -h
```

Output

```text
Usage: demo.sh -n NAME
```

# Option Parsing

Option parsing means processing command-line options such as:

```text
-h
-v
-f filename
-u username
```

---

## Example

```bash
#!/bin/bash

while getopts "f:u:" opt
do

    case $opt in

        f)

            file=$OPTARG
            ;;

        u)

            user=$OPTARG
            ;;

        *)

            echo "Invalid Option"
            exit 1
            ;;

    esac

done

echo "File : $file"
echo "User : $user"
```

Run

```bash
bash demo.sh -f backup.txt -u natraj
```

Output

```text
File : backup.txt
User : natraj
```

---

# Complete Example

```bash
#!/bin/bash

while getopts "n:c:" opt
do

    case $opt in

        n)

            name=$OPTARG
            ;;

        c)

            city=$OPTARG
            ;;

        *)

            echo "Usage: demo.sh -n NAME -c CITY"
            exit 1
            ;;

    esac

done

echo "Name : $name"
echo "City : $city"
```

Run

```bash
bash demo.sh -n Natraj -c Pune
```

Output

```text
Name : Natraj
City : Pune
```

# Real-World DevOps Example

## Backup Script with Options

```bash
#!/bin/bash

while getopts "s:d:" opt
do

    case $opt in

        s)
            SOURCE=$OPTARG
            ;;

        d)
            DEST=$OPTARG
            ;;

    esac

done

cp -r "$SOURCE" "$DEST"

echo "Backup Completed"
```

Run

```bash
bash backup.sh -s /etc -d /backup
```

| `$*`      | All arguments as one string                 |
| `$@`      | All arguments separately                    |

| `getopts` | Parses command-line options                 |
| `OPTARG`  | Stores option value                         |
| `OPTIND`  | Current option index                        |

---

# Best Practices

* Use **`"$@"`** instead of **`"$*"`** when forwarding or looping through arguments.
* Use `getopts` for professional scripts instead of manually checking `$1`, `$2`, etc.
* Validate required arguments before processing.
* Provide a `-h` or `--help` option for usage instructions.
* Quote variables to safely handle spaces:

```bash
cp "$SOURCE" "$DEST"
```

# Interview Questions

### 1. What are command-line arguments?

Values passed to a script when it is executed.

---

### 2. What is the difference between `$0` and `$1`?

* `$0` → Script name
* `$1` → First command-line argument

---

### 3. What does `shift` do?

It removes the first positional parameter and shifts all remaining arguments one position to the left.

---

### 4. What is `getopts` used for?

It is a built-in Bash utility used to parse command-line options like `-f`, `-u`, and `-h`.

---

### 5. What is `OPTARG`?

`OPTARG` contains the value associated with the current option processed by `getopts`.

---

### 6. What is the difference between `$*` and `$@`?

* `"$*"` combines all arguments into a **single string**.
* `"$@"` preserves each argument as a **separate item**.

---

### 7. How do you access the tenth command-line argument?

```bash
echo "${10}"
```

---

### 8. Why is `getopts` preferred over manually checking `$1`, `$2`, etc.?

Because it provides structured, reliable parsing of command-line options, supports option values, handles invalid options more cleanly, and makes scripts easier to maintain.
