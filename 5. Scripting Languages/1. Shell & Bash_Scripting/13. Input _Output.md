# Module 13: Input / Output (I/O)

Input and Output (I/O) are fundamental concepts in Linux and Shell Scripting.

Every Linux command uses three standard streams:

| Stream     | File Descriptor (FD) | Description     |
| ---------- | -------------------- | --------------- |
| **stdin**  | `0`                  | Standard Input  |
| **stdout** | `1`                  | Standard Output |
| **stderr** | `2`                  | Standard Error  |

```text
                Keyboard
                   │
                   ▼
            Standard Input
              stdin (0)
                   │
                   ▼
              Shell Command
              /           \
             /             \
            ▼               ▼
    stdout (1)         stderr (2)
   Standard Output    Error Output
            │               │
            ▼               ▼
         Terminal        Terminal
```

---

# 1. stdin (Standard Input)

`stdin` is the default input stream.

By default, Linux reads input from the **keyboard**.

File Descriptor

```text
0
```

---

## Example 1

```bash
cat
```

Input

```text
Hello Linux
```

Output

```text
Hello Linux
```

Stop with

```text
Ctrl + D
```

---

## Example 2

```bash
read name

echo "$name"
```

Input comes from the keyboard.

---

# Input Redirection (`<`)

Instead of reading from the keyboard, input can come from a file.

## Syntax

```bash
command < file
```

---

## Example

`numbers.txt`

```text
10
20
30
```

Command

```bash
cat < numbers.txt
```

Output

```text
10
20
30
```

---

# 2. stdout (Standard Output)

`stdout` is the normal output produced by a command.

File Descriptor

```text
1
```

By default, stdout is displayed on the terminal.

---

## Example

```bash
pwd
```

Output

```text
/home/natraj
```

---

# Output Redirection (`>`)

Redirect output to a file.

## Syntax

```bash
command > file
```

---

## Example

```bash
date > today.txt
```

Instead of displaying the date on the terminal, it is written to `today.txt`.

---

## Verify

```bash
cat today.txt
```

---

# Append Output (`>>`)

Append output to an existing file.

## Syntax

```bash
command >> file
```

---

## Example

```bash
echo "Linux" > demo.txt

echo "Docker" >> demo.txt

echo "Kubernetes" >> demo.txt
```

Contents

```text
Linux
Docker
Kubernetes
```

---

# Difference: `>` vs `>>`

| Operator | Description                 |
| -------- | --------------------------- |
| `>`      | Overwrites existing content |
| `>>`     | Appends to existing content |

---

# 3. stderr (Standard Error)

Errors generated by commands are sent to **stderr**.

File Descriptor

```text
2
```

---

## Example

```bash
ls abc
```

Output

```text
ls: cannot access 'abc': No such file or directory
```

This message comes from **stderr**.

---

# Error Redirection (`2>`)

Redirect only errors to a file.

## Syntax

```bash
command 2> error.log
```

---

## Example

```bash
ls abc 2> error.log
```

Terminal

```text

```

(No error shown)

Check file

```bash
cat error.log
```

Output

```text
ls: cannot access 'abc': No such file or directory
```

---

# Redirect stdout and stderr Separately

```bash
ls demo.txt abc > output.txt 2> error.txt
```

- `output.txt` → Normal output
- `error.txt` → Error output

---

# Redirect Both stdout and stderr

## Method 1

```bash
command > output.txt 2>&1
```

---

## Method 2 (Recommended in Bash)

```bash
command &> output.txt
```

---

## Example

```bash
ls demo.txt abc &> result.txt
```

Both success and error messages go into `result.txt`.

---

# Discard Output

Linux provides a special device:

```text
/dev/null
```

Anything written to it is discarded.

---

## Ignore stdout

```bash
command > /dev/null
```

---

## Ignore stderr

```bash
command 2> /dev/null
```

---

## Ignore Everything

```bash
command > /dev/null 2>&1
```

---

# 4. Pipe (`|`)

A pipe sends the output of one command directly as the input to another command.

## Syntax

```bash
command1 | command2
```

---

## Example 1

```bash
ls -l | wc -l
```

Output

```text
15
```

---

## Example 2

```bash
cat demo.txt | grep Docker
```

Output

```text
Docker
```

---

## Example 3

```bash
ps -ef | grep nginx
```

---

## Example 4

```bash
df -h | grep "/dev/sda1"
```

---

# Multiple Pipes

```bash
cat users.txt | sort | uniq
```

Process Flow

```text
users.txt
     │
     ▼
   sort
     │
     ▼
   uniq
```

---

# 5. tee Command

`tee` displays output on the terminal **and** saves it to a file simultaneously.

## Syntax

```bash
command | tee file
```

---

## Example

```bash
date | tee today.txt
```

Output

```text
Sat Jul 26 21:15:00 IST 2026
```

The same output is also saved in `today.txt`.

---

## Append Using tee

```bash
command | tee -a file
```

---

## Example

```bash
echo "Linux" | tee demo.txt

echo "Docker" | tee -a demo.txt
```

Contents

```text
Linux
Docker
```

| Descriptor | Name   | Default Destination |
| ---------- | ------ | ------------------- |
| `0`        | stdin  | Keyboard            |
| `1`        | stdout | Terminal            |
| `2`        | stderr | Terminal            |

# Complete Example

```bash
#!/bin/bash

echo "========== System Information =========="

hostname | tee system.log

date | tee -a system.log

df -h | tee -a system.log

echo "Completed"
```

Output

```text
========== System Information ==========

server01

Sat Jul 26 21:15:00 IST 2026

Filesystem      Size Used Avail Use%
...

Completed
```

The same information is also stored in `system.log`.

# Quick Summary

| Operator | Purpose                             |
| -------- | ----------------------------------- |
| `<`      | Read input from file                |
| `>`      | Write output (overwrite)            |
| `>>`     | Append output                       |
| `2>`     | Redirect errors                     |
| `2>>`    | Append errors                       |
| `2>&1`   | Redirect stderr to stdout           |
| `&>`     | Redirect stdout and stderr together |
| `\|`     | Pipe output to another command      |
| `tee`    | Display and save output             |

---

# Best Practices

- Use `>` only when overwriting is intended.
- Use `>>` for log files to preserve previous data.
- Redirect errors to a separate log file for troubleshooting.
- Use `tee` when you need both terminal output and a saved log.
- Use `/dev/null` to suppress unnecessary output in automation scripts.
- Use pipes to combine small commands instead of writing long scripts.

# Interview Questions

### 1. What are the three standard streams in Linux?

| Stream | File Descriptor |
| ------ | --------------- |
| stdin  | `0`             |
| stdout | `1`             |
| stderr | `2`             |

---

### 2. What is the difference between `>` and `>>`?

- `>` overwrites a file.
- `>>` appends to an existing file.

---

### 3. What does `2>` do?

It redirects **standard error (stderr)** to a file.

Example:

```bash
ls invalid_file 2> error.log
```

---

### 4. What is the purpose of a pipe (`|`)?

A pipe passes the **stdout of one command** as the **stdin of another command**.

Example:

```bash
ps -ef | grep nginx
```

---

### 5. What is the purpose of the `tee` command?

It displays command output on the terminal and writes the same output to a file simultaneously.

---

### 6. What is `/dev/null`?

`/dev/null` is a special device that discards any data written to it. It is commonly used to suppress unwanted output or errors.

---

### 7. What is the difference between stdout and stderr?

- **stdout (1)**: Normal command output.
- **stderr (2)**: Error messages generated by commands.

---

### 8. How do you redirect both stdout and stderr to the same file?

```bash
command > output.log 2>&1
```

or, in Bash:

```bash
command &> output.log
```

> **Interview Tip:** Questions about **stdin/stdout/stderr**, **`>`, `>>`, `2>`**, **pipes**, and **`tee`** are among the most common Bash scripting interview topics, especially for Linux Administrator and DevOps roles.
