# Module 17: Logging & Debugging

Logging and debugging help identify, troubleshoot, and fix problems in shell scripts.

They are essential for:

* Finding script errors
* Tracking execution flow
* Recording script activity
* Error handling
* Production troubleshooting

---

# Why Logging & Debugging?

Without logging:

```text
Backup Failed
```

You don't know:

* Which file failed?
* At what time?
* Why did it fail?

With logging:

```text
2026-07-26 10:30:15 INFO  Backup Started

2026-07-26 10:30:18 ERROR Permission Denied

2026-07-26 10:30:20 Backup Failed
```

Now troubleshooting becomes much easier.

---

# 1. set -x (Debug Mode)

`set -x` displays every command before it is executed.

Useful for debugging.

---

## Syntax

```bash
set -x
```

---

## Example

```bash
#!/bin/bash

set -x

name="Linux"

echo "$name"

pwd
```

Output

```text
+ name=Linux

+ echo Linux

Linux

+ pwd

/home/user
```

Every command is displayed before execution.

---

## Disable Debugging

```bash
set +x
```

---

## Example

```bash
#!/bin/bash

set -x

echo "Debug ON"

set +x

echo "Debug OFF"
```

---

# 2. set -e

Stops the script immediately if any command returns a non-zero exit status.

Very useful in production scripts.

---

## Syntax

```bash
set -e
```

---

## Example Without set -e

```bash
#!/bin/bash

mkdir test

cd xyz

echo "Completed"
```

Output

```text
cd: xyz: No such file

Completed
```

The script continues.

---

## Example With set -e

```bash
#!/bin/bash

set -e

mkdir test

cd xyz

echo "Completed"
```

Output

```text
cd: xyz: No such file
```

The script stops immediately.

---

# 3. set -v

Displays each line of the script as it is read.

---

## Syntax

```bash
set -v
```

---

## Example

```bash
#!/bin/bash

set -v

echo "Linux"

pwd
```

Output

```text
echo "Linux"

Linux

pwd

/home/user
```

---

# Difference: set -x vs set -v

| `set -x`                             | `set -v`                            |
| ------------------------------------ | ----------------------------------- |
| Shows commands after shell expansion | Shows script lines before execution |
| Displays variable values             | Displays original script            |
| Best for debugging                   | Best for understanding script flow  |

---

# 4. trap

`trap` executes a command when a signal or event occurs.

Useful for:

* Cleanup
* Temporary file removal
* Logging
* Signal handling

---

## Syntax

```bash
trap "command" SIGNAL
```

---

## Example (Ctrl + C)

```bash
#!/bin/bash

trap 'echo "Script Interrupted"; exit' INT

while true
do
    sleep 1
done
```

Press

```text
Ctrl + C
```

Output

```text
Script Interrupted
```

---

## Cleanup Temporary File

```bash
#!/bin/bash

tempfile="/tmp/demo.txt"

touch "$tempfile"

trap 'rm -f "$tempfile"' EXIT

echo "Working..."
```

When the script exits, the temporary file is automatically removed.

---

## Common Signals

| Signal | Description         |
| ------ | ------------------- |
| `EXIT` | Script exits        |
| `INT`  | Ctrl + C            |
| `TERM` | Termination request |
| `HUP`  | Hangup              |
| `QUIT` | Quit signal         |

# 5. logger

`logger` writes messages to the system log (Syslog or Journald).

---

## Syntax

```bash
logger "Message"
```

---

## Example

```bash
logger "Backup Started"
```

---

## Custom Tag

```bash
logger -t BackupScript "Backup Completed"
```

---

## Verify Logs

On RHEL/CentOS

```bash
tail /var/log/messages
```

Ubuntu

```bash
journalctl -t BackupScript
```

---

## Script Example

```bash
#!/bin/bash

logger -t Backup "Backup Started"

cp -r /home/data /backup

logger -t Backup "Backup Completed"
```

# 6. Error Handling

Error handling prevents unexpected script failures.

Always check whether critical commands succeed.

---

## Using `$?`

```bash
cp test.txt backup.txt

if [ $? -eq 0 ]
then
    echo "Success"
else
    echo "Failed"
fi
```

---

## Better Method

```bash
if cp test.txt backup.txt
then
    echo "Backup Successful"
else
    echo "Backup Failed"
fi
```

This is cleaner and avoids checking `$?` separately.

---

## Exit with Custom Status

```bash
#!/bin/bash

if [ ! -f test.txt ]
then

    echo "File Not Found"

    exit 1

fi
```

---

## Function-Based Error Handling

```bash
#!/bin/bash

error_exit() {

    echo "ERROR: $1"

    exit 1

}

cp test.txt backup.txt || error_exit "Backup Failed"
```

# Logging to a File

```bash
#!/bin/bash

LOGFILE="/tmp/script.log"

echo "$(date) Script Started" >> "$LOGFILE"

echo "$(date) Backup Completed" >> "$LOGFILE"
```

---

# Redirect All Output to a Log File

```bash
#!/bin/bash

exec > script.log 2>&1

echo "Script Started"

pwd
```

Both normal output and errors are stored in `script.log`.

---

# Complete Example

```bash
#!/bin/bash

set -e

LOGFILE="/tmp/backup.log"

exec >> "$LOGFILE" 2>&1

logger -t Backup "Backup Started"

cp -r /etc /backup

logger -t Backup "Backup Completed"

echo "Success"
```

# Quick Summary

| Command            | Purpose                            |
| ------------------ | ---------------------------------- |
| `set -x`           | Show executed commands (debugging) |
| `set +x`           | Disable debugging                  |
| `set -e`           | Exit script on first error         |
| `set -v`           | Show script lines before execution |
| `trap`             | Execute command on signal/event    |
| `logger`           | Write messages to system logs      |
| `exec > file 2>&1` | Redirect all output to a log file  |
| `exit N`           | Exit script with a status code     |

---

# Best Practices

* Use `set -e` in production scripts to avoid continuing after critical failures.
* Enable `set -x` only during debugging or troubleshooting.
* Use `trap` to clean up temporary files and release resources.
* Record important events with `logger` or a dedicated log file.
* Handle command failures immediately using `if` or `||`.
* Use meaningful exit codes:

  * `0` = Success
  * Non-zero = Error

# Interview Questions

### 1. What is the purpose of `set -x`?

It displays each command after shell expansion and before execution, making debugging easier.

---

### 2. What is the purpose of `set -e`?

It stops the script immediately when a command exits with a non-zero status.

---

### 3. What is the difference between `set -x` and `set -v`?

| `set -x`                                 | `set -v`                                         |
| ---------------------------------------- | ------------------------------------------------ |
| Shows expanded commands before execution | Shows the original script lines as they are read |
| Useful for debugging variable values     | Useful for understanding script flow             |

---

### 4. What is `trap` used for?

It executes a specified command when the script receives a signal or exits, commonly used for cleanup and signal handling.

---

### 5. What does the `logger` command do?

It writes messages to the system logging service (Syslog/Journald).

---

### 6. How do you redirect all script output to a log file?

```bash
exec > script.log 2>&1
```

---

### 7. What is a good way to handle command failures?

```bash
command || {
    echo "Command failed"
    exit 1
}
```

or

```bash
if command
then
    echo "Success"
else
    echo "Failed"
fi
```

---

### 8. Why should temporary files be cleaned up using `trap`?

Because `trap` ensures cleanup happens even if the script exits unexpectedly (for example, due to an error or `Ctrl + C`), preventing leftover temporary files.
