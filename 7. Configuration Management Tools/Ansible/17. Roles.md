# 17. Roles

## Learning Objectives

After completing this chapter, you will be able to:

- Understand what Ansible Roles are.
- Learn the standard Role directory structure.
- Use defaults, vars, tasks, handlers, templates, files, and meta.
- Understand Role dependencies.
- Install and use Galaxy Roles.
- Follow Role best practices.

---

# What is a Role?

A **Role** is a standardized way to organize Playbooks, variables, templates, handlers, and files into reusable components.

Instead of writing one large Playbook, Roles divide automation into smaller, manageable parts.

Example:

```
Web Server Role

↓

Install Package

↓

Copy Configuration

↓

Start Service

↓

Restart if Needed
```

---

# Why Use Roles?

Without Roles

```
playbook.yml

1000+ lines
```

Hard to maintain.

---

With Roles

```
roles/

├── nginx/

├── mysql/

├── docker/

└── users/
```

Each Role performs one specific task.

---

# Benefits of Roles

- Reusable
- Organized
- Easy to maintain
- Easy to test
- Team collaboration
- Production-ready
- Scalable

# Standard Role Structure

```
roles/

└── nginx/

    ├── defaults/

    │   └── main.yml

    ├── files/

    ├── handlers/

    │   └── main.yml

    ├── meta/

    │   └── main.yml

    ├── tasks/

    │   └── main.yml

    ├── templates/

    ├── tests/

    ├── vars/

    │   └── main.yml

    └── README.md
```

---

# Create a Role

Generate a new Role using Ansible.

```bash
ansible-galaxy role init nginx
```

Example Output

```
roles/

└── nginx/

    ├── defaults/

    ├── files/

    ├── handlers/

    ├── meta/

    ├── tasks/

    ├── templates/

    ├── tests/

    ├── vars/
```

---

# tasks/

Contains the main automation tasks.

Example

```yaml
# tasks/main.yml

- name: Install Nginx

  package:
    name: nginx

    state: present
```

---

# handlers/

Contains Handlers triggered by `notify`.

Example

```yaml
# handlers/main.yml

- name: Restart Nginx

  service:
    name: nginx

    state: restarted
```

---

# defaults/

Stores default variable values.

Example

```yaml
# defaults/main.yml

http_port: 80

service_name: nginx
```

These variables have the **lowest precedence**.

---

# vars/

Stores variables that should rarely change.

Example

```yaml
# vars/main.yml

package_name: nginx
```

These variables have **higher precedence** than `defaults`.

---

# templates/

Stores Jinja2 templates.

Example

```
templates/

└── nginx.conf.j2
```

Deploy using:

```yaml
template:
  src: nginx.conf.j2

  dest: /etc/nginx/nginx.conf
```

---

# files/

Stores static files.

Example

```
files/

├── index.html

├── logo.png

└── banner.jpg
```

Copy using:

```yaml
copy:
  src: index.html

  dest: /var/www/html/index.html
```

---

# meta/

Stores Role metadata and dependencies.

Example

```yaml
# meta/main.yml

dependencies:
  - role: common

  - role: firewall
```

---

# Role Dependencies

A Role can automatically execute another Role before it runs.

Example

```
common

↓

firewall

↓

nginx
```

Useful when one Role depends on another.

---

# Using a Role

Playbook

```yaml
---
- hosts: web

  become: true

  roles:
    - nginx
```

Multiple Roles

```yaml
roles:
  - common

  - docker

  - nginx

  - monitoring
```

Roles execute from top to bottom.

---

# Role Execution Order

```
Playbook

↓

Role

↓

Tasks

↓

Handlers

↓

Complete
```

# Ansible Galaxy

**Ansible Galaxy** is the official repository for reusable Roles and Collections.

It allows you to download community-created Roles instead of writing everything from scratch.

---

# Search Galaxy Roles

```bash
ansible-galaxy search nginx
```

---

# Install a Galaxy Role

```bash
ansible-galaxy role install geerlingguy.nginx
```

---

# List Installed Roles

```bash
ansible-galaxy role list
```

---

# Remove a Role

```bash
ansible-galaxy role remove geerlingguy.nginx
```

---

# Galaxy Collections

Collections provide Roles, Modules, Plugins, and Documentation.

Install a Collection

```bash
ansible-galaxy collection install amazon.aws
```

List Installed Collections

```bash
ansible-galaxy collection list
```

---

# Best Practices

- One Role should have one responsibility.
- Keep Roles small and reusable.
- Store defaults in `defaults/`.
- Store templates in `templates/`.
- Store static files in `files/`.
- Use Handlers instead of restarting services repeatedly.
- Keep Role names meaningful.
- Reuse community Roles when appropriate.

# Summary

- Roles organize Ansible code into reusable components.
- Each Role has a standard directory structure.
- `tasks/` contains automation tasks.
- `handlers/` contains service restart logic.
- `defaults/` stores default variables.
- `vars/` stores higher-precedence variables.
- `templates/` stores Jinja2 templates.
- `files/` stores static files.
- `meta/` defines Role dependencies.
- Ansible Galaxy provides reusable Roles and Collections.
