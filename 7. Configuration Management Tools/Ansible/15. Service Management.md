# 15. Service Management

## Learning Objectives

After completing this chapter, you will be able to:

- Understand Service Management in Ansible.
- Manage Linux services.
- Start, stop, restart, and reload services.
- Enable or disable services at boot.
- Reboot managed nodes.
- Wait for services and ports.
- Collect service information.
- Follow Service Management best practices.

---

# What is Service Management?

Service Management is the process of controlling system services on managed nodes.

Using Ansible, you can automate tasks such as:

- Start services
- Stop services
- Restart services
- Reload services
- Enable services at boot
- Disable services
- Reboot servers
- Wait until a service is available

Examples of services:

- Nginx
- Apache (httpd)
- SSH
- Docker
- MySQL
- PostgreSQL
- Tomcat

# Service Management Modules

| Module | Purpose |
|---------|----------|
| service | Manage Linux services |

# service Module

The **service** module manages Linux services.

It works on most Linux distributions and provides a generic interface.

## Common Parameters

| Parameter | Description |
|-----------|-------------|
| name | Service name |
| state | Desired service state |
| enabled | Enable or disable service at boot |

---

## Service States

| State | Description |
|--------|-------------|
| started | Start the service |
| stopped | Stop the service |
| restarted | Restart the service |
| reloaded | Reload configuration without restarting |

---

## Start a Service

```yaml
- name: Start Nginx

  service:

    name: nginx

    state: started
```

---

## Stop a Service

```yaml
- name: Stop Nginx

  service:

    name: nginx

    state: stopped
```

---

## Restart a Service

```yaml
- name: Restart Nginx

  service:

    name: nginx

    state: restarted
```

---

## Reload a Service

```yaml
- name: Reload Nginx

  service:

    name: nginx

    state: reloaded
```

---

## Enable a Service

```yaml
- name: Enable Nginx

  service:

    name: nginx

    enabled: true
```

---

## Disable a Service

```yaml
- name: Disable Nginx

  service:

    name: nginx

    enabled: false
```

---

# systemd Module

The **systemd** module is designed for Linux systems that use **systemd**.

Compared to the `service` module, it provides additional features.

---

## Common Parameters

| Parameter | Description |
|-----------|-------------|
| name | Service name |
| state | Desired state |
| enabled | Enable service at boot |
| daemon_reload | Reload systemd configuration |
| masked | Prevent a service from starting |

---

## Restart a Service

```yaml
- name: Restart Docker

  systemd:

    name: docker

    state: restarted
```

---

## Reload systemd

```yaml
- name: Reload systemd

  systemd:

    daemon_reload: true
```

---

## Mask a Service

```yaml
- name: Disable SSH Completely

  systemd:

    name: sshd

    masked: true
```

---

# service vs systemd

| service | systemd |
|----------|----------|
| Generic module | Designed for systemd |
| Works on many Linux distributions | Supports systemd-specific features |
| Simple | More powerful |

---

# reboot Module

The **reboot** module safely restarts the managed node.

Unlike running the `reboot` command manually, Ansible waits until the server becomes reachable again.

---

## Basic Example

```yaml
- name: Reboot Server

  reboot:
```

---

## Common Parameters

| Parameter | Description |
|-----------|-------------|
| reboot_timeout | Maximum wait time |
| pre_reboot_delay | Delay before reboot |
| post_reboot_delay | Delay after reboot |
| test_command | Command used to verify the system is ready |

---

## Example

```yaml
- name: Reboot Server

  reboot:

    reboot_timeout: 600
```

---

# wait_for Module

The **wait_for** module pauses execution until a condition becomes true.

Useful after restarting services or servers.

---

## Wait for SSH Port

```yaml
- name: Wait for SSH

  wait_for:

    port: 22

    timeout: 300
```

---

## Wait for HTTP

```yaml
- name: Wait for Web Server

  wait_for:

    port: 80

    timeout: 120
```

---

## Wait for a File

```yaml
- name: Wait for Log File

  wait_for:

    path: /tmp/app.log
```

---

## Common Parameters

| Parameter | Description |
|-----------|-------------|
| port | Wait for a TCP port |
| path | Wait for a file |
| timeout | Maximum wait time |
| delay | Initial delay before checking |

---

# service_facts Module

The **service_facts** module gathers information about services on the managed node.

---

## Collect Service Information

```yaml
- name: Gather Service Facts

  service_facts:
```

---

## Display Service Information

```yaml
- debug:

    var: ansible_facts.services
```

---

## Example Condition

```yaml
- name: Check SSH Service

  debug:

    msg: "SSH Service is Running"

  when:

    ansible_facts.services["sshd.service"].state == "running"
```

# Common Use Cases

- Start Apache after installation.
- Restart Nginx when the configuration changes.
- Reboot servers after kernel updates.
- Wait until SSH is available after reboot.
- Check whether a service is running.
- Enable Docker at boot.

---

# Best Practices

- Use the **service** module for general compatibility.
- Use the **systemd** module when systemd-specific features are required.
- Use **Handlers** instead of restarting services directly.
- Use **wait_for** after rebooting or restarting applications.
- Avoid using shell commands such as `systemctl restart`; prefer Ansible modules.

---

# Interview Questions

### What is the difference between the `service` and `systemd` modules?

The `service` module provides a generic interface for managing services across different Linux distributions, while the `systemd` module is designed specifically for systems that use systemd and supports additional features such as `daemon_reload` and `masked`.

---

### Which module reboots a managed node?

```yaml
reboot
```

---

### Which module waits until a service or port is available?

```yaml
wait_for
```

---

### Which module collects information about services?

```yaml
service_facts
```

---

### What is the difference between `restart` and `reload`?

- **restart** stops and starts the service again.
- **reload** reloads the configuration without fully restarting the service (if supported).

# Summary

- Service Management automates service operations.
- Use the **service** module for basic service management.
- Use the **systemd** module for systemd-specific functionality.
- Use the **reboot** module to restart managed nodes safely.
- Use the **wait_for** module to pause until services, ports, or files are available.
- Use **service_facts** to collect service information.
- Prefer Ansible modules over manual shell commands.
