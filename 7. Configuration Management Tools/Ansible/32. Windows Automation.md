# 32. Windows Automation

After completing this chapter, you will be able to:

* Understand Windows Automation using Ansible.
* Configure WinRM for Windows management.
* Execute PowerShell commands.
* Install Windows Updates.
* Manage IIS Web Server.
* Manage Windows Services.

# What is Windows Automation?

Windows Automation means using **Ansible** to automate Windows administration tasks.

Instead of manually configuring Windows servers, Ansible can perform tasks automatically.

Examples

* Install Software
* Configure IIS
* Start Services
* Apply Windows Updates
* Join Domain
* Manage Registry
* Schedule Tasks

---

# Why Use Windows Automation?

Benefits

* Faster administration
* Consistent configuration
* Reduced manual work
* Improved reliability
* Easy server deployment
* Centralized management

# WinRM (Windows Remote Management)

## What is WinRM?

**WinRM** is Microsoft's remote management protocol.

Ansible uses **WinRM** instead of SSH to connect to Windows servers.

Without WinRM

```text
Ansible

↓

Cannot connect
```

With WinRM

```text
Ansible

↓

WinRM

↓

Windows Server
```

---

## Common WinRM Tasks

* Configure WinRM
* Enable Remote Management
* Authenticate Users
* Execute Remote Commands

# PowerShell Automation

PowerShell is the default scripting language for Windows.

Ansible can execute PowerShell scripts remotely.

Common Modules

* win_shell
* win_command
* win_powershell

Automation Tasks

* Execute Commands
* Run Scripts
* Configure Windows
* Collect Information

---

# Windows Updates

Windows updates can be automated using Ansible.

Automation Tasks

* Check Available Updates
* Install Updates
* Security Updates
* Reboot if Required

Common Module

```text
ansible.windows.win_updates
```

# Domain Join

Windows servers can automatically join an Active Directory Domain.

Automation Tasks

* Join Domain
* Leave Domain
* Configure Computer Name
* Restart Server

Common Module


# Best Practices

* Use WinRM over HTTPS whenever possible.
* Use Ansible Vault for Windows credentials.
* Test Playbooks before production deployment.
* Use PowerShell modules instead of raw shell commands when available.
* Keep Windows servers updated.
* Store reusable tasks in Roles.
* Use Tags for selective execution.
