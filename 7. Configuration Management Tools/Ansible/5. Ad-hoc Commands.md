# 5. Ad-hoc Commands

## Learning Objectives

After completing this chapter, you will be able to:

- Understand what Ad-hoc Commands are.
- Execute commands on one or multiple servers.
- Use common Ansible modules with Ad-hoc Commands.
- Use command-line options like `-m`, `-a`, `--become`, and `-i`.
- Perform basic administration tasks without writing Playbooks.

---

# What are Ad-hoc Commands?

Ansible **Ad-hoc Commands** are one-line commands used to perform a single task on one or more managed nodes.

They are useful for:

- Checking connectivity
- Installing packages
- Starting services
- Creating users
- Copying files
- Running Linux commands

> **Note:** Ad-hoc Commands are best for quick tasks. For complex or repeated tasks, use **Playbooks**.

---

# Command Syntax

```bash
ansible <host-pattern> -i <inventory-file> -m <module> -a "<arguments>"
```

Example:

```bash
ansible servers -i hosts.ini -m ping
```

---

# Common Command Options

| Option | Description |
|---------|-------------|
| `-i` | Inventory file |
| `-m` | Module name |
| `-a` | Module arguments |
| `--become` | Execute with sudo/root privileges |
| `-v` | Verbose output |
| `-vv` | More detailed output |
| `-vvv` | Debug output |

---

# Ping Module

Checks whether Ansible can connect to the managed nodes.

```bash
ansible all -m ping
```

Using an inventory file:

```bash
ansible servers -i hosts.ini -m ping
```

Expected Output:

```text
worker-node-1 | SUCCESS
worker-node-2 | SUCCESS
worker-node-3 | SUCCESS
```

---

# Command Module

Executes a Linux command.

```bash
ansible servers -i hosts.ini -m command -a "hostname"
```

Examples:

Check Uptime

```bash
ansible servers -i hosts.ini -m command -a "uptime"
```

Check Disk Usage

```bash
ansible servers -i hosts.ini -m command -a "df -h"
```

Check Memory

```bash
ansible servers -i hosts.ini -m command -a "free -h"
```

Check Kernel Version

```bash
ansible servers -i hosts.ini -m command -a "uname -r"
```

> **Note:** The `command` module does **not** support shell features like pipes (`|`), redirection (`>`), or variables.

---

# Shell Module

Runs shell commands on managed nodes.

```bash
ansible servers -i hosts.ini -m shell -a "hostname"
```

Example:

```bash
ansible servers -i hosts.ini -m shell -a "df -h | grep /dev"
```

Another Example:

```bash
ansible servers -i hosts.ini  -m shell -a "echo Hello World > /tmp/test.txt"
```

> Use the **shell** module only when shell features are required.

---

# Copy Module

Copies files from the Control Node to Managed Nodes.

Example:

```bash
ansible servers -m copy -a "src=index.html dest=/var/www/html/index.html"
```

Copy a configuration file:

```bash
ansible servers -m copy -a "src=httpd.conf dest=/etc/httpd/conf/httpd.conf"
```

---

# Package Module

Installs packages using the system's package manager.

Example:

```bash
ansible servers -m package -a "name=git state=present" --become
```

Remove a package:

```bash
ansible servers -m package -a "name=git state=absent" --become
```

---

# DNF Module (RHEL)

Install Nginx

```bash
ansible servers -m dnf -a "name=nginx state=present" --become
```

Update all packages

```bash
ansible servers -m dnf -a "name=* state=latest" --become
```

---

# APT Module (Ubuntu)

Install Nginx

```bash
ansible servers -m apt -a "name=nginx state=present update_cache=yes" --become
```

Update Packages

```bash
ansible servers -m apt -a "upgrade=yes" --become
```

---

# Service Module

Start a service

```bash
ansible servers -m service -a "name=nginx state=started" --become
```

Stop a service

```bash
ansible servers -m service -a "name=nginx state=stopped" --become
```

Restart a service

```bash
ansible servers -m service -a "name=nginx state=restarted" --become
```

Enable service at boot

```bash
ansible servers -m service -a "name=nginx enabled=yes" --become
```

---

# User Module

Create a user

```bash
ansible servers -m user -a "name=devops state=present" --become
```

Delete a user

```bash
ansible servers -m user -a "name=devops state=absent remove=yes" --become
```

---

# Group Module

Create a group

```bash
ansible servers -m group -a "name=developers state=present" --become
```

Delete a group

```bash
ansible servers -m group -a "name=developers state=absent" --become
```

---

# File Module

Create a directory

```bash
ansible servers -m file -a "path=/backup state=directory" --become
```

Create an empty file

```bash
ansible servers -m file -a "path=/tmp/demo.txt state=touch"
```

Delete a file

```bash
ansible servers -m file -a "path=/tmp/demo.txt state=absent"
```

---

# Cron Module

Create a cron job

```bash
ansible servers -m cron -a "name='Backup' minute='0' hour='2' job='/opt/backup.sh'" --become
```

Remove a cron job

```bash
ansible servers -m cron -a "name='Backup' state=absent" --become
```

---

# Using Become (sudo)

Run commands with root privileges.

```bash
--become
```

Example:

```bash
ansible servers -m dnf -a "name=httpd state=present" --become
```

---

# Verbose Mode

Show more detailed output.

```bash
-v
```

More detailed:

```bash
-vv
```

Maximum debugging:

```bash
-vvv
```

Example:

```bash
ansible servers -m ping -vvv
```

---

# Best Practices

- Use the correct module for each task.
- Prefer the `command` module whenever possible.
- Use the `shell` module only when shell features are required.
- Use `--become` only when necessary.
- Test commands on a small group before running on all servers.

### What are Ad-hoc Commands?

Ad-hoc Commands are one-line Ansible commands used to perform a single task without creating a Playbook.

### What is the difference between the `command` and `shell` modules?

| command | shell |
|----------|-------|
| Does not use a shell | Uses a shell |
| Faster and more secure | Supports pipes, redirection, and variables |
| Recommended for simple commands | Use only when shell features are needed |

# Summary

- Ad-hoc Commands execute one-time tasks.
- `ping` checks connectivity.
- `command` executes Linux commands.
- `shell` executes shell commands.
- `copy` copies files.
- `package`, `dnf`, and `apt` manage packages.
- `service` manages services.
- `user` and `group` manage users and groups.
- `file` manages files and directories.
- `cron` schedules recurring tasks.
