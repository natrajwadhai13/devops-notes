# 6. Modules


## Learning Objectives

After completing this chapter, you will be able to:

- Understand what Ansible Modules are.
- Learn the most commonly used built-in modules.
- Execute modules using Ad-hoc Commands.
- Understand module parameters.
- Choose the correct module for different tasks.
- Learn module best practices.

---

# What is a Module?

A **Module** is a small reusable program that performs a specific task on a managed node.

Think of a module as a **ready-made tool**.

Examples:

- Install software
- Create users
- Copy files
- Start services
- Create directories
- Execute commands

---

# Why Use Modules?

Without modules, you would need to write shell scripts for every task.

With modules, Ansible provides ready-made functionality.

Benefits:

- Easy to use
- Reusable
- Idempotent
- Platform independent
- Less scripting required

---

# Module Execution Flow

```
Control Node
      │
      ▼
Ansible Module
      │
      ▼
Managed Node
      │
      ▼
Task Executed
```

---

# Module Syntax

```bash
ansible <hosts> -m <module> -a "<arguments>"
```

Example

```bash
ansible servers -m ping
```

---

| Module | Purpose |
|---------|----------|
| ping | Test connectivity |
| command | Execute Linux commands |
| shell | Execute shell commands |
| copy | Copy files |
| file | Manage files/directories |
| package | Install packages |

| dnf | Package management (RHEL) |
| yum | Package management (Older RHEL) |

| blockinfile | Insert or remove a block of text |
| replace | Replace text in files |

| archive | Create archives |

| get_url | Download files from URLs |

# Ping Module

Checks connectivity between the Control Node and Managed Nodes.

```bash
ansible servers -m ping
```

Expected Output

```text
worker-node-1 | SUCCESS

worker-node-2 | SUCCESS
```

---

# Command Module

Executes Linux commands.

```bash
ansible servers -m command -a "hostname"
```

Example

```bash
ansible servers -m command -a "uptime"
```

**Limitations**

- No pipes (`|`)
- No redirection (`>`)
- No environment variable expansion

---

# Shell Module

Runs commands using a shell.

```bash
ansible servers -m shell -a "df -h | grep /dev"
```

Supports:

- Pipes
- Redirection
- Variables
- Shell operators

---

# Copy Module

Copies files from the Control Node to Managed Nodes.

```bash
ansible servers -m copy -a "src=index.html dest=/var/www/html/index.html"
```

Useful Parameters

- src
- dest
- owner
- group
- mode

---

# File Module

Manages files and directories.

Create a directory

```bash
ansible servers -m file -a "path=/backup state=directory"
```

Create a file

```bash
ansible servers -m file -a "path=/tmp/demo.txt state=touch"
```

Delete a file

```bash
ansible servers -m file -a "path=/tmp/demo.txt state=absent"
```

---

# Package Module

Installs software using the system's default package manager.

```bash
ansible servers -m package -a "name=git state=present"
```

---

# APT Module (Ubuntu)

Install Nginx

```bash
ansible servers -m apt -a "name=nginx state=present update_cache=yes" --become
```

---

# DNF Module (RHEL)

Install Git

```bash
ansible servers -m dnf -a "name=git state=present" --become
```

Update all packages

```bash
ansible servers -m dnf -a "name=* state=latest" --become
```

---

# Service Module

Start a service

```bash
ansible servers -m service -a "name=nginx state=started" --become
```

Restart a service

```bash
ansible servers -m service -a "name=nginx state=restarted" --become
```

Stop a service

```bash
ansible servers -m service -a "name=nginx state=stopped" --become
```

Enable a service

```bash
ansible servers -m service -a "name=nginx enabled=yes" --become
```

---

# User Module

Create a user

```bash
ansible servers -m user -a "name=devops state=present" --become
```

Delete a user

```bash
ansible servers -m user -a "name=devops state=absent remove=yes" --become
```

---

# Group Module

Create a group

```bash
ansible servers -m group -a "name=developers state=present"
```

Delete a group

```bash
ansible servers -m group -a "name=developers state=absent"
```

---

# Cron Module

Create a cron job

```bash
ansible servers -m cron -a "name='Backup' minute='0' hour='2' job='/opt/backup.sh'"
```

---

# Template Module

Copies a **Jinja2 template** to the managed node.

```bash
ansible servers -m template -a "src=nginx.conf.j2 dest=/etc/nginx/nginx.conf"
```

---

# Lineinfile Module

Add or modify a single line.

```bash
ansible servers -m lineinfile -a "path=/etc/hosts line='192.168.1.10 app01'"
```

---

# Blockinfile Module

Insert a block of text.

```bash
ansible servers -m blockinfile -a "path=/etc/hosts block='192.168.1.20 db01'"
```

---

# Replace Module

Replace text inside a file.

```bash
ansible servers -m replace -a "path=/etc/httpd/conf/httpd.conf regexp='80' replace='8080'"
```

---

# Stat Module

Retrieve file information.

```bash
ansible servers -m stat -a "path=/etc/passwd"
```

---

# Fetch Module

Copy a file from the Managed Node to the Control Node.

```bash
ansible servers -m fetch -a "src=/var/log/messages dest=backup/"
```

---

# Archive Module

Create an archive.

```bash
ansible servers -m archive -a "path=/opt/project dest=/backup/project.tar.gz"
```

---

# Unarchive Module

Extract an archive.

```bash
ansible servers -m unarchive -a "src=backup.tar.gz dest=/opt/"
```

---

# Get URL Module

Download a file from a URL.

```bash
ansible servers -m get_url -a "url=https://example.com/file.zip dest=/tmp/file.zip"
```

---

# URI Module

Interact with REST APIs.

```bash
ansible localhost -m uri -a "url=https://api.github.com method=GET"
```

---

# Best Practices

- Use built-in modules instead of shell scripts.
- Prefer `command` over `shell` when possible.
- Use the `package` module for cross-platform package management.
- Always use `--become` when administrative privileges are required.
- Use idempotent modules whenever possible.
