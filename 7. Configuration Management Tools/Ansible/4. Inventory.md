# 4. Inventory

## Learning Objectives

After completing this chapter, you will be able to:

- Understand what an Inventory is.
- Create a Static Inventory.
- Organize servers into groups.
- Use Host Variables.
- Use Group Variables.
- Create Child Groups.
- Understand Dynamic Inventory.
- Verify the Inventory.

---

# What is Inventory?

An **Inventory** is a file that contains the list of servers Ansible will manage.

Instead of typing IP addresses every time, Ansible reads the servers from the Inventory file.

Think of it as an **address book** for Ansible.

---

# Why Do We Need Inventory?

Without Inventory:

```bash
ssh root@192.168.16.130

ssh root@192.168.16.131

ssh root@192.168.16.132
```

Every server must be managed manually.

---

With Inventory:

```bash
ansible servers -m ping
```

Ansible automatically connects to every server listed in the Inventory.

---

# Types of Inventory

Ansible supports two types of Inventory.

1. Static Inventory
2. Dynamic Inventory

---

# Static Inventory

A **Static Inventory** is a manually created file containing server names or IP addresses.

Example:

```ini
[servers]

worker-node-1 ansible_host=192.168.16.130 ansible_user=root

worker-node-2 ansible_host=192.168.16.131 ansible_user=root

worker-node-3 ansible_host=192.168.16.132 ansible_user=root

[all:vars]

ansible_ssh_private_key_file=/root/ansible-master-key

ansible_python_interpreter=/usr/bin/python3
```

Save the file as:

```text
hosts.ini
```

---

# Inventory Structure

```
hosts.ini
      │
      ├── Groups
      ├── Hosts
      ├── Variables
      └── Global Variables
```

---

# Host Groups

A group is a collection of similar servers.

Example:

```ini
[web]

web01

web02

web03
```

Here, all web servers belong to the **web** group.

---

Another example:

```ini
[database]

db01

db02
```

---

# Multiple Groups

```ini
[web]

web01

web02

[database]

db01

db02

[monitoring]

prometheus

grafana
```

---

# Child Groups

A Child Group is a group that contains other groups.

Example:

```ini
[web]

web01

web02

[database]

db01

db02

[production:children]

web

database
```

Now running a command on **production** automatically includes both groups.

---

# Host Variables

Host Variables apply to only one server.

Example:

```ini
web01 ansible_host=192.168.16.130 ansible_user=root

web02 ansible_host=192.168.16.131 ansible_user=ubuntu
```

Here, each host has its own configuration.

---

# Group Variables

Group Variables apply to every host inside a group.

Example:

```ini
[web]

web01

web02

[web:vars]

ansible_user=root

http_port=80
```

Both servers automatically use these values.

---

# Global Variables

Variables under **all:vars** apply to every managed node.

Example:

```ini
[all:vars]

ansible_ssh_private_key_file=/root/ansible-master-key

ansible_python_interpreter=/usr/bin/python3
```

No need to repeat these values for every server.

---

# Inventory File Formats

Ansible supports multiple formats.

## INI Format

```ini
[web]

web01

web02
```

---

## YAML Format

```yaml
all:
  children:
    web:
      hosts:
        web01:
        web02:
```

Both formats are supported.

---

# Dynamic Inventory

A Dynamic Inventory automatically retrieves servers from cloud providers instead of manually maintaining a file.

Example providers:

- AWS EC2
- Azure Virtual Machines
- Google Cloud Platform (GCP)
- VMware vSphere
- OpenStack

Instead of editing `hosts.ini`, Ansible fetches the latest list of servers automatically.

---

# Why Use Dynamic Inventory?

Imagine AWS Auto Scaling creates a new EC2 instance.

Without Dynamic Inventory:

- Edit `hosts.ini`
- Add the new IP manually

With Dynamic Inventory:

- The new EC2 instance is discovered automatically.

No manual updates are required.

---

# Dynamic Inventory Plugins

- openstack.cloud.openstack
- kubernetes.core.k8s

# Verify Inventory

Display the Inventory graph.

```bash
ansible-inventory -i hosts.ini --graph
```

---

Display all Inventory information.

```bash
ansible-inventory -i hosts.ini --list
```

---

Display the Inventory in YAML format.

```bash
ansible-inventory -i hosts.ini --yaml
```

---

# Best Practices

- Use meaningful group names.
- Store common variables in `all:vars`.
- Avoid duplicate host entries.
- Keep production and development servers in separate groups.
- Use Dynamic Inventory for cloud environments.

---

# Interview Questions

### What is an Inventory?

An Inventory is a file that contains the list of servers managed by Ansible.

---

### What are the two types of Inventory?

- Static Inventory
- Dynamic Inventory

---

### What is the difference between Host Variables and Group Variables?

**Host Variables** apply to a single host.

**Group Variables** apply to every host in a group.

---

### What is a Child Group?

A Child Group is a group that contains one or more other groups.

---

### Why is Dynamic Inventory used?

It automatically discovers cloud resources such as AWS EC2 or Azure VMs without manually updating the Inventory file.

---

# Summary

- Inventory stores the list of managed servers.
- Static Inventory is manually maintained.
- Dynamic Inventory automatically discovers cloud resources.
- Groups organize similar servers.
- Host Variables apply to individual hosts.
- Group Variables apply to all hosts in a group.
- Child Groups combine multiple groups.
- Use `ansible-inventory` commands to verify your Inventory.
