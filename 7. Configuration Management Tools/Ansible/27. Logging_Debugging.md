# What is Logging & Debugging?

While running a Playbook, errors may occur due to:

* SSH connection issues
* Incorrect variables
* Invalid YAML syntax
* Missing packages
* Permission problems
* Network issues

Logging and Debugging help identify and fix these problems.

# Verbose Mode

Verbose Mode provides additional details during Playbook execution.

### Syntax

```bash
ansible-playbook playbook.yml -v
```

---

## Verbose Levels

| Option | Description                   |
| ------ | ----------------------------- |
| -v     | Basic details                 |
| -vv    | More detailed information     |
| -vvv   | SSH connection details        |
| -vvvv  | Maximum debugging information |

---

## Examples

Basic Output

```bash
ansible-playbook playbook.yml -v
```

Detailed Output

```bash
ansible-playbook playbook.yml -vv
```

SSH Debugging

```bash
ansible-playbook playbook.yml -vvv
```

Maximum Debugging

```bash
ansible-playbook playbook.yml -vvvv
```

# Debug Module

The **debug** module displays messages or variable values.

It is commonly used while developing and troubleshooting Playbooks.

---

## Display a Message

```yaml
- name: Display Message

  debug:

    msg: "Deployment Started"
```

Output

```text
Deployment Started
```

---

## Display a Variable

```yaml
- name: Show Hostname

  debug:

    var: ansible_hostname
```

---

## Display Multiple Variables

```yaml
- name: Show System Information

  debug:

    msg:

      - "Hostname: {{ ansible_hostname }}"

      - "IP Address: {{ ansible_default_ipv4.address }}"
```

---

## Debug Registered Variable

```yaml
- name: Check Disk Usage

  command: df -h

  register: disk_info

- debug:

    var: disk_info.stdout
```

---

# Register Module Output

The `register` keyword stores the output of a task.

Example

```yaml
- name: Check Uptime

  command: uptime

  register: uptime_output
```

Display Output

```yaml
- debug:

    var: uptime_output.stdout
```

---

# Log Files

Ansible can save Playbook execution logs.

Configure logging in **ansible.cfg**

```ini
[defaults]

log_path = /var/log/ansible.log
```

Now every Playbook execution is saved to:

```text
/var/log/ansible.log
```

---

# View Log File

Linux

```bash
cat /var/log/ansible.log
```

Monitor in real time

```bash
tail -f /var/log/ansible.log
```

# Common Errors

## SSH Connection Failed

Possible Causes

* Wrong IP Address
* SSH Service Down
* Firewall
* Incorrect SSH Key

Check

```bash
ansible all -m ping
```

---

## Permission Denied

Possible Causes

* Missing sudo permission
* Wrong SSH user
* Incorrect private key

Solution

```bash
ansible-playbook playbook.yml --become
```

---

## YAML Syntax Error

Example

```yaml
tasks

- name Install Nginx
```

Correct

```yaml
tasks:

- name: Install Nginx
```

---

## Variable Not Found

Example

```yaml
{{ username }}
```

If the variable is not defined, Ansible reports an error.

Use

```yaml
- debug:

    var: username
```

to verify its value.

---

## Module Not Found

Possible Causes

* Collection not installed
* Typographical error
* Unsupported module

Check installed collections

```bash
ansible-galaxy collection list
```

# Best Practices

* Use the `debug` module during development.
* Remove unnecessary debug statements before production.
* Enable logging for production environments.
* Use `--check` before making changes.
* Use `--diff` to review configuration updates.
* Use `-vvv` for SSH-related issues.
* Store logs securely.
