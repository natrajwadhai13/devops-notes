# What are Includes & Imports?

As Playbooks grow larger, they become difficult to read and maintain.

Instead of keeping everything in one file, Ansible allows you to split automation into multiple files.

Example

```text
Before

playbook.yml

↓

500+ Lines
```

After

```text
playbook.yml

├── install.yml

├── configure.yml

├── deploy.yml

└── cleanup.yml
```

This makes Playbooks easier to understand and reuse.

# Types of Includes & Imports

| Keyword         | Purpose                       |
| --------------- | ----------------------------- |
| import_tasks    | Import another task file      |
| include_tasks   | Dynamically include task file |
| import_role     | Import a Role                 |
| include_role    | Dynamically include a Role    |
| import_playbook | Import another Playbook       |

---

# import_tasks

`import_tasks` imports another task file before Playbook execution starts.

This is called a **Static Import**.

Example

```yaml
# playbook.yml

- hosts: web

  tasks:

    - import_tasks: install.yml
```

install.yml

```yaml
- name: Install Nginx

  package:

    name: nginx

    state: present
```

Execution

```text
playbook.yml

↓

install.yml

↓

Task Executes
```

---

# When to Use import_tasks

* Tasks are always required.
* Execution order is fixed.
* Better performance.
* Easier syntax validation.

---

# include_tasks

`include_tasks` loads another task file **during Playbook execution**.

This is called a **Dynamic Include**.

Example

```yaml
- hosts: web

  tasks:

    - include_tasks: install.yml
```

Unlike `import_tasks`, the file is loaded only when Ansible reaches that task.

---

# When to Use include_tasks

* Conditional execution
* Dynamic task selection
* Looping over task files
* Runtime decisions

---

# import_tasks vs include_tasks

| import_tasks            | include_tasks              |
| ----------------------- | -------------------------- |
| Static                  | Dynamic                    |
| Loaded before execution | Loaded during execution    |
| Faster                  | More flexible              |
| Cannot be looped        | Supports loops             |
| Best for fixed tasks    | Best for conditional tasks |

---

# import_role

Imports an entire Role before execution.

Example

```yaml
- hosts: web

  tasks:

    - import_role:

        name: nginx
```

The Role becomes part of the Playbook during parsing.

---

# include_role

Includes a Role dynamically while the Playbook is running.

Example

```yaml
- hosts: web

  tasks:

    - include_role:

        name: nginx
```

Useful when a Role should run only under certain conditions.

---

# import_role vs include_role

| import_role             | include_role                  |
| ----------------------- | ----------------------------- |
| Static                  | Dynamic                       |
| Loaded before execution | Loaded during execution       |
| Better performance      | Supports conditions and loops |

---

# import_playbook

Imports another Playbook into the current Playbook.

Example

main.yml

```yaml
- import_playbook: web.yml

- import_playbook: database.yml
```

Execution

```text
main.yml

↓

web.yml

↓

database.yml
```

This helps organize large automation projects.

---

# Static vs Dynamic Includes

## Static

Loaded before execution.

Examples

* import_tasks
* import_role
* import_playbook

---

## Dynamic

Loaded during execution.

Examples

* include_tasks
* include_role

---

# Static vs Dynamic Comparison

| Static                   | Dynamic                    |
| ------------------------ | -------------------------- |
| Loaded before execution  | Loaded during execution    |
| Better performance       | More flexible              |
| Fixed execution          | Conditional execution      |
| Easier syntax validation | Supports runtime decisions |

# Best Practices

* Keep task files small and focused.
* Use `import_tasks` for tasks that always run.
* Use `include_tasks` for conditional or dynamic tasks.
* Use Roles for reusable automation.
* Organize Playbooks into logical files.
* Avoid very deep include hierarchies.

# Summary

* Includes and Imports make Playbooks modular.
* `import_tasks` statically imports task files.
* `include_tasks` dynamically includes task files.
* `import_role` imports an entire Role.
* `include_role` dynamically includes a Role.
* `import_playbook` combines multiple Playbooks.
* Static imports are faster.
* Dynamic includes provide greater flexibility.
