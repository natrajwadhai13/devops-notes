# Module 1: Introduction to Ansible

## What is Ansible?

Ansible is an **open-source automation tool** used to automate IT tasks such as:

- Server configuration
- Application deployment
- Software installation
- User management
- Security patching
- Cloud provisioning (AWS, Azure, GCP)
- Infrastructure automation

Unlike many automation tools, Ansible **does not require an agent** to be installed on the target servers. It connects using **SSH** (Linux) or **WinRM** (Windows).

---

## Why Use Ansible?

- reduce the time to market by faster configartions
- We need to have a scalable approach to manage multipal servers
- Push based mechanisam- Agentless


Without Ansible:

- Login to each server manually.
- Run the same commands again and again.
- More chances of human error.
- Time-consuming.

With Ansible:

- Write the task once.
- Run it on hundreds of servers.
- Faster, consistent, and reliable.



---

## Real-Life Example

Imagine you have **100 Linux servers**.

You need to install **Apache** on all servers.

### Without Ansible

```bash
ssh server1
sudo yum install httpd

ssh server2
sudo yum install httpd

ssh server3
sudo yum install httpd
```

Repeat the same steps for all servers.

Time: **2-3 hours**

---

### With Ansible

```bash
ansible web -m yum -a "name=httpd state=present"
```

Time: **Less than 1 minute**

This is the power of automation.

# What is Configuration Management?

Configuration Management is the process of keeping all servers in the desired and consistent state.

It ensures every server has:

- Same software
- Same configuration
- Same users
- Same security settings
- Same packages

---

## Example

Server 1

- Apache Installed
- Java 17
- Docker Installed

Server 2

- Apache Installed
- Java 17
- Docker Installed

Server 3

- Apache Installed
- Java 17
- Docker Installed

All servers are identical.

This is called **Configuration Management**.

# What is Infrastructure as Code (IaC)?

Infrastructure as Code (IaC) means managing infrastructure using **code instead of manual work**.

Instead of clicking buttons in a cloud portal, you write code that creates the infrastructure.

# Agent vs Agentless

## Agent

An agent is a small software installed on every server.

The management server communicates with this agent.

### Examples

- Puppet
- Chef

```
Management Server
        │
        │
   Agent Installed
        │
   Linux Server
```

---

## Agentless

No software needs to be installed on the target server.

Ansible connects directly using:

- SSH (Linux)
- WinRM (Windows)

```
Ansible Control Node
          │
      SSH / WinRM
          │
     Target Server
```

---

## Advantages of Agentless

- Easy setup
- Less maintenance
- Better security
- Faster deployment
- No extra software

---

## Interview Question

### Why is Ansible called Agentless?

Because Ansible does not require any software (agent) to be installed on the managed servers. It connects using SSH (Linux) or WinRM (Windows).

# Push vs Pull Architecture

## Push Architecture

The control server sends tasks to all target servers.

```
Control Node
      │
      ├────────► Server 1
      ├────────► Server 2
      ├────────► Server 3
```

Examples

- Ansible

---

## Pull Architecture

Servers periodically contact the management server and pull their configuration.

```
Server 1 ──► Management Server

Server 2 ──► Management Server

Server 3 ──► Management Server
```

Examples

- Puppet
- Chef

---

## Difference

| Push | Pull |
|------|------|
| Control node sends tasks | Server requests tasks |
| Faster execution | Runs on schedule |
| Used by Ansible | Used by Puppet/Chef |

## Components

- Control Node
- Inventory
- Playbooks
- Modules
- Managed Nodes
- SSH
- WinRM

---

# Control Node

The machine where Ansible is installed.

It executes playbooks and sends tasks to target servers.

Examples

- Ubuntu Server
- RHEL Server
- Amazon Linux
- Azure VM

---

## Responsibilities

- Stores playbooks
- Stores inventory
- Runs automation
- Connects using SSH
- Collects results

---

# Managed Nodes

Managed Nodes are the target machines that Ansible controls.

Examples

- Linux Server
- Windows Server
- AWS EC2
- Azure VM
- GCP VM
- VMware VM

No Ansible installation is required on these servers.

---

# Inventory

Inventory is a file containing the list of servers managed by Ansible.

Example:

```ini
[web]
server1
server2

[db]
server3
```

Here:

- **web** is a group containing `server1` and `server2`.
- **db** is a group containing `server3`.

---

## Types of Inventory

### Static Inventory

Servers are manually added.

### Dynamic Inventory

Servers are automatically fetched from:

- AWS
- Azure
- VMware
- GCP

---

# Modules

Modules are small programs that perform specific tasks.

Think of a module as a ready-made command.

Examples:

| Module | Purpose |
|---------|---------|
| ping | Check connectivity |
| copy | Copy files |
| file | Create/Delete files |
| yum | Install packages (RHEL) |
| apt | Install packages (Ubuntu) |
| service | Start/Stop services |
| user | Create users |
| group | Create groups |
| shell | Run shell commands |
| command | Execute Linux commands |

Example:

```bash
ansible all -m ping
```

---

# Plugins

Plugins extend Ansible's functionality.

Examples:

- Connection Plugin
- Callback Plugin
- Lookup Plugin
- Cache Plugin
- Inventory Plugin

Think of plugins as **extra features** that help Ansible work more efficiently.

---

# Collections

A Collection is a package containing reusable Ansible content.

It may include:

- Modules
- Roles
- Plugins
- Playbooks
- Documentation

Example:

```bash
ansible-galaxy collection install amazon.aws
```

This installs the AWS collection for managing AWS resources.

---

# Key Points

- Ansible is an **agentless automation tool**.
- Uses **SSH** for Linux and **WinRM** for Windows.
- Inventory stores the list of target servers.
- Modules perform individual tasks.
- Plugins add extra functionality.
- Collections group related Ansible content.
- Configuration Management keeps all servers consistent.
- Infrastructure as Code (IaC) manages infrastructure using code.
- Ansible uses a **Push Architecture**.

# Interview Questions

### 1. What is Ansible?

An open-source automation tool used for configuration management, application deployment, and infrastructure automation.

---

### 2. Why is Ansible called Agentless?

Because it uses SSH (Linux) and WinRM (Windows) instead of installing agents on target servers.

---

### 3. What is Configuration Management?

Keeping all servers in a consistent and desired state by automating software installation, configuration, and updates.

---

### 4. What is Infrastructure as Code (IaC)?

Managing infrastructure using code instead of manual processes.

---

### 5. What is an Inventory?

A file containing the list of servers managed by Ansible.

---

### 6. What is a Module?

A reusable component that performs a specific task, such as installing packages or managing users.

---

### 7. What is a Collection?

A package containing modules, roles, plugins, and documentation for a specific platform or technology.

---

### 8. What is the difference between Push and Pull Architecture?

- **Push:** The control node sends tasks to servers (Ansible).
- **Pull:** Servers periodically fetch tasks from the management server (Puppet/Chef).
