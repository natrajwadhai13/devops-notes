# 23. Delegation

## Learning Objectives

After completing this chapter, you will be able to:

* Understand Delegation in Ansible.
* Execute tasks on different hosts using `delegate_to`.
* Run tasks locally using `local_action`.
* Execute tasks only once using `run_once`.
* Store delegated facts using `delegate_facts`.
* Understand Local vs Remote Execution.
* Follow Delegation best practices.

---

# What is Delegation?

By default, Ansible executes every task on the target host defined in the `hosts` section.

**Delegation** allows you to execute a task on a **different host** instead of the target host.

Example:

```text
Target Host: web01

↓

Task executes on

↓

localhost
```

---

# Why Use Delegation?

Delegation is useful when:

* Downloading files to the Control Node
* Updating a Load Balancer
* Calling REST APIs
* Sending notifications
* Creating backups
* Running database operations
* Executing commands on another server

---

# Default Execution

```yaml
- hosts: web

  tasks:

    - name: Check Hostname

      command: hostname
```

Execution

```text
web01 → hostname

web02 → hostname

web03 → hostname
```

Tasks run on each managed node.

---

# delegate_to

The `delegate_to` keyword executes a task on another host.

Syntax

```yaml
delegate_to: hostname
```

---

# Example: Execute on Localhost

```yaml
- hosts: web

  tasks:

    - name: Create Backup

      command: tar -czf backup.tar.gz /var/www

      delegate_to: localhost
```

The Play targets the web servers, but the task runs on the Control Node.

---

# Example: Execute on Another Server

```yaml
- hosts: web

  tasks:

    - name: Update Load Balancer

      command: /opt/update-lb.sh

      delegate_to: lb01
```

Execution

```text
Target Host

↓

web01

↓

Task runs on

↓

lb01
```

---

# local_action

`local_action` is a shortcut for executing a task on the Control Node.

Example

```yaml
- hosts: web

  tasks:

    - name: Send Notification

      local_action:

        module: mail

        subject: "Deployment Completed"

        to: admin@example.com

        body: "Deployment Successful"
```

Equivalent to:

```yaml
delegate_to: localhost
```

---

# delegate_to vs local_action

| delegate_to                   | local_action                  |
| ----------------------------- | ----------------------------- |
| Runs on any host              | Runs only on localhost        |
| Flexible                      | Shortcut for localhost        |
| Preferred in modern Playbooks | Legacy style, still supported |

---

# run_once

Normally, every task executes on every managed host.

`run_once` executes the task only one time.

Example

```yaml
- hosts: web

  tasks:

    - name: Create Database

      command: createdb inventory

      run_once: true
```

Execution

```text
web01 ✔

web02 ✖

web03 ✖
```

The task executes only once.

---

# delegate_to with run_once

This combination is commonly used.

Example

```yaml
- hosts: web

  tasks:

    - name: Update Load Balancer

      command: /opt/update-lb.sh

      delegate_to: localhost

      run_once: true
```

The task runs:

* One time
* On localhost

---

# delegate_facts

Normally, Facts are stored for the current host.

`delegate_facts` stores Facts for the delegated host.

Example

```yaml
- hosts: web

  tasks:

    - name: Gather Database Facts

      setup:

      delegate_to: db01

      delegate_facts: true
```

Facts are stored for **db01**, not the web server.

```text

web01

```

---

## Local Execution

```text

↓

localhost

↓

Task Executes
```

# Best Practices

* Use `delegate_to` for tasks that belong on another host.
* Use `run_once` for tasks that should execute only one time.
* Use `delegate_facts` when collecting facts from delegated hosts.
* Prefer `delegate_to: localhost` over `local_action` in new Playbooks.
* Avoid unnecessary delegation to keep Playbooks simple.

# Interview Questions

### What is Delegation?

Delegation allows a task to execute on a different host than the current target host.

---

### Which keyword delegates a task?

```yaml
delegate_to
```

---

### What is `local_action`?

A shortcut for executing a task on the Control Node (`localhost`).

---

### What does `run_once` do?

It executes a task only one time, even if multiple hosts are targeted.

---

### What does `delegate_facts` do?

It stores gathered facts for the delegated host instead of the current host.

---

### What is the difference between `delegate_to` and `local_action`?

* `delegate_to` can execute on any host.
* `local_action` executes only on `localhost`.

---

# Summary

* Delegation executes tasks on a different host.
* `delegate_to` specifies where the task runs.
* `local_action` runs tasks on the Control Node.
* `run_once` executes a task only one time.
* `delegate_facts` stores facts for delegated hosts.
* Delegation is commonly used for load balancers, notifications, backups, and centralized operations.
