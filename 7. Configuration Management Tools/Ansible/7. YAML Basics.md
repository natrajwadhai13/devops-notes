# 6. YAML Basics

## Learning Objectives

After completing this chapter, you will be able to:

- Understand what YAML is.
- Learn YAML syntax.
- Write valid YAML files.
- Understand data types.
- Use lists and dictionaries.
- Add comments.
- Use variables.
- Understand Anchors and Aliases.
- Write multi-line strings.
- Avoid common YAML mistakes.

---

# What is YAML?

**YAML** stands for:

> **YAML Ain't Markup Language**

YAML is a **human-readable data serialization language** used to store configuration data.

YAML is widely used in DevOps tools because it is simple and easy to read.

---

# Where is YAML Used?

YAML is used in many DevOps tools.

- Ansible
- Kubernetes
- Docker Compose
- GitHub Actions
- GitLab CI/CD
- Azure Pipelines
- Prometheus
- Helm Charts

---

# Why YAML?

Compared to XML and JSON, YAML is:

- Easy to read
- Easy to write
- Less syntax
- Human friendly
- Supports comments
- Supports nested data

---

# YAML File Extension

```text
.yaml
```

or

```text
.yml
```

Example:

```text
playbook.yml

docker-compose.yml

deployment.yaml
```

---

# YAML Syntax Rules

- Uses **spaces**, not tabs.
- Indentation is very important.
- Keys are case-sensitive.
- Uses `key: value` format.
- Comments start with `#`.

---

# Indentation

Correct:

```yaml
server:
  hostname: web01
  port: 80
```

Wrong (using tabs):

```yaml
server:
<TAB>hostname: web01
```

> Always use spaces instead of tabs.

---

# Key-Value Pair

```yaml
name: nginx

port: 80

enabled: true
```

---

# Data Types

YAML supports many data types.

| Type | Example |
|------|---------|
| String | `name: nginx` |
| Integer | `port: 80` |
| Float | `version: 1.2` |
| Boolean | `enabled: true` |
| Null | `value: null` |
| List | `users:` |
| Dictionary | `server:` |

---

# Strings

```yaml
name: nginx

city: Pune
```

Quoted string

```yaml
name: "Apache Server"
```

Single quote

```yaml
name: 'Apache Server'
```

---

# Numbers

```yaml
port: 80

version: 2.4

cpu: 4
```

---

# Boolean

```yaml
enabled: true

running: false
```

---

# Null

```yaml
password: null

username:
```

Both are valid.

---

# Variables

Variables are stored as key-value pairs.

```yaml
app_name: nginx

http_port: 80

environment: Production
```

---

# Lists

A list stores multiple values.

Example:

```yaml
packages:
  - nginx
  - git
  - docker
```

Another example:

```yaml
users:
  - john
  - david
  - admin
```

---

# Dictionary

A dictionary stores related key-value pairs.

```yaml
server:
  hostname: web01
  ip: 192.168.1.10
  port: 80
```

---

# Nested Dictionary

```yaml
server:
  hostname: web01

  network:
    ip: 192.168.1.10
    gateway: 192.168.1.1
```

---

# List of Dictionaries

Very common in Ansible.

```yaml
users:
  - name: john
    uid: 1001

  - name: david
    uid: 1002
```

---

# Comments

Single-line comment

```yaml
# Install Nginx

package: nginx
```

Comments improve readability.

---

# Multi-line Strings

Using `|`

```yaml
message: |
  Welcome to DevOps.
  Learn YAML.
  Learn Ansible.
```

Output

```text
Welcome to DevOps.
Learn YAML.
Learn Ansible.
```

---

Using `>`

```yaml
message: >
  Welcome to DevOps.
  Learn YAML.
  Learn Ansible.
```

Output

```text
Welcome to DevOps. Learn YAML. Learn Ansible.
```

---

# Anchors

Anchors allow data reuse.

```yaml
defaults: &server

  port: 80

  protocol: http

web:

  <<: *server

api:

  <<: *server
```

---

# Aliases

Reuse existing data.

```yaml
database: &db

  host: mysql

  port: 3306

app:

  database: *db
```

---

# Common YAML Errors

Wrong indentation

```yaml
server:

hostname: web01
```

Correct

```yaml
server:
  hostname: web01
```

---

Using tabs

❌ Wrong

Using spaces

✅ Correct

---

Missing colon

Wrong

```yaml
hostname web01
```

Correct

```yaml
hostname: web01
```

---

# YAML Validation

Validate YAML using online tools or command-line tools.

Examples:

```bash
yamllint playbook.yml
```

or

```bash
python -c "import yaml; yaml.safe_load(open('playbook.yml'))"
```

---

# Best Practices

- Use 2 spaces for indentation.
- Never use tabs.
- Use meaningful key names.
- Keep files properly aligned.
- Add comments where necessary.
- Validate YAML before using it.
- Keep nesting simple.

# Interview Questions

### What does YAML stand for?

YAML Ain't Markup Language.

---

### Why is YAML used in Ansible?

Because YAML is simple, readable, and easy to write configuration files.

---

### What are the two valid YAML file extensions?

```text
.yml
.yaml
```

---

### Does YAML support comments?

Yes.

```yaml
# This is a comment
```

---

### Can YAML contain lists and dictionaries?

Yes.

---

### What is the difference between `|` and `>`?

`|` preserves line breaks.

`>` folds multiple lines into a single line.

---

### Does YAML allow tabs?

No.

Only spaces should be used.

---

# Summary

- YAML is a human-readable configuration language.
- Ansible Playbooks are written in YAML.
- YAML uses spaces instead of tabs.
- Data is stored using key-value pairs.
- Supports strings, numbers, lists, and dictionaries.
- Anchors and Aliases help reuse data.
- `|` preserves line breaks.
- `>` joins multiple lines into one.
- YAML is used by Ansible, Kubernetes, Docker Compose, GitHub Actions, GitLab CI/CD, Helm, and many other DevOps tools.
