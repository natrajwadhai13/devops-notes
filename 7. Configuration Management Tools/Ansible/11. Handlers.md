# 11. Handlers

## Learning Objectives

After completing this chapter, you will be able to:

- Understand what Handlers are.
- Learn how `notify` works.
- Execute Handlers.
- Use Multiple Handlers.
- Use `listen`.
- Force handler execution using `flush_handlers`.
- Follow Handler best practices.

---

# What are Handlers?

A **Handler** is a special type of task that runs **only when another task notifies it**.

Handlers are commonly used to:

- Restart services
- Reload services
- Restart applications
- Reload configuration files

Unlike normal tasks, Handlers do **not** run every time.

---

# Why Use Handlers?

Without Handlers

```
Copy Config

↓

Restart Nginx

↓

Copy Another Config

↓

Restart Nginx

↓

Copy SSL

↓

Restart Nginx
```

The service restarts three times.

---

With Handlers

```
Copy Config

↓

Notify Handler

↓

Copy Another Config

↓

Notify Handler

↓

Copy SSL

↓

Notify Handler

↓

Restart Nginx (Only Once)
```

This reduces unnecessary service restarts.

---

# Handler Structure

```yaml
tasks:

handlers:
```

Handlers are defined at the end of the Playbook.

---

# notify

The `notify` keyword tells Ansible which Handler should run if a task changes something.

Example

```yaml
tasks:
  - name: Copy Nginx Configuration

    copy:
      src: nginx.conf

      dest: /etc/nginx/nginx.conf

    notify: Restart Nginx
```

---

# Basic Handler

```yaml
handlers:
  - name: Restart Nginx

    service:
      name: nginx

      state: restarted
```

---

# Complete Example

```yaml
---
- hosts: web

  become: true

  tasks:
    - name: Copy Configuration

      copy:
        src: nginx.conf

        dest: /etc/nginx/nginx.conf

      notify: Restart Nginx

  handlers:
    - name: Restart Nginx

      service:
        name: nginx

        state: restarted
```

---

# When Does a Handler Run?

A Handler runs only when the task reports:

```text
changed = true
```

If nothing changes,

the Handler is skipped.

---

# Handler Execution

Handlers run **after all normal tasks have completed**.

Execution Order

```
Task 1

↓

Task 2

↓

Task 3

↓

Handlers
```

Even if several tasks notify the same Handler,

it executes only once.

---

# Multiple Handlers

A task can notify multiple Handlers.

```yaml
tasks:
  - name: Update Configuration

    copy:
      src: app.conf

      dest: /etc/app.conf

    notify:
      - Restart Nginx

      - Restart PHP
```

Handlers

```yaml
handlers:
  - name: Restart Nginx

    service:
      name: nginx

      state: restarted

  - name: Restart PHP

    service:
      name: php-fpm

      state: restarted
```

---

# Multiple Tasks, One Handler

```yaml
tasks:
  - name: Update Config

    copy:
      src: nginx.conf

      dest: /etc/nginx/nginx.conf

    notify: Restart Nginx

  - name: Copy SSL

    copy:
      src: ssl.conf

      dest: /etc/nginx/ssl.conf

    notify: Restart Nginx
```

Handler

```yaml
handlers:
  - name: Restart Nginx

    service:
      name: nginx

      state: restarted
```

Even though both tasks notify the Handler,

it executes only once.

---

# listen

The `listen` keyword allows multiple Handler names to trigger the same Handler.

Example

```yaml
tasks:
  - name: Copy Config

    copy:
      src: nginx.conf

      dest: /etc/nginx/nginx.conf

    notify: Restart Web Services
```

Handler

```yaml
handlers:
  - name: Restart Nginx

    listen: Restart Web Services

    service:
      name: nginx

      state: restarted
```

This makes Handler names easier to organize.

---

# flush_handlers

Normally, Handlers run at the end of a Play.

To run them immediately, use:

```yaml
- meta: flush_handlers
```

Example

```yaml
tasks:
  - name: Copy Config

    copy:
      src: nginx.conf

      dest: /etc/nginx/nginx.conf

    notify: Restart Nginx

  - meta: flush_handlers

  - name: Continue Deployment

    debug:
      msg: Deployment continues...
```

The Handler runs before the next task.

# Common Use Cases

- Restart Nginx
- Restart Apache
- Reload HAProxy
- Restart Tomcat
- Restart Docker
- Reload Systemd
- Restart SSH
- Restart PostgreSQL
- Restart MySQL

---

# Best Practices

- Use Handlers only for actions that should occur after a change.
- Use meaningful Handler names.
- Avoid unnecessary service restarts.
- Group related service restarts together.
- Use `listen` when multiple notifications should trigger the same Handler.
- Use `flush_handlers` only when immediate execution is required.

# Interview Questions

### What is a Handler?

A special task that runs only when notified by another task.

---

### Which keyword triggers a Handler?

```yaml
notify
```

---

### When are Handlers executed?

After all normal tasks in the Play have completed.

---

### If five tasks notify the same Handler, how many times does it execute?

Only **one time**.

---

### What does `listen` do?

Allows multiple notification names to trigger the same Handler.

---

### What does `flush_handlers` do?

Executes all pending Handlers immediately instead of waiting until the end of the Play.

---

# Summary

- Handlers are special tasks.
- They run only when notified.
- `notify` triggers a Handler.
- Handlers execute only if a task changes something.
- Multiple tasks can notify the same Handler.
- A Handler runs only once, even if notified multiple times.
- `listen` groups notifications.
- `flush_handlers` forces immediate execution.
