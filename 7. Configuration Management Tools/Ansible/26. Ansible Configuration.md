# What is Ansible Configuration?

Ansible uses configuration settings to control its behavior.

These settings define how Ansible:

* Connects to managed nodes
* Executes Playbooks
* Finds inventories
* Stores logs
* Uses SSH
* Controls performance

Most configuration settings are stored in the **ansible.cfg** file.

---

# ansible.cfg

`ansible.cfg` is the main configuration file used by Ansible.

It allows you to customize default settings instead of specifying them in every command.

Example

```ini
[defaults]

inventory = ./hosts.ini

remote_user = ansible

host_key_checking = False

forks = 10

timeout = 30
```

---

# Configuration File Locations

Ansible searches for `ansible.cfg` in the following order:

1. Environment Variable (`ANSIBLE_CONFIG`)
2. Current Working Directory
3. User Home Directory
4. System Directory

```text
ANSIBLE_CONFIG

↓

./ansible.cfg

↓

~/.ansible.cfg

↓

/etc/ansible/ansible.cfg
```

The first file found is used.

# Configuration Precedence

When the same option is defined in multiple places, Ansible follows a priority order.

Highest Priority

```text
Command Line Options

↓

Playbook Variables

↓

Environment Variables

↓

ansible.cfg

↓

Default Values
```

Command-line options override all other settings.

---

# Environment Variables

Environment variables can temporarily override configuration.

Common Variables

| Variable                  | Purpose                          |
| ------------------------- | -------------------------------- |
| ANSIBLE_CONFIG            | Specify configuration file       |
| ANSIBLE_HOST_KEY_CHECKING | Enable/Disable host key checking |
| ANSIBLE_INVENTORY         | Specify inventory file           |
| ANSIBLE_REMOTE_USER       | Set default remote user          |
| ANSIBLE_STDOUT_CALLBACK   | Change output format             |

Example

```bash
export ANSIBLE_CONFIG=/home/user/ansible.cfg
```

---

# Inventory Configuration

Instead of specifying the inventory file every time:

```bash
ansible -i hosts.ini all -m ping
```

Configure it once:

```ini
[defaults]

inventory = hosts.ini
```

Now you can run:

```bash
ansible all -m ping
```

# SSH Optimization

SSH is the default connection method used by Ansible.

Common SSH settings:

```ini
[ssh_connection]

ssh_args = -o ControlMaster=auto -o ControlPersist=60s
```

Benefits

* Faster SSH connections
* Connection reuse
* Reduced execution time

---

# Host Key Checking

By default, SSH verifies the server's host key.

Disable it:

```ini
[defaults]

host_key_checking = False
```

Or using an environment variable:

```bash
export ANSIBLE_HOST_KEY_CHECKING=False
```

> **Note:** Disabling host key checking is useful in labs but should be used carefully in production because it reduces SSH security.

---

# Forks

Forks define how many hosts Ansible manages simultaneously.

Default

```ini
forks = 5
```

Increase the value:

```ini
forks = 20
```

Execution Example

```text
forks = 5

Host1

Host2

Host3

Host4

Host5
```

More forks allow Ansible to manage more hosts in parallel.

---

# Timeouts

Timeout specifies how long Ansible waits for a connection.

Example

```ini
timeout = 30
```

Meaning:

* Wait up to **30 seconds**
* If no response is received, the connection fails.

---

# Pipelining

Pipelining reduces the number of SSH operations required to execute modules.

Enable it:

```ini
[ssh_connection]

pipelining = True
```

Benefits

* Faster execution
* Lower network overhead
* Better performance

> **Note:** When using `sudo`, pipelining may require disabling `requiretty` in the sudo configuration on some systems.

---

# Performance Tuning

Common performance improvements:

* Increase `forks`
* Enable `pipelining`
* Reuse SSH connections
* Use Dynamic Inventory
* Reduce unnecessary `gather_facts`
* Use `run_once` where appropriate
* Execute only required tasks using Tags

# Best Practices

* Keep `ansible.cfg` in the project directory.
* Use version control (Git) for project configuration.
* Increase `forks` only when system resources allow.
* Enable `pipelining` for faster execution.
* Keep host key checking enabled in production whenever possible.
* Store common settings in `ansible.cfg` instead of repeating command-line options.
