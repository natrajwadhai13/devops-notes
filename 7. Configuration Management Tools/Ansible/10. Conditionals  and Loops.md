### 10. Conditionals & Loops

# **Conditionals**

## Learning Objectives

After completing this chapter, you will be able to:

- Understand Conditional Statements.
- Use the `when` statement.
- Compare Variables and Facts.
- Use Logical Operators.
- Use `failed_when`.
- Use `changed_when`.
- Validate conditions using `assert`.
- Write dynamic Playbooks.

---

# What are Conditionals?

Conditionals allow Ansible to execute a task only when a specified condition is true.

Instead of executing every task, Ansible checks the condition first.

Example:

```
Condition

↓

True

↓

Execute Task
```

---

# Why Use Conditionals?

Examples

- Install Apache only on RHEL.
- Install Nginx only on Ubuntu.
- Restart service only if configuration changes.
- Skip tasks for specific servers.
- Execute tasks based on memory or disk space.

---

# The when Statement

Syntax

```yaml
when: condition
```

Example

```yaml
- name: Install Apache
  dnf:
    name: httpd
    state: present
  when: ansible_os_family == "RedHat"
```

---

# Using Variables

```yaml
vars:
  install_nginx: true

tasks:
  - name: Install Nginx
    package:
      name: nginx
      state: present
    when: install_nginx
```

---

# Using Facts

```yaml
when: ansible_distribution == "Ubuntu"
```

Another example

```yaml
when: ansible_memtotal_mb > 2048
```

---

# Comparison Operators

| Operator | Meaning               |
| -------- | --------------------- |
| ==       | Equal                 |
| !=       | Not Equal             |
| >        | Greater Than          |
| <        | Less Than             |
| >=       | Greater Than or Equal |
| <=       | Less Than or Equal    |

---

# Logical Operators

AND

```yaml
when:
  - ansible_os_family == "RedHat"
  - ansible_memtotal_mb > 2048
```

OR

```yaml
when: ansible_distribution == "Ubuntu" or ansible_distribution == "Debian"
```

NOT

```yaml
when: not install_nginx
```

---

# failed_when

Override Ansible's default failure condition.

```yaml
- name: Check Service
  command: systemctl status nginx
  register: result

  failed_when: "'failed' in result.stderr"
```

---

# changed_when

Override the "changed" status.

```yaml
- name: Check Disk
  command: df -h

  changed_when: false
```

Useful for read-only commands.

---

# Assert Module

Validate required conditions.

```yaml
- name: Check Memory

  assert:
    that:
      - ansible_memtotal_mb > 1024

    fail_msg: "Insufficient Memory"

    success_msg: "Memory Check Passed"
```

---

# Best Practices

- Keep conditions simple.
- Use Facts instead of hardcoding.
- Use `changed_when` for read-only commands.
- Use `assert` to validate prerequisites.
- Test conditions using `--check`.

---

# Interview Questions

### What is the purpose of `when`?

Executes a task only when the specified condition is true.

---

### What is `failed_when`?

Defines a custom condition for marking a task as failed.

---

### What is `changed_when`?

Defines a custom condition for marking a task as changed.

---

### What does the `assert` module do?

Validates conditions and stops execution if they are not met.

---

# Summary

- `when` controls task execution.
- Conditions can use Variables or Facts.
- `failed_when` customizes failure detection.
- `changed_when` customizes change reporting.
- `assert` validates prerequisites.

# Loops

## Learning Objectives

After completing this chapter, you will be able to:

- Understand Loops.
- Use the `loop` keyword.
- Learn legacy `with_*` loops.
- Iterate over lists and dictionaries.
- Create Nested Loops.
- Retry tasks using `until`.
- Use `retries` and `delay`.

---

# What are Loops?

Loops repeat the same task multiple times using different input values.

Without loops, you would repeat the same task several times.

With loops, one task handles multiple values.

---

# Why Use Loops?

Examples

- Install multiple packages.
- Create multiple users.
- Copy multiple files.
- Create multiple directories.
- Execute repetitive tasks.

---

# loop (Recommended)

```yaml
- name: Install Packages

  package:
    name: "{{ item }}"

    state: present

  loop:
    - git

    - nginx

    - docker
```

---

# Loop Over Users

```yaml
- name: Create Users

  user:
    name: "{{ item }}"

  loop:
    - john

    - david

    - admin
```

---

# Loop Over Dictionaries

```yaml
- name: Create Users

  user:
    name: "{{ item.name }}"

    uid: "{{ item.uid }}"

  loop:
    - { name: john, uid: 1001 }

    - { name: david, uid: 1002 }
```

---

# with_items (Legacy)

Older Playbooks use:

```yaml
with_items:
  - git

  - nginx

  - docker
```

Equivalent modern syntax:

```yaml
loop:
  - git

  - nginx

  - docker
```

> Prefer `loop` for new Playbooks.

---

# with_dict (Legacy)

```yaml
vars:
  users:
    john: 1001

    david: 1002

tasks:
  - debug:
      msg: "{{ item.key }}"

    with_dict: "{{ users }}"
```

---

# with_file (Legacy)

Read file contents.

```yaml
- debug:
    msg: "{{ item }}"

  with_file:
    - /tmp/file1.txt
```

---

# Nested Loops

{% raw %}
```yaml
- debug:
    msg: "{{ item.0 }} - {{ item.1 }}"

  loop:
    - [web, nginx]

    - [db, mysql]
```
{% endraw %}

Another common approach uses the `product` filter:

{% raw %}
```yaml
loop: "{{ users | product(groups) | list }}"
```
{% endraw %}

---

# until

Retry a task until a condition becomes true.

```yaml
- name: Wait for Service

  command: systemctl is-active nginx

  register: result

  until: result.stdout == "active"

  retries: 5

  delay: 10
```

---

# retries

Specify the maximum number of retry attempts.

```yaml
retries: 5
```

---

# delay

Specify the wait time between retries.

```yaml
delay: 10
```

---

# Best Practices

- Prefer `loop` over `with_*`.
- Use dictionaries for complex data.
- Avoid deeply nested loops.
- Use `until` for retry logic.
- Combine loops with Variables.

---

# Interview Questions

### What is the recommended looping method?

```text
loop
```

---

### Is `with_items` deprecated?

It is considered legacy syntax. It still works, but `loop` is recommended for new Playbooks.

---

### What does `until` do?

Retries a task until the specified condition becomes true.

---

### What is the purpose of `delay`?

Specifies the wait time between retries.

---

### What is the purpose of `retries`?

Defines how many retry attempts Ansible should make.

---

# Summary

- `loop` is the preferred looping mechanism.
- `with_*` loops are legacy but still supported.
- Loops simplify repetitive tasks.
- `until`, `retries`, and `delay` implement retry logic.
- Loops work with Variables, Facts, and registered output.
