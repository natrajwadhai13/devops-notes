# 3. SSH Setup

## Learning Objectives

After completing this chapter, you will be able to:

- Understand why SSH is required in Ansible.
- Configure passwordless SSH authentication.
- Generate SSH key pairs.
- Copy the public key to managed nodes.
- Test SSH connectivity.
- Understand common SSH options used by Ansible.

---

# What is SSH?

**SSH (Secure Shell)** is a secure network protocol used to connect to remote servers over an encrypted connection.

Ansible uses SSH to communicate with Linux/Unix managed nodes.

> **Note:** Ansible is an **agentless** tool, so it uses SSH instead of installing an agent on every server.

---

# Why Does Ansible Use SSH?

Instead of logging in manually to each server, Ansible connects using SSH and executes tasks remotely.

### Benefits

- Secure communication
- Encrypted connection
- No agent installation
- Easy automation
- Passwordless authentication

---

# SSH Authentication Methods

There are two ways to connect using SSH.

## 1. Password Authentication

```
Control Node
      │
 Username + Password
      │
Managed Node
```

**Not recommended** because passwords must be entered every time.

---

## 2. SSH Key Authentication (Recommended)

```
Control Node
     │
 Private Key
     │
──────── SSH ────────
     │
 Public Key
     │
Managed Node
```

This is the method recommended for Ansible.

---

# SSH Key Pair

SSH creates two keys.

| Key | Description |
|------|-------------|
| Private Key | Stored securely on the Control Node. Never share it. |
| Public Key | Copied to every Managed Node. |

Example:

```
ansible-master-key
ansible-master-key.pub
```

---

# Generate SSH Key Pair

Generate a new SSH key.

```bash
ssh-keygen
```

Example:

```text
Enter file in which to save the key:
/root/ansible-master-key
```

Generated files:

```text
ansible-master-key
ansible-master-key.pub
```

---

# Copy the Public Key to Managed Nodes

## Method 1 (Recommended)

```bash
ssh-copy-id -i ansible-master-key.pub root@192.168.16.130
```

Repeat for every managed node.

---

## Method 2 (Manual)

Open the authorized keys file.

```bash
vim ~/.ssh/authorized_keys
```

Paste the contents of:

```text
ansible-master-key.pub
```

Save the file.

---

# Verify SSH Connectivity

Check whether SSH works without entering a password.

```bash
ssh -i ansible-master-key root@192.168.16.130
```

If the login succeeds without prompting for a password, SSH is configured correctly.

---

# Verify Multiple Servers

```bash
ssh -i ansible-master-key root@192.168.16.131

ssh -i ansible-master-key root@192.168.16.132
```

# Common SSH Errors

## Permission denied (publickey)

**Cause**

- Public key not copied.
- Wrong private key.
- Incorrect file permissions.

**Solution**

- Verify `authorized_keys`.
- Verify the private key path.
- Check permissions.

---

## Connection refused

**Cause**

SSH service is not running.

**Solution**

```bash
systemctl status sshd

systemctl start sshd

systemctl enable sshd
```

---

## Host key verification failed

**Solution**

Remove the old SSH entry.

```bash
ssh-keygen -R 192.168.16.130
```

---

# Best Practices

- Never share your private key.
- Use SSH key authentication instead of passwords.
- Protect private keys with proper file permissions.
- Keep a backup of your SSH keys.
- Rotate SSH keys periodically.

# Interview Questions

### Why does Ansible use SSH?

Because Ansible is an **agentless** automation tool. It connects to managed nodes securely using SSH.

---

### Which key should be copied to the Managed Node?

The **public key** (`.pub`) is copied to the managed node.

---

### Where is the public key stored on the Managed Node?

```text
~/.ssh/authorized_keys
```

---

### Which key remains on the Control Node?

The **private key** remains on the Control Node and should never be shared.

---

### Which SSH command tests passwordless authentication?

```bash
ssh -i ansible-master-key root@192.168.16.130
```
