# What are Ansible Collections?

An **Ansible Collection** is a package that groups related Ansible content together.

A Collection can contain:

* Roles
* Modules
* Plugins
* Playbooks
* Documentation
* Tests

Collections make it easy to organize, reuse, and share automation.

---

# Why Use Collections?

Before Collections, Ansible content was mainly shared as individual Roles.

Collections provide a standard way to package everything related to an automation project.

Benefits:

* Better organization
* Reusable automation
* Easy sharing
* Version management
* Dependency management
* Simplified installation

# Collection Structure

A typical Collection directory looks like this:

```text id="lmsb4h"
my_namespace/

└── my_collection/

    ├── docs/

    ├── meta/

    ├── playbooks/

    ├── plugins/

    │   ├── modules/

    │   ├── filter/

    │   ├── lookup/

    │   └── callback/

    ├── roles/

    ├── tests/

    ├── galaxy.yml

    ├── README.md

    └── LICENSE
```

# Install Collections

Install a Collection from Ansible Galaxy.

```bash
ansible-galaxy collection install community.general
```

---

# Install Specific Version

```bash

```

---

# List Installed Collections

```bash
ansible-galaxy collection list
```

Example Output

```text
community.general

amazon.aws

ansible.posix
```

---

# Remove Collections

Collections are installed under the Ansible collections directory.

To remove one manually, delete its directory.

Example:

```text
~/.ansible/collections/
```

or

```text
/usr/share/ansible/collections/
```

# Create a Collection

Use the `ansible-galaxy` command.

```bash
ansible-galaxy collection init mycompany.web
```

Example

```text
Namespace : mycompany

Collection : web
```

# galaxy.yml

`galaxy.yml` contains Collection metadata.

Common fields

* namespace
* name
* version
* authors
* description
* license
* dependencies

Example

```yaml
namespace: mycompany

name: web

version: 1.0.0
```

# Versioning

Collections use **Semantic Versioning**.

Format

```text
MAJOR.MINOR.PATCH
```

Example

```text
1.0.0

1.2.0

2.0.0
```

Meaning

| Version | Description      |
| ------- | ---------------- |
| MAJOR   | Breaking changes |
| MINOR   | New features     |
| PATCH   | Bug fixes        |

---

# Collection Dependencies

Dependencies are defined in `galaxy.yml`.

Example

```yaml
dependencies:

  community.general: ">=10.0.0"

  ansible.posix: ">=2.0.0"
```

Ansible installs the required Collections automatically.

---

# Publishing Collections

Publish a Collection to **Ansible Galaxy**.

Steps

1. Create a Galaxy account.
2. Build the Collection.
3. Upload the Collection.
4. Release new versions when required.

* Use meaningful namespace names.
* Follow Semantic Versioning.
* Keep documentation updated.
* Test Collections before publishing.
* Store Collections in Git.
* Keep Roles and Modules organized.
* Declare dependencies in `galaxy.yml`.
