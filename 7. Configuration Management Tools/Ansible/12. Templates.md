# Introduction

## What are Templates?

A **Template** is a reusable configuration file that contains **variables and Jinja2 expressions**. Instead of maintaining multiple static configuration files, a single template can generate different configurations based on the provided variables.

Templates are typically stored with the **`.j2`** extension.

**Common Examples**

```text
nginx.conf.j2
httpd.conf.j2
application.properties.j2
```

---

## What is Jinja2?

Jinja2 is a **Python-based templating engine** used by Ansible to generate dynamic configuration files.

It supports:

- Variables
- Conditions
- Loops
- Filters
- Expressions
- Comments

---

# Why Use Templates?

| Without Templates            | With Templates           |
| ---------------------------- | ------------------------ |
| Multiple configuration files | Single reusable template |
| Manual updates               | Dynamic generation       |
| Difficult to maintain        | Easy to maintain         |
| High duplication             | Reusable configuration   |

---

# Template Module

The **template** module copies a Jinja2 template to the managed node after replacing variables with their values.

```yaml
- name: Deploy nginx configuration
  template:
    src: nginx.conf.j2
    dest: /etc/nginx/nginx.conf
```

# Jinja2 Syntax

## Variables

Variables are enclosed within double curly braces.

**Example**

```text
{{ inventory_hostname }}

{{ http_port }}
```

---

## Loops

Loops repeat a block of text for every item in a collection.

**Example**

```text
{% for server in servers %}
server {{ server }}
{% endfor %}
```

---

## Conditions

Conditions generate content only when a condition is true.

**Example**

```text
{% if ssl_enabled %}
listen 443 ssl;
{% else %}
listen 80;
{% endif %}
```

---

## Filters

Filters modify variable values before rendering.

| Filter  | Example                                     | Purpose              |
| ------- | ------------------------------------------- | -------------------- |
| upper   | `{{ username \| upper }}`                   | Convert to uppercase |
| lower   | `{{ username \| lower }}`                   | Convert to lowercase |
| default | `{{ server_name \| default("localhost") }}` | Default value        |
| length  | `{{ users \| length }}`                     | Count items          |
| join    | `{{ servers \| join(",") }}`                | Join list            |
| replace | `{{ hostname \| replace("-", "_") }}`       | Replace characters   |

---

## Comments

Comments are ignored during template rendering.

```text
{# This is a comment #}
```

---

## Whitespace Control

Remove unwanted spaces around variables.

```text
{{- variable -}}
```

# Real-World Example

## nginx.conf Template

```text
server {
    listen {{ http_port }};
    server_name {{ inventory_hostname }};
    root {{ document_root }};
}
```

### Variables

```yaml
http_port: 80
document_root: /var/www/html
```

### Generated Output

```text
server {
    listen 80;
    server_name web01;
    root /var/www/html;
}
```

# Best Practices

- Store templates in the `templates/` directory.
- Keep templates simple and readable.
- Avoid hardcoded values.
- Use meaningful variable names.
- Validate generated configuration before deployment.
- Restart services only when templates change.
- Reuse templates across multiple hosts.

### Difference between `copy` and `template`

| copy                              | template                                           |
| --------------------------------- | -------------------------------------------------- |
| Copies files without modification | Generates files dynamically                        |
| No variable substitution          | Supports variables, loops, filters, and conditions |
| Best for static files             | Best for dynamic configuration                     |
