---

# Introduction

## What are Ansible Plugins?

Plugins are components that **extend Ansible's functionality**. Unlike modules, plugins generally execute on the **Control Node** and assist Ansible during Playbook execution.

Plugins help retrieve external data, transform variables, generate inventories, customize output, cache facts, and manage remote connections.

### Common Uses

- Read external data
- Transform variables
- Generate dynamic inventory
- Cache Facts
- Customize Playbook output
- Manage remote connections

---

# Why Use Plugins?

Plugins provide several benefits:

- Extend Ansible functionality
- Improve automation workflows
- Integrate with external systems
- Improve Playbook performance
- Reduce repetitive logic

---

# Modules vs Plugins

| Feature       | Modules                      | Plugins                         |
| ------------- | ---------------------------- | ------------------------------- |
| Execution     | Managed Nodes                | Mostly Control Node             |
| Purpose       | Perform tasks                | Extend Ansible functionality    |
| Modify System | Yes                          | Usually No                      |
| Examples      | `package`, `copy`, `service` | `lookup`, `filter`, `inventory` |

---

# Plugin Types

| Plugin     | Purpose                      | Common Examples       |
| ---------- | ---------------------------- | --------------------- |
| Lookup     | Read external data           | file, env, pipe       |
| Filter     | Transform variables          | upper, lower, default |
| Inventory  | Dynamic inventory            | aws_ec2, azure_rm     |
| Callback   | Customize output             | yaml, json            |
| Action     | Pre-process module execution | Built-in              |
| Cache      | Store Facts                  | memory, redis         |
| Connection | Connect to hosts             | ssh, winrm            |

---

# Lookup Plugins

Lookup Plugins retrieve information from external sources before a task executes.

### Common Lookup Plugins

- file
- env
- pipe
- password
- url

### Example Use Cases

- Read a configuration file
- Read an environment variable
- Execute a local command
- Retrieve secrets
- Access remote resources

---

# Filter Plugins

Filter Plugins transform variables using Jinja2 filters.

### Common Filters

| Filter  | Purpose                   |
| ------- | ------------------------- |
| upper   | Convert text to uppercase |
| lower   | Convert text to lowercase |
| default | Set a default value       |
| join    | Join list elements        |
| length  | Count elements            |
| replace | Replace characters        |
| trim    | Remove spaces             |
| unique  | Remove duplicates         |
| sort    | Sort values               |
| to_json | Convert to JSON           |
| to_yaml | Convert to YAML           |

### Common Use Cases

- Format strings
- Handle missing variables
- Process lists
- Convert data formats

---

# Inventory Plugins

Inventory Plugins generate inventories dynamically instead of using static inventory files.

### Common Inventory Plugins

- amazon.aws.aws_ec2
- azure.azcollection.azure_rm
- vmware.vmware_vm_inventory
- openstack.cloud.openstack

### Benefits

- Automatic host discovery
- Cloud integration
- Reduced manual inventory management

---

# Callback Plugins

Callback Plugins customize Playbook output.

### Common Callback Plugins

- default
- yaml
- json
- minimal
- oneline
- profile_tasks
- timer

### Common Uses

- Better output formatting
- Execution timing
- Logging
- Reporting

---

# Action Plugins

Action Plugins execute on the Control Node before the module runs.

### Responsibilities

- Validate parameters
- Prepare task data
- Optimize execution
- Reduce unnecessary remote operations

---

# Cache Plugins

Cache Plugins store gathered Facts to improve Playbook performance.

### Common Cache Plugins

- memory
- jsonfile
- redis
- memcached

### Benefits

- Faster execution
- Reduced fact gathering
- Better scalability

---

# Connection Plugins

| -------- | ----------------- |

| local    | Localhost         |
| winrm    | Windows           |
| docker   | Docker Containers |

# Best Practices

- Use Lookup Plugins for external data.
- Prefer Filter Plugins for data transformation.
- Use Inventory Plugins in cloud environments.
- Enable Fact Caching for large infrastructures.
- Keep Callback Plugins lightweight.
- Prefer SSH for Linux systems.
- Install Plugins only from trusted Collections.

# Interview Questions

### What are Ansible Plugins?

Components that extend Ansible functionality and support Playbook execution.

### Where do Plugins execute?

Mostly on the **Control Node**.

### Difference between Modules and Plugins?

| Modules              | Plugins                        |
| -------------------- | ------------------------------ |
| Execute tasks        | Extend Ansible                 |
| Run on managed nodes | Mostly run on the Control Node |

### Which Plugin...

| Question                    | Answer            |
| --------------------------- | ----------------- |
| Reads external data?        | Lookup Plugin     |
| Transforms variables?       | Filter Plugin     |
| Creates dynamic inventory?  | Inventory Plugin  |
| Customizes Playbook output? | Callback Plugin   |
| Stores Facts?               | Cache Plugin      |
| Controls connections?       | Connection Plugin |
| Windows connection?         | `winrm`           |
