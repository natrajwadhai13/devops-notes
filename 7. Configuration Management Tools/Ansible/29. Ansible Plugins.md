# What are Ansible Plugins?

Plugins are small pieces of code that **extend Ansible's functionality**.

Unlike modules, plugins are **not executed on managed nodes**. Most plugins run on the **Control Node** and help Ansible perform specific tasks.

Examples:

* Read data from a file
* Format variables
* Generate output
* Connect to remote systems
* Cache Facts

---

# Why Use Plugins?

Plugins help Ansible:

* Extend functionality
* Improve automation
* Reuse common logic
* Integrate with external systems
* Improve Playbook performance

---

# Modules vs Plugins

| Modules                    | Plugins                            |
| -------------------------- | ---------------------------------- |
| Execute on Managed Nodes   | Mostly execute on the Control Node |
| Perform tasks              | Extend Ansible functionality       |
| Change system state        | Support Playbook execution         |
| Example: `package`, `copy` | Example: `lookup`, `filter`        |

---

# Types of Plugins

| Plugin            | Purpose                         |
| ----------------- | ------------------------------- |
| Lookup Plugin     | Read data from external sources |
| Filter Plugin     | Modify variables                |
| Inventory Plugin  | Generate inventory dynamically  |
| Callback Plugin   | Customize Playbook output       |
| Action Plugin     | Execute tasks before modules    |
| Cache Plugin      | Cache Facts                     |
| Connection Plugin | Connect to managed nodes        |

# Lookup Plugins

Lookup Plugins retrieve data from external sources before a task runs.

Common Lookup Plugins

* file
* env
* password
* pipe
* url

---

## Read File Content

```yaml
- name: Read File

  debug:

    msg: "{{ lookup('file','message.txt') }}"
```

---

## Read Environment Variable

```yaml
- name: Display HOME

  debug:

    msg: "{{ lookup('env','HOME') }}"
```

---

## Execute Linux Command

```yaml
- name: Get Date

  debug:

    msg: "{{ lookup('pipe','date') }}"
```

---

# Filter Plugins

Filter Plugins modify variables using Jinja2.

They are written using the pipe (`|`) operator.

---

## Convert to Uppercase

```yaml
- debug:

    msg: "{{ username | upper }}"
```

---

## Convert to Lowercase

```yaml
- debug:

    msg: "{{ username | lower }}"
```

---

## Default Value

```yaml
- debug:

    msg: "{{ city | default('Pune') }}"
```

---

## Join List

```yaml
- debug:

    msg: "{{ users | join(', ') }}"
```

---

## Common Filters

* upper
* lower
* default
* join
* length
* replace
* trim
* unique
* sort
* to_json
* to_yaml

# Inventory Plugins

Inventory Plugins create inventory dynamically.

Instead of manually updating `hosts.ini`, Ansible retrieves hosts automatically.

Common Inventory Plugins

* amazon.aws.aws_ec2
* azure.azcollection.azure_rm
* vmware.vmware_vm_inventory
* openstack.cloud.openstack

---

## Example

```yaml
plugin: amazon.aws.aws_ec2
```

Ansible automatically discovers EC2 instances.

---

# Callback Plugins

Callback Plugins customize Playbook output.

Examples

* default
* yaml
* json
* minimal
* oneline
* profile_tasks
* timer

---

## Configure Callback Plugin

```ini
[defaults]

stdout_callback = yaml
```

---

# Action Plugins

Action Plugins execute on the Control Node before the module runs.

Responsibilities include:

* Validate parameters
* Prepare data
* Optimize execution
* Reduce unnecessary remote operations

Action Plugins are commonly used internally by Ansible.

---

# Cache Plugins

Cache Plugins store gathered Facts.

Without caching:

```text
Playbook

↓

Gather Facts

↓

Execute
```

Every run gathers Facts again.

---

With caching:

```text
Playbook

↓

Read Cached Facts

↓

Execute
```

This improves performance.

---

## Common Cache Plugins

* memory
* jsonfile
* redis
* memcached

---

## Example

```ini
[defaults]

fact_caching = jsonfile

fact_caching_connection = /tmp/ansible_cache
```

---

## Local Connection

```

---

## Windows Connection

```

# Best Practices

* Use Lookup Plugins to retrieve external data.
* Use Filter Plugins instead of complex Jinja2 expressions.
* Use Inventory Plugins for cloud environments.
* Enable Cache Plugins in large infrastructures.
* Keep Callback Plugins simple.
* Use the default SSH Connection Plugin whenever possible.
* Install trusted Plugins and Collections only.
