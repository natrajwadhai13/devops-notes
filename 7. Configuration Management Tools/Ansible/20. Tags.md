# 20. Tags

## Learning Objectives

After completing this chapter, you will be able to:

* Understand what Ansible Tags are.
* Execute specific tasks using Tags.
* Skip unwanted tasks.
* Use multiple Tags.
* Understand `always` and `never` Tags.
* Use Tags with Roles and Included Tasks.
* Follow Tag best practices.

---

# What are Tags?

**Tags** are labels assigned to Ansible tasks, plays, roles, or imported files.

Tags allow you to execute **only the required parts** of a Playbook instead of running the entire Playbook.

---

# Why Use Tags?

Without Tags

```
Playbook

↓

Install Packages

↓

Configure Server

↓

Deploy Application

↓

Restart Service

↓

Cleanup
```

Every task runs.

---

With Tags

```
Playbook

↓

Run Only "install"

↓

Install Packages
```

Only the selected task runs.

---

# Benefits of Tags

* Faster Playbook execution
* Run only required tasks
* Skip unnecessary tasks
* Easy testing
* Better maintenance
* Reusable Playbooks

---

# Tag Syntax

```yaml
tasks:

- name: Install Nginx

  package:

    name: nginx

    state: present

  tags:

    - install
```

---

# Single Tag

```yaml
- name: Install Git

  package:

    name: git

    state: present

  tags:

    - install
```

Run

```bash
ansible-playbook playbook.yml --tags install
```

Only the **install** task executes.

---

# Multiple Tags

A task can have more than one tag.

```yaml
- name: Install Apache

  package:

    name: httpd

    state: present

  tags:

    - install

    - apache

    - webserver
```

Run

```bash
ansible-playbook playbook.yml --tags apache
```

or

```bash
ansible-playbook playbook.yml --tags install
```

---

# Tags at Play Level

Tags can be applied to the entire Play.

```yaml
- hosts: web

  tags:

    - webserver

  tasks:

    - name: Install Nginx

      package:

        name: nginx

        state: present
```

All tasks in the Play inherit the tag.

---

# Tags with Roles

Apply a tag to an entire Role.

```yaml
roles:

- role: nginx

  tags:

    - web
```

Run

```bash
ansible-playbook site.yml --tags web
```

---

# Run Specific Tasks

Execute only selected Tags.

```bash
ansible-playbook playbook.yml --tags install
```

Run multiple Tags

```bash
ansible-playbook playbook.yml --tags "install,config"
```

---

# Skip Tags

Skip one Tag

```bash
ansible-playbook playbook.yml --skip-tags restart
```

Skip multiple Tags

```bash
ansible-playbook playbook.yml --skip-tags "restart,cleanup"
```

---

# List Available Tags

Display all Tags in a Playbook.

```bash
ansible-playbook playbook.yml --list-tags
```

Example Output

```text
playbook: playbook.yml

TASK TAGS:

install

config

restart

cleanup
```

---

# List Tasks

Display all tasks without executing them.

```bash
ansible-playbook playbook.yml --list-tasks
```

---

# Special Tag: always

The **always** tag runs every time, even when another tag is specified.

Example

```yaml
- name: Gather Facts

  setup:

  tags:

    - always
```

Run

```bash
ansible-playbook playbook.yml --tags install
```

The task with the **always** tag also runs.

---

# Special Tag: never

The **never** tag prevents a task from running unless it is explicitly requested.

Example

```yaml
- name: Reset Database

  command: reset-db.sh

  tags:

    - never
```

This task does not execute during a normal Playbook run.

Run it explicitly

```bash
ansible-playbook playbook.yml --tags never
```

---

# Tags with include_tasks

```yaml
- name: Include Install Tasks

  include_tasks: install.yml

  tags:

    - install
```

---

# Tags with import_tasks

```yaml
- name: Import Configuration Tasks

  import_tasks: config.yml

  tags:

    - config
```

---

# Tags with include_role

```yaml
- name: Include Nginx Role

  include_role:

    name: nginx

  tags:

    - web
```

---

# Tags with import_role

```yaml
- name: Import Apache Role

  import_role:

    name: apache

  tags:

    - apache
```

# Common Use Cases

* Install packages
* Configure servers
* Deploy applications
* Restart services
* Backup files
* Cleanup temporary files
* Update configuration
* Database migration

---

# Best Practices

* Use meaningful tag names.
* Group related tasks under the same tag.
* Keep tag names short and simple.
* Use `always` only for mandatory tasks.
* Use `never` for dangerous or rarely used tasks.
* Document important tags in the Playbook.

# Interview Questions

### What are Ansible Tags?

Tags are labels that allow specific tasks, plays, or roles to be executed.

---

### Why use Tags?

To run only the required tasks and reduce Playbook execution time.

---

### Which option runs only specific Tags?

```bash
ansible-playbook playbook.yml --tags install
```

---

### Which option skips specific Tags?

```bash
ansible-playbook playbook.yml --skip-tags restart
```

---

### What does the `always` tag do?

Tasks with the `always` tag execute every time.

---

### What does the `never` tag do?

Tasks with the `never` tag run only when explicitly requested.

---

### How do you list all Tags?

```bash
ansible-playbook playbook.yml --list-tags
```

---

### Can a task have multiple Tags?

Yes.

Example

```yaml
tags:

- install

- nginx

- webserver
```

---

# Summary

* Tags help execute specific parts of a Playbook.
* A task can have one or more Tags.
* Use `--tags` to run selected tasks.
* Use `--skip-tags` to skip tasks.
* `always` runs every time.
* `never` runs only when explicitly requested.
* Tags can be applied to tasks, plays, roles, and included files.
* Proper use of Tags makes Playbooks faster, cleaner, and easier to maintain.
