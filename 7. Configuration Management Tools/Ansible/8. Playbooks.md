# What is a Playbook?

A **Playbook** is a YAML file that defines one or more automation tasks.

Instead of running multiple Ad-hoc Commands, you can store all tasks in a single Playbook and execute them whenever needed.

Example:

```text
Install Nginx
↓

Start Nginx

↓

Enable Nginx

↓

Copy Configuration

↓

Restart Service
```

All these tasks can be written in one Playbook.

---

# Why Use Playbooks?

Playbooks are:

- Reusable
- Easy to maintain
- Version controlled
- Human-readable
- Repeatable
- Idempotent

# Playbook File Extension


Example:

```text

```

---

# Basic Playbook Structure

```yaml
---
- name: Install Nginx
  hosts: web
  become: true

  tasks:
    - name: Install Nginx
      dnf:
        name: nginx
        state: present

    - name: Start Nginx
      service:
        name: nginx
        state: started
```

---

# Main Components

Every Playbook usually contains:

- name
- hosts
- become
- gather_facts
- vars (optional)
- tasks
- handlers (optional)

---

# Name

Provides a readable description.

```yaml
- name: Install Apache Web Server
```

---

# Hosts

Specifies where the Playbook will run.

```yaml
hosts: web
```

Run on all servers

```yaml
hosts: all
```

---

# Become

Executes tasks with root/sudo privileges.

```yaml
become: true
```

Without Become

```yaml
become: false
```

---

# Gather Facts

Collects system information before running tasks.

```yaml
gather_facts: true
```

Disable

```yaml
gather_facts: false
```

Disabling facts speeds up Playbook execution when system information isn't required.

---

# Tasks

Tasks are the individual operations performed by the Playbook.

```yaml
tasks:
  - name: Install Git
    package:
      name: git
      state: present

  - name: Start Service
    service:
      name: nginx
      state: started
```

---

# Variables

Variables can be defined inside a Playbook.

```yaml
vars:
  package_name: nginx

  service_name: nginx
```

Use variables

```yaml
tasks:
  - name: Install Package
    package:
      name: "{{ package_name }}"
      state: present
```

---

# Gather Facts

Common facts include:

```yaml
ansible_hostname

ansible_distribution

ansible_os_family

ansible_kernel

ansible_processor

ansible_default_ipv4.address
```

Example

```yaml
- debug:
    var: ansible_hostname
```

---

# Multiple Plays

One Playbook can contain multiple Plays.

```yaml
---
- name: Configure Web Servers
  hosts: web

  tasks:
    - name: Install Nginx
      package:
        name: nginx
        state: present

- name: Configure Database Servers
  hosts: database

  tasks:
    - name: Install MySQL
      package:
        name: mysql
        state: present
```

---

# Execution Order

Tasks execute from top to bottom.

Example

```
Task 1

↓

Task 2

↓

Task 3

↓

Task 4
```

If a task fails, Playbook execution usually stops unless error handling is configured.

# Error Handling

Ignore an error

```yaml
ignore_errors: true
```

Example

```yaml
- name: Stop Apache
  service:
    name: httpd
    state: stopped
  ignore_errors: true
```

---

# Register Output

Store command output for later use.

```yaml
- name: Check Uptime
  command: uptime
  register: uptime_output
```

Display Output

```yaml
- debug:
    var: uptime_output.stdout
```

---

# Basic Handler Example

```yaml
tasks:
  - name: Copy Config
    copy:
      src: nginx.conf
      dest: /etc/nginx/nginx.conf
    notify: Restart Nginx

handlers:
  - name: Restart Nginx
    service:
      name: nginx
      state: restarted
```

Handlers run **only when notified**.

(Handlers will be covered in detail in a later chapter.)

---

# Best Practices

- Give every task a meaningful name.
- Keep Playbooks small and reusable.
- Use variables instead of hard-coded values.
- Use modules instead of shell commands.
- Use `--check` before running in production.
- Group related tasks into separate Playbooks.
- Follow proper YAML indentation.

# Summary

- Playbooks are YAML files used to automate tasks.
- A Playbook consists of Plays, Tasks, and Modules.
- `hosts` defines the target systems.
- `become` provides elevated privileges.
- `gather_facts` collects system information.
- Multiple Plays can exist in one Playbook.
- Tasks execute sequentially.
- Use `ansible-playbook` to execute Playbooks.
- Use `--check` and `--syntax-check` before production deployments.

# Automatic Nginx Setup Using Ansible

This playbook installs **Nginx**, copies a custom `index.html` file to the web server, restarts the service, and enables it to start automatically on boot.

---

## Directory Structure

```text
nginx-playbook/
├── hosts.ini
├── setup_nginx.yml
└── index.html
```

---

## Create the Playbook

```bash
vi setup_nginx.yml
```

---

## Create the Custom HTML File

```bash
vi index.html
```

Example `index.html`:

```html
<!DOCTYPE html>
<html>
<head>
    <title>Welcome</title>
</head>
<body>
    <h1>Hello from Ansible!</h1>
    <p>Nginx has been configured successfully.</p>
</body>
</html>
```

---

## Run the Playbook

```bash
ansible-playbook -i ../hosts.ini setup_nginx.yml
```

> Replace `../hosts.ini` with the correct path to your inventory file if needed.

---

# Playbook: `setup_nginx.yml`

```yaml
---
- name: Setup Nginx with Custom HTML File
  hosts: servers
  become: yes

  tasks:

    - name: Install Nginx
      apt:
        name: nginx
        state: present
        update_cache: yes

    - name: Copy the Custom HTML File
      copy:
        src: index.html
        dest: /var/www/html/index.html
        owner: root
        group: root
        mode: '0644'

    - name: Restart Nginx
      service:
        name: nginx
        state: reloaded

    - name: Enable Nginx
      systemd_service:
        name: nginx
        enabled: true
```

---

# Explanation

| Task           | Description                                                                            |
| -------------- | -------------------------------------------------------------------------------------- |
| Install Nginx  | Installs the Nginx package using the `apt` module.                                     |
| Copy HTML File | Copies the local `index.html` file to `/var/www/html/index.html` on the target server. |
| Restart Nginx  | Reloads the Nginx service so the new web page is served.                               |
| Enable Nginx   | Configures Nginx to start automatically after every system reboot.                     |

---

## Verify Installation

Check the Nginx service status:

```bash
sudo systemctl status nginx
```

Open the web page in a browser:

```text
http://<server-ip>
```

Or verify using `curl`:

```bash
curl http://<server-ip>
```

You should see the contents of the custom `index.html` page served by Nginx.
