# 28. Custom Modules

## Learning Objectives

After completing this chapter, you will be able to:

* Understand Custom Modules in Ansible.
* Learn why Custom Modules are used.
* Create Python-based Ansible Modules.
* Define Module Arguments.
* Return data from a Module.
* Test Custom Modules.
* Document Custom Modules.
* Follow best practices for Module development.

---

# What are Custom Modules?

Ansible provides hundreds of built-in modules such as:

* copy
* file
* package
* service
* user

Sometimes these modules cannot perform a specific task required in your environment.

In such cases, you can create your own **Custom Module**.

---

# Why Use Custom Modules?

Use Custom Modules when:

* No built-in module exists.
* Company-specific automation is required.
* Complex logic is needed.
* External APIs must be integrated.
* Internal tools need automation.

---

# Built-in Module vs Custom Module

| Built-in Module       | Custom Module                       |
| --------------------- | ----------------------------------- |
| Provided by Ansible   | Created by the user                 |
| Ready to use          | Developed for specific requirements |
| Supports common tasks | Supports custom business logic      |
| No coding required    | Usually written in Python           |

---

# Module Development Languages

Although modules can be written in different languages, **Python** is the recommended language.

Supported languages include:

* Python (Recommended)
* PowerShell (Windows)
* Shell Script (Limited support)

Most production environments use Python.

---

# Module Directory Structure

Custom modules are usually stored in a project directory.

Example

```text
project/

├── playbook.yml

├── inventory.ini

└── library/

    └── my_module.py
```

The **library/** directory contains custom modules.

---

# Basic Python Module

Example

```python
#!/usr/bin/python3

from ansible.module_utils.basic import AnsibleModule

module = AnsibleModule(

    argument_spec={

        "name": {"type": "str", "required": True}

    }

)

name = module.params["name"]

module.exit_json(

    changed=False,

    message=f"Hello {name}"
)
```

---

# Module Arguments

Arguments are inputs passed to the module.

Example

```python
argument_spec={

    "name": {

        "type": "str",

        "required": True

    },

    "age": {

        "type": "int"

    }
}
```

---

# Common Argument Types

| Type  | Description    |
| ----- | -------------- |
| str   | String         |
| int   | Integer        |
| bool  | Boolean        |
| list  | List           |
| dict  | Dictionary     |
| path  | File Path      |
| float | Decimal Number |

---

# Common Argument Options

| Option   | Description                 |
| -------- | --------------------------- |
| required | Mandatory parameter         |
| default  | Default value               |
| choices  | Allowed values              |
| no_log   | Hide sensitive values       |
| aliases  | Alternative parameter names |

Example

```python
"name": {

    "type": "str",

    "required": True
}
```

---

# Reading Module Parameters

Example

```python
username = module.params["name"]
```

---

# Returning Success

Use `exit_json()` when the module completes successfully.

Example

```python
module.exit_json(

    changed=True,

    message="User Created"
)
```

---

# Returning Failure

Use `fail_json()` when an error occurs.

Example

```python
module.fail_json(

    msg="User Creation Failed"
)
```

---

# Using the Custom Module

Playbook

```yaml
- hosts: localhost

  tasks:

    - name: Run Custom Module

      my_module:

        name: Natraj
```

# Testing Custom Modules

Run the Playbook

```bash
ansible-playbook playbook.yml
```

Increase debugging

```bash
ansible-playbook playbook.yml -vvv
```

Syntax check

```bash
ansible-playbook playbook.yml --syntax-check
```

# Documentation

Every Custom Module should include documentation.

Common sections:

* Module Name
* Description
* Parameters
* Examples
* Return Values
* Author

Example

```python
DOCUMENTATION = r'''

module: my_module

short_description: Demo Custom Module

author: Natraj

'''
```

---

# Return Values

Document the values returned by the module.

Example

```python
RETURN = r'''

message:

    description: Result Message

    returned: always

    type: str

'''
```

# Best Practices

* Use Python for Custom Modules.
* Validate all input parameters.
* Return meaningful error messages.
* Use `no_log=True` for passwords and secrets.
* Keep modules focused on a single task.
* Document parameters and return values.
* Test modules before production.
* Follow Ansible coding standards.
