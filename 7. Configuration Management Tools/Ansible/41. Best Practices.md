# 1. Write Idempotent Playbooks

## What is Idempotency?

An idempotent Playbook produces the **same result every time it is executed**, regardless of how many times it runs.

Example

```text id="vpyf9s"
Run Playbook

↓

Package Installed

↓

Run Again

↓

No Changes
```

Good Modules

* package
* service
* file
* user
* copy
* template

Avoid unnecessary shell commands when dedicated modules exist.

---

# 2. Create Reusable Roles

Instead of writing everything in one Playbook, organize automation into Roles.

Example

```text id="czv54y"
roles/

├── nginx/

├── docker/

├── mysql/

└── monitoring/
```

Benefits

* Reusability
* Better organization
* Easy maintenance
* Team collaboration

---

# 3. Secure Secrets with Ansible Vault

Never store passwords or API keys in plain text.

Use **Ansible Vault** to encrypt sensitive information.

Examples

* Passwords
* API Keys
* SSH Private Keys
* Database Credentials
* Cloud Access Keys

Benefits

* Improved security
* Secure source code repository
* Safe team collaboration

---

# 4. Organize Inventory

Avoid storing all servers in a single inventory file.

Example

```text id="cpr5si"
inventory/

├── dev/

├── test/

├── uat/

└── production/
```

Benefits

* Easier management
* Environment isolation
* Better scalability

---

# 5. Use Git for Version Control

Store Playbooks and Roles in Git.

Benefits

* Version History
* Team Collaboration
* Rollback Changes
* Code Review
* Backup

Common Git Workflow

```text id="gv03dr"
Developer

↓

Git Repository

↓

Pull Request

↓

Review

↓

Merge
```

---

# 6. Separate Environments

Maintain separate inventories and variables for each environment.

Example

```text id="ebdnp8"
Development

↓

Testing

↓

UAT

↓

Production
```

Avoid using production variables in development.

# 8. Validate with ansible-lint

**ansible-lint** checks Playbooks for syntax errors and best practice violations.

Install

```bash id="8bydxy"
pip install ansible-lint
```

Run

```bash id="jr9z9q"
ansible-lint playbook.yml
```

Benefits

* Detect errors early
* Improve code quality
* Enforce standards

---

# 9. Test Roles with Molecule

**Molecule** is used to test Ansible Roles automatically.

It helps verify that Roles work correctly before deployment.

Typical Workflow

```text id="glv8xk"
Create Role

↓

Run Molecule Tests

↓

Verify Role

↓

Deploy
```

Benefits

* Automated testing
* Reliable Roles
* Early bug detection

---

# 10. Optimize Performance

Improve Playbook execution speed.

Recommendations

* Increase `forks`
* Enable `pipelining`
* Use Dynamic Inventory
* Cache Facts
* Use Tags
* Use `run_once`
* Use asynchronous tasks for long-running operations

Benefits

* Faster execution
* Better scalability
* Lower resource usage

# Interview Questions

### What is Idempotency?

Running the same Playbook multiple times produces the same desired state without unnecessary changes.

---

### Why use Roles?

Roles organize automation into reusable, modular components.

---

### Why use Ansible Vault?

To securely store sensitive information such as passwords, API keys, and certificates.

---

### Why separate Development and Production inventories?

To prevent accidental changes and keep environment-specific configurations isolated.

---

### What is ansible-lint?

A tool that checks Playbooks for syntax errors and best practice violations.

---

### What is Molecule?

A testing framework used to validate and test Ansible Roles.

---

### Why store Playbooks in Git?

Git provides version control, collaboration, code review, and rollback capabilities.

---

### How can Playbook performance be improved?

By increasing `forks`, enabling `pipelining`, caching Facts, using Tags, and avoiding unnecessary tasks.
