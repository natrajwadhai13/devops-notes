# 12. Templates (Jinja2)

## Learning Objectives

After completing this chapter, you will be able to:

- Understand Jinja2 Templates.
- Use Variables inside Templates.
- Use Loops in Templates.
- Use Conditions in Templates.
- Apply Jinja2 Filters.
- Generate Dynamic Configuration Files.
- Deploy Templates using the `template` module.
- Create reusable configuration files.

---

# What are Templates?

A **Template** is a file that contains **variables and Jinja2 expressions**.

Instead of creating multiple configuration files manually, one template can generate different configuration files for different servers.

Templates are usually saved with the **`.j2`** extension.

Example

```text
nginx.conf.j2

httpd.conf.j2

application.properties.j2
```

---

# What is Jinja2?

Jinja2 is a **Python-based Template Engine** used by Ansible.

It allows dynamic content generation using:

- Variables
- Loops
- Conditions
- Filters
- Expressions

---

# Why Use Templates?

Without Templates

```
web01.conf

web02.conf

web03.conf
```

You maintain three different files.

---

With Templates

```
nginx.conf.j2

↓

Variables

↓

Dynamic Configuration
```

Only one template is needed.

---

# Template Module

Ansible uses the **template** module to copy a template to the managed node.

Syntax

```yaml
- name: Deploy Template

  template:
    src: nginx.conf.j2

    dest: /etc/nginx/nginx.conf
```

# Variable Syntax

Variables are enclosed in double curly braces.

```jinja
{{ variable_name }}
```

Example

```jinja
server_name {{ inventory_hostname }};
```

---

# Using Variables

Playbook

```yaml
vars:
  http_port: 80

  server_name: web01
```

Template

```jinja
listen {{ http_port }};

server_name {{ server_name }};
```

Generated Output

```text
listen 80;

server_name web01;
```

---

# Loops

Generate repeated configuration.

Example

```jinja
upstream backend {

{% for server in servers %}

server {{ server }};

{% endfor %}

}
```

Variables

```yaml
servers:
  - 192.168.1.10

  - 192.168.1.11

  - 192.168.1.12
```

Generated Output

```text
upstream backend {

server 192.168.1.10;

server 192.168.1.11;

server 192.168.1.12;

}
```

---

# Conditions

Display content only when a condition is true.

Template

```jinja
{% if ssl_enabled %}

listen 443 ssl;

{% else %}

listen 80;

{% endif %}
```

Variable

```yaml
ssl_enabled: true
```

Generated Output

```text
listen 443 ssl;
```

---

# Filters

Filters modify variable values.

Uppercase

```jinja
{{ username | upper }}
```

Lowercase

```jinja
{{ username | lower }}
```

Default Value

```jinja
{{ server_name | default("localhost") }}
```

Length

```jinja
{{ users | length }}
```

Join

```jinja
{{ servers | join(",") }}
```

Replace

```jinja
{{ hostname | replace("-", "_") }}
```

---

# Comments

Jinja2 comments are not included in the generated file.

```jinja
{# This is a comment #}
```

---

# Whitespace Control

Remove extra spaces.

```jinja
{{- variable -}}
```

Useful for cleaner configuration files.

---

# Configuration Generation

Templates are commonly used to generate:

- nginx.conf
- httpd.conf
- haproxy.cfg
- application.properties
- sshd_config
- resolv.conf
- hosts
- Kubernetes YAML
- Docker Compose files

---

# Example 1: nginx.conf

Template

```jinja
server {

listen {{ http_port }};

server_name {{ inventory_hostname }};

root {{ document_root }};

}
```

Variables

```yaml
http_port: 80

document_root: /var/www/html
```

Generated Output

```text
server {

listen 80;

server_name web01;

root /var/www/html;

}
```

---

# Example 2: httpd.conf

Template

```jinja
Listen {{ apache_port }}

ServerName {{ inventory_hostname }}
```

Generated Output

```text
Listen 8080

ServerName web01
```

# Best Practices

- Keep templates simple.
- Use meaningful variable names.
- Avoid hardcoded values.
- Store templates in the `templates/` directory.
- Validate generated configuration before restarting services.
- Use Handlers to restart services only when templates change.

### What is the difference between the `copy` module and the `template` module?

| copy                             | template                                           |
| -------------------------------- | -------------------------------------------------- |
| Copies the file exactly as it is | Generates a dynamic file using Jinja2 variables    |
| No variable substitution         | Supports variables, loops, conditions, and filters |
| Best for static files            | Best for dynamic configuration files               |
