# 2. Installation and Setup

## 2.1 Terraform Installation

Terraform is available for Windows, Linux, and macOS.

Before installing Terraform, verify the operating system architecture:

```bash
terraform version
```

If Terraform is not installed, the command will return an error indicating that Terraform is not recognized.

---

## 2.2 Windows Installation

### Method 1: Install using Winget

Windows systems with `winget` can install Terraform using:

```powershell
winget install Hashicorp.Terraform
```

After installation, close and reopen the terminal.

Verify the installation:

```powershell
terraform version
```

Example:

```text
Terraform v1.x.x
on windows_amd64
```

---

## 2.3 Windows Manual Installation

Terraform can also be installed manually.

### Steps

1. Download the Terraform ZIP package for Windows.
2. Extract the ZIP file.
3. Locate `terraform.exe`.
4. Create a directory such as:

```text
C:\Terraform
```

5. Copy `terraform.exe` into this directory.
6. Add `C:\Terraform` to the Windows `PATH`.
7. Open a new terminal.
8. Verify the installation.

Check the executable location:

```powershell
where.exe terraform
```

Expected output:

```text
C:\Terraform\terraform.exe
```

---

## 2.9 Terraform Version Management

Terraform projects can require specific Terraform versions.

Example:

```hcl
terraform {
  required_version = ">= 1.5.0"
}
```

A project can also specify a version range:

```hcl
terraform {
  required_version = "~> 1.10"
}
```

This helps maintain consistency between development, testing, and production environments.

---

## 2.10 Terraform Configuration Files

Terraform configuration files normally use the `.tf` extension.

Common files include:

```text
main.tf
variables.tf
outputs.tf
providers.tf
versions.tf
terraform.tfvars
```

Terraform automatically loads `.tf` files in the current working directory.

### Example Project

```text
terraform-project/
├── main.tf
├── providers.tf
├── variables.tf
├── outputs.tf
└── terraform.tfvars
```

---

## 2.11 `main.tf`

`main.tf` commonly contains the primary infrastructure resources.

Example:

```hcl
resource "aws_instance" "web" {
  ami           = "ami-xxxxxxxx"
  instance_type = "t3.micro"
}
```

---

## 2.12 `providers.tf`

`providers.tf` commonly contains provider configuration.

Example:

```hcl
terraform {
  required_providers {
    aws = {
      source = "hashicorp/aws"
    }
  }
}

provider "aws" {
  region = "ap-south-1"
}
```

---

## 2.13 `variables.tf`

`variables.tf` contains input variable definitions.

Example:

```hcl
variable "instance_type" {
  type    = string
  default = "t3.micro"
}
```

---

## 2.14 `outputs.tf`

`outputs.tf` contains values that Terraform should display or expose.

Example:

```hcl
output "instance_id" {
  value = aws_instance.web.id
}
```

---

## 2.15 `terraform.tfvars`

`terraform.tfvars` can contain values for input variables.

Example:

```hcl
instance_type = "t3.micro"
```

Terraform automatically loads `terraform.tfvars`.

> Do not store passwords, access keys, or other sensitive information in Git.

---

## 2.16 Terraform Working Directory

Terraform works with the configuration files in the **current working directory**.

Example:

```bash
cd terraform-project
```

Then:

```bash
terraform init
```

Terraform reads the configuration files from this directory.

---

# 2.17 `terraform init`

`terraform init` is normally the **first Terraform command** executed in a new or cloned Terraform project.

```bash
terraform init
```

It initializes the working directory.

### What does `terraform init` do?

It can:

* Initialize the Terraform working directory
* Download required providers
* Initialize the configured backend
* Download required modules
* Prepare the directory for other Terraform commands

---

## 2.18 Files and Directories Created by `terraform init`

After running:

```bash
terraform init
```

Terraform may create:

```text
terraform-project/
├── .terraform/
│   └── providers/
│
├── .terraform.lock.hcl
├── main.tf
└── providers.tf
```

The `.terraform` directory contains Terraform working data such as downloaded provider packages.

The `.terraform.lock.hcl` file records provider selections and checksums to help ensure consistent provider installations.

### Important

`terraform init` **does not normally create**:

```text
main.tf
variables.tf
outputs.tf
providers.tf
```

These configuration files are created by the developer.

---

## 2.19 `.terraform` Directory

The `.terraform` directory is created and managed by Terraform.

Example:

```text
.terraform/
└── providers/
    └── registry.terraform.io/
```

It should generally **not be committed to Git**.

Add it to `.gitignore`:

```gitignore
.terraform/
```

---

## 2.20 `.terraform.lock.hcl`

Terraform creates `.terraform.lock.hcl` when provider dependency selections are initialized.

Example:

```text
terraform-project/
├── .terraform/
├── .terraform.lock.hcl
├── main.tf
└── providers.tf
```

The lock file helps Terraform use consistent provider versions and verify provider package checksums.

### Git recommendation

Unlike `.terraform/`, the lock file is generally **committed to Git**.

```text
.terraform/          → Do not commit
.terraform.lock.hcl  → Commit
```

---

## 2.21 Terraform Format

Terraform provides a formatter:

```bash
terraform fmt
```

It automatically formats Terraform configuration files according to Terraform's standard formatting conventions.

To format subdirectories recursively:

```bash
terraform fmt -recursive
```

---

## 2.22 Terraform Validate

Use:

```bash
terraform validate
```

This checks whether the Terraform configuration is syntactically valid and internally consistent.

Example:

```text
Success! The configuration is valid.
```

`terraform validate` does not create infrastructure.

---

## 2.23 Basic Terraform Workflow

After installation, the normal workflow is:

```text
Create Terraform Files
        ↓
terraform fmt
        ↓
terraform init
        ↓
terraform validate
        ↓
terraform plan
        ↓
terraform apply
```

---

## 2.24 First Terraform Project

Create a directory:

```bash
mkdir terraform-demo
cd terraform-demo
```

Create:

```text
main.tf
```

Add:

```hcl
terraform {
  required_providers {
    local = {
      source = "hashicorp/local"
    }
  }
}

provider "local" {}

resource "local_file" "example" {
  filename = "example.txt"
  content  = "Hello Terraform"
}
```

Initialize:

```bash
terraform init
```

Format:

```bash
terraform fmt
```

Validate:

```bash
terraform validate
```

Preview:

```bash
terraform plan
```

Apply:

```bash
terraform apply
```

Terraform will ask for confirmation before applying the changes.

---

## 2.25 Terraform Directory After Initialization

A basic project may look like:

```text
terraform-demo/
│
├── .terraform/
│   └── providers/
│
├── .terraform.lock.hcl
│
└── main.tf
```

After applying the configuration, Terraform will also create its state file:

```text
terraform.tfstate
```

---

## 2.26 Terraform State File

After `terraform apply`, Terraform normally creates:

```text
terraform.tfstate
```

The state file contains information Terraform uses to track managed infrastructure.

Example:

```text
terraform-demo/
├── .terraform/
├── .terraform.lock.hcl
├── main.tf
└── terraform.tfstate
```

The state file can contain sensitive information depending on the resources being managed.

**Never commit `terraform.tfstate` to a public Git repository.**

Add it to `.gitignore`:

```gitignore
.terraform/
terraform.tfstate
terraform.tfstate.*
*.tfstate.backup
```

---

## 2.27 Recommended `.gitignore`

A basic Terraform `.gitignore`:

```gitignore
# Terraform working directory
.terraform/

# Terraform state files
*.tfstate
*.tfstate.*
terraform.tfstate
terraform.tfstate.*

# Crash logs
crash.log
crash.*.log

# Variable files containing sensitive values
*.tfvars
*.tfvars.json

# Override files
override.tf
override.tf.json
*_override.tf
*_override.tf.json

# Terraform CLI configuration
.terraformrc
terraform.rc
```

The exact `.gitignore` rules can be adjusted depending on the project and whether `.tfvars` files contain only non-sensitive configuration.

## 2.29 Common Installation Problems

### Terraform command not found

Error:

```text
terraform is not recognized as an internal or external command
```

Possible causes:

* Terraform is not installed
* Terraform is not added to `PATH`
* Terminal was not restarted after installation

Check:

```powershell
where.exe terraform
```

---

### Multiple Terraform Versions

Check:

```powershell
where.exe terraform
```

If multiple paths are returned, multiple Terraform installations may exist.

Check the active version:

```bash
terraform version
```

---

### PATH Changes Not Reflected

After installing Terraform or changing the Windows `PATH`:

1. Close the terminal.
2. Close VS Code if necessary.
3. Reopen VS Code.
4. Open a new terminal.
5. Run:

```bash
terraform version
```

## 2.30 Interview Questions

### Q1. What does `terraform init` do?

`terraform init` initializes a Terraform working directory and downloads required providers and modules while initializing the configured backend.

### Q2. Does `terraform init` create `main.tf`?

No. `main.tf` is normally created by the developer.

### Q3. What is the `.terraform` directory?

It is Terraform's working directory containing initialization-related data such as downloaded providers and module information.

### Q4. Should `.terraform` be committed to Git?

No. It should normally be added to `.gitignore`.

### Q5. What is `.terraform.lock.hcl`?

It is a dependency lock file that records provider selections and checksums.

### Q6. Should `.terraform.lock.hcl` be committed?

Yes, it is generally recommended to commit it to version control.

### Q7. What does `terraform fmt` do?

It formats Terraform configuration files according to Terraform's standard formatting conventions.

### Q8. What does `terraform validate` do?

It checks whether the Terraform configuration is syntactically valid and internally consistent.

### Q9. What is `terraform.tfstate`?

It is Terraform's state file containing information used to track managed infrastructure.

### Q10. Should `terraform.tfstate` be committed to Git?

No. It can contain sensitive information and should normally be excluded from source control.
