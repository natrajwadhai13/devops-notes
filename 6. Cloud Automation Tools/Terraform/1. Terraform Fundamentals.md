# 1. Terraform Fundamentals

## 1.1 What is Terraform?

Terraform is an **Infrastructure as Code (IaC)** tool developed by **HashiCorp**.

It allows us to define, provision, modify, and manage infrastructure using configuration files instead of manually creating resources through cloud-provider consoles.

Terraform supports multiple cloud and infrastructure providers such as:

* AWS
* Microsoft Azure
* Google Cloud Platform (GCP)
* Kubernetes
* VMware
* GitHub
* Cloudflare

### Example

Instead of manually creating an AWS EC2 instance from the AWS Console, we can define it using Terraform:

```hcl
resource "aws_instance" "web" {
  ami           = "ami-xxxxxxxx"
  instance_type = "t3.micro"
}
```

Terraform reads this configuration and creates the required infrastructure.

---

## 1.2 What is Infrastructure as Code (IaC)?

**Infrastructure as Code (IaC)** is the practice of managing infrastructure through machine-readable configuration files.

Instead of manually performing:

```text
AWS Console
    ↓
Create VPC
    ↓
Create Subnet
    ↓
Create Security Group
    ↓
Create EC2
```

We define the infrastructure as code:

```text
Terraform Code
      ↓
Terraform Plan
      ↓
Terraform Apply
      ↓
Cloud Infrastructure
```

### Benefits of IaC

* Automation
* Repeatability
* Version control
* Consistency
* Faster provisioning
* Reduced human errors
* Easy disaster recovery
* Infrastructure auditing
* Easy environment creation

## 1.6 Declarative Approach

Terraform follows a **declarative approach**.

We define **what the desired infrastructure should look like**, and Terraform determines how to create or modify it.

Example:

```hcl
resource "aws_instance" "web" {
  instance_type = "t3.micro"
}
```

We do not normally specify every manual step such as:

```text
1. Login to AWS
2. Open EC2
3. Click Launch Instance
4. Select AMI
5. Select instance type
6. Create instance
```

Instead, we describe the desired state.

```text
Desired State
      ↓
Terraform
      ↓
Compare with Current State
      ↓
Required Changes
      ↓
Infrastructure
```

---

## 1.7 Declarative vs Imperative

### Declarative

Defines **what** the final state should be.

Examples:

* Terraform
* Kubernetes YAML

```text
Desired State
     ↓
Tool determines required actions
```

### Imperative

Defines **how** to perform the operation step-by-step.

Examples:

* Shell scripts
* Python scripts

```text
Step 1
  ↓
Step 2
  ↓
Step 3
  ↓
Step 4
```

## 1.8 Terraform vs Ansible

| Terraform                        | Ansible                                         |
| -------------------------------- | ----------------------------------------------- |
| Infrastructure provisioning      | Configuration management                        |
| Infrastructure as Code           | Configuration automation                        |
| Creates cloud resources          | Configures existing systems                     |
| Declarative                      | Mostly declarative                              |
| Manages infrastructure lifecycle | Manages server/application configuration        |
| Uses providers                   | Uses modules                                    |
| Uses Terraform state             | Does not normally require Terraform-style state |

### Example

Terraform:

```text
Create VPC
Create Subnet
Create EC2
Create Load Balancer
Create RDS
```

Ansible:

```text
Install Nginx
Configure Nginx
Deploy Application
Create Users
Modify Configuration
```

### Terraform + Ansible

They are often used together:

```text
Terraform
    ↓
Create Infrastructure
    ↓
EC2
    ↓
Ansible
    ↓
Configure Server
    ↓
Deploy Application
```

## 1.12 Terraform Limitations

* State management requires careful handling
* Secrets can become exposed if state is not secured
* Complex configurations can become difficult to maintain
* Provider behavior can vary
* Not primarily designed for application configuration management
* Provisioners should generally be avoided when better alternatives exist
* Large Terraform projects require proper module and state architecture

## 1.15 Important Terraform Terms

| Term            | Meaning                                                 |
| --------------- | ------------------------------------------------------- |
| **IaC**         | Infrastructure as Code                                  |
| **Provider**    | Interface between Terraform and an external platform    |
| **Resource**    | Infrastructure object managed by Terraform              |
| **Data Source** | Reads existing information                              |
| **State**       | Records Terraform's knowledge of managed infrastructure |
| **Module**      | Reusable Terraform configuration                        |
| **Backend**     | Defines where Terraform state is stored                 |
| **Plan**        | Shows proposed infrastructure changes                   |
| **Apply**       | Applies the planned changes                             |
| **Destroy**     | Removes managed infrastructure                          |

## 1.17 Interview Questions

### Q1. What is Terraform?

Terraform is an Infrastructure as Code tool developed by HashiCorp that allows infrastructure to be defined, provisioned, and managed using configuration files.

### Q2. Is Terraform declarative or imperative?

Terraform is primarily **declarative**.

### Q3. What is IaC?

Infrastructure as Code is the practice of managing infrastructure through code or configuration instead of manually provisioning it.

### Q4. What is Terraform mainly used for?

Terraform is mainly used for infrastructure provisioning and infrastructure lifecycle management.

### Q5. Terraform vs Ansible?

Terraform is primarily used for **infrastructure provisioning**, while Ansible is commonly used for **configuration management and server/application automation**.

### Q6. What is a Terraform provider?

A provider is a plugin that allows Terraform to communicate with a specific platform or service such as AWS, Azure, GCP, or Kubernetes.

### Q7. What is Terraform state?

Terraform state is the record Terraform uses to map its configuration to real-world infrastructure and track managed resources.

### Q8. What does `terraform plan` do?

It creates an execution plan showing what Terraform intends to create, modify, or destroy.

### Q9. What does `terraform apply` do?

It applies the proposed changes and creates, updates, or destroys infrastructure according to the configuration.

### Q10. What does `terraform destroy` do?

It destroys resources managed by Terraform.
