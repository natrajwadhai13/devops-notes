# Q51. What is NFS?

## Answer

**NFS (Network File System)** is a network-based filesystem that allows a client server to access and use directories/files located on a remote NFS server as if they were local filesystems.

### Example

```text
NFS Server
10.10.10.10
     |
     | Network
     |
NFS Client
10.10.10.20
```

The NFS server shares:

```text
/data/app
```

The client mounts it:

```text
/mnt/app
```

The application can then access `/mnt/app` as a normal filesystem.

---

## Common NFS Versions

* NFSv3
* NFSv4

NFSv4 is commonly preferred in modern environments.

---

## Important Files/Commands

Server:

```bash
/etc/exports
exportfs
```

Client:

```bash
/etc/fstab
mount
```

---

## Interview Tip

Remember:

> `/etc/exports` → NFS server-side exports
> `/etc/fstab` → persistent client-side mounts

# Q52. NFS mount is failing. How do you troubleshoot?

## Answer

Follow a structured approach.

### Step 1: Check Network Connectivity

```bash
ping <nfs-server-ip>
```

---

### Step 2: Check NFS Server

```bash
systemctl status nfs-server
```

---

### Step 3: Check Export

On the server:

```bash
exportfs -v
```

---

### Step 4: Check Available Exports

From client:

```bash
showmount -e <nfs-server>
```

---

### Step 5: Test Mount Manually

```bash
mount -t nfs <server>:/data /mnt/data
```

---

### Step 6: Check Mount

```bash
mount | grep /mnt/data
```

or:

```bash
findmnt /mnt/data
```

---

### Step 7: Check Firewall

```bash
firewall-cmd --list-services
```

---

### Step 8: Check Logs

```bash
journalctl -u nfs-server
```

---

## Common Causes

* NFS service stopped
* Wrong export path
* Network issue
* Firewall
* Permission problem
* Incorrect NFS version
* Wrong server IP/hostname

# Q53. NFS server is not exporting the directory. How do you troubleshoot?

## Answer

First check `/etc/exports`.

```bash
cat /etc/exports
```

Example:

```text
/data 192.168.1.0/24(rw,sync)
```

Reload exports:

```bash
exportfs -rav
```

Verify:

```bash
exportfs -v
```

From client:

```bash
showmount -e <server-ip>
```

---

## Common Mistakes

Incorrect:

```text
/data 192.168.1.0/24
```

Correct options should be explicitly configured according to the requirement, for example:

```text
/data 192.168.1.0/24(rw,sync)
```

<a id="q54"></a>

# Q54. What is `/etc/exports`?

## Answer

`/etc/exports` is the primary NFS server configuration file.

It defines:

* Which directory is shared
* Which clients can access it
* Read/write permissions
* NFS export options

### Example

```text
/data 192.168.1.100(rw,sync)
```

This means `/data` is exported to `192.168.1.100` with read/write access.

---

## Common Options

| Option           | Meaning                            |
| ---------------- | ---------------------------------- |
| `rw`             | Read/write                         |
| `ro`             | Read-only                          |
| `sync`           | Write changes synchronously        |
| `async`          | Asynchronous writes                |
| `root_squash`    | Maps remote root to anonymous user |
| `no_root_squash` | Does not squash remote root        |
| `all_squash`     | Maps all users to anonymous user   |

---

## Security Tip

Prefer `root_squash` unless there is a specific requirement not to use it.

# Q55. How do you verify NFS exports?

## Answer

On the NFS server:

```bash
exportfs -v
```

Show current exports:

```bash
exportfs -s
```

From the client:

```bash
showmount -e <nfs-server>
```

---

## Example

```bash
showmount -e 10.10.10.10
```

Possible output:

```text
Export list for 10.10.10.10:
/data  192.168.1.0/24
```

# Q56. NFS mount shows "Permission denied". How do you troubleshoot?

## Answer

Check the export configuration, client IP, filesystem permissions, SELinux, and NFS options.

### Step 1: Check Export

```bash
cat /etc/exports
```

### Step 2: Verify Export

```bash
exportfs -v
```

### Step 3: Check Client IP

```bash
ip addr
```

Make sure the client is allowed in `/etc/exports`.

### Step 4: Check Directory Permissions

```bash
ls -ld /data
```

### Step 5: Check SELinux

```bash
getenforce
```

### Step 6: Check Logs

```bash
journalctl -xe
```

---

## Common Causes

* Client IP not allowed
* Wrong export options
* Filesystem permissions
* SELinux
* Root squashing
* Incorrect UID/GID mapping

# Q57. What is "Stale file handle" in NFS?

## Answer

A **stale file handle** occurs when the NFS client has a reference to a file or directory that no longer exists or has changed on the NFS server.

Example:

```text
Stale file handle
```

---

## Common Causes

* NFS server filesystem was unmounted/remounted
* Exported directory was recreated
* Filesystem changed
* NFS server restarted under certain conditions

---

## Troubleshooting

Check mount:

```bash
mount | grep nfs
```

Try accessing the mount:

```bash
ls -la /mnt/data
```

Unmount:

```bash
umount /mnt/data
```

If busy:

```bash
fuser -vm /mnt/data
```

Then remount:

```bash
mount /mnt/data
```

---

## Interview Tip

Do not immediately force-unmount a production NFS filesystem.

First identify processes using the mount.

# Q58. NFS service is running but the client cannot mount. What do you check?

## Answer

Check the complete path from client to server.

### Server

```bash
systemctl status nfs-server
```

### Exports

```bash
exportfs -v
```

### Client

```bash
showmount -e <server-ip>
```

### Network

```bash
ping <server-ip>
```

### Firewall

```bash
firewall-cmd --list-all
```

### Ports

For NFSv4, TCP **2049** is the key NFS service port.

Check:

```bash
ss -lntp | grep 2049
```

---

## Common Causes

* Firewall
* Incorrect export
* Wrong NFS version
* Network connectivity
* DNS resolution
* SELinux
* NFS service dependency

# Q59. How do you troubleshoot NFS performance issues?

## Answer

First determine whether the bottleneck is **network, NFS server, client, storage, or application**.

---

## Check Client

```bash
iostat -xz 1
```

```bash
nfsstat -c
```

---

## Check Server

```bash
nfsstat -s
```

---

## Check Network

```bash
sar -n DEV 1
```

```bash
ss -s
```

---

## Check CPU/Memory

```bash
top
```

```bash
free -h
```

---

## Check Disk

```bash
iostat -xz 1
```

---

## Common Causes

* High disk latency
* Network congestion
* High server load
* Too many NFS requests
* Slow underlying storage
* Incorrect mount options
* Application generating excessive I/O

# Q60. An NFS mount suddenly stopped working in production. How do you troubleshoot?

## Answer

I would follow a structured incident approach.

### 1. Check Impact

Determine:

* Which servers are affected?
* Which mount is affected?
* Is the application down?
* Is it read-only or completely unavailable?

---

### 2. Check Mount

```bash
findmnt
```

```bash
mount | grep nfs
```

---

### 3. Test NFS Server

```bash
ping <nfs-server>
```

```bash
showmount -e <nfs-server>
```

---

### 4. Check NFS Server

```bash
systemctl status nfs-server
```

```bash
exportfs -v
```

---

### 5. Check Network

```bash
ip route
```

```bash
ss -nt
```

---

### 6. Check Firewall

```bash
firewall-cmd --list-all
```

---

### 7. Check Logs

```bash
journalctl -xe
```

```bash
dmesg | tail -50
```

---

### 8. Check Processes

If the filesystem is stuck:

```bash
fuser -vm /mnt/data
```

---

### 9. Validate Recovery

After fixing the root cause:

```bash
ls -la /mnt/data
```

Verify that the application can read/write the required files.

---

## Possible Root Causes

* NFS server outage
* Network failure
* Firewall change
* Export configuration change
* Storage failure
* Stale NFS handle
* DNS issue
* NFS version mismatch
* Server overload
