# Q71. What is LVM?

## Answer

**LVM (Logical Volume Manager)** is a Linux storage management system that provides flexible management of disks and filesystems.

The main LVM components are:

```text
Physical Disk
     |
     v
Physical Volume (PV)
     |
     v
Volume Group (VG)
     |
     v
Logical Volume (LV)
     |
     v
Filesystem
```

Example:

```text
/dev/sdb
   |
   +-- PV
       |
       +-- VG: vg_data
              |
              +-- LV: lv_app
                     |
                     +-- /app
```

### Advantages

* Easily extend storage
* Combine multiple disks
* Flexible disk management
* Logical volumes can span multiple physical disks
* Supports snapshots
* Simplifies storage administration

### Common LVM Commands

```bash
pvs
vgs
lvs
```

### Interview Tip

> "LVM provides an abstraction layer between physical storage and the filesystem, allowing logical volumes to be managed more flexibly."

<a id="q73"></a>

# Q73. How do you extend a logical volume?

## Answer

First check available space:

```bash
vgs
```

Check the LV:

```bash
lvs
```

Example:

```text
VG       VSize   VFree
vg_data  100G     20G
```

Extend the LV by 10 GB:

```bash
lvextend -L +10G /dev/vg_data/lv_app
```

Then extend the filesystem.

For **XFS**:

```bash
xfs_growfs /app
```

For **ext4**:

```bash
resize2fs /dev/vg_data/lv_app
```

### Easier Method

`lvextend -r` can extend the LV and resize a supported filesystem automatically:

```bash
lvextend -r -L +10G /dev/vg_data/lv_app
```

### Verify

```bash
lvs
df -h /app
```

### Interview Tip

> "When extending LVM, I check VG free space, extend the LV, then grow the filesystem. With `lvextend -r`, the filesystem resize can be performed automatically for supported filesystems."

<a id="q74"></a>

# Q74. What is the difference between extending an LV and extending the filesystem?

## Answer

An LVM logical volume and its filesystem are two different layers.

```text
VG
 |
 +-- LV  ← Storage block device
      |
      +-- Filesystem
           |
           +-- Files/directories
```

If you only extend the LV:

```bash
lvextend -L +10G /dev/vg_data/lv_app
```

the underlying block device becomes larger, but the filesystem may still report the old size.

Check:

```bash
lvs
df -h
```

You may need to grow the filesystem separately.

### XFS

```bash
xfs_growfs /app
```

### ext4

```bash
resize2fs /dev/vg_data/lv_app
```

### Interview Tip

> "LV size and filesystem size are separate. Increasing the LV does not automatically mean the filesystem can use the additional space unless the filesystem is also grown."

# Q75. How do you extend an LVM filesystem in production?

## Answer

Suppose `/data` is full.

### Step 1: Check filesystem

```bash
df -h /data
```

### Step 2: Check LV

```bash
lvs
```

### Step 3: Check VG free space

```bash
vgs
```

Example:

```text
VG       VSize   VFree
vg_data  200G     50G
```

### Step 4: Extend the LV

```bash
lvextend -L +20G /dev/vg_data/lv_data
```

### Step 5: Grow the filesystem

For XFS:

```bash
xfs_growfs /data
```

For ext4:

```bash
resize2fs /dev/vg_data/lv_data
```

### Step 6: Verify

```bash
lvs
df -h /data
```

### Production Checklist

```text
Check current usage
       ↓
Check LV size
       ↓
Check VG free space
       ↓
Confirm change approval
       ↓
Extend LV
       ↓
Grow filesystem
       ↓
Verify capacity
       ↓
Check application
```

### Interview Tip

> "Before extending production storage, I verify the filesystem type, LV size, VG free space, and change approval. After the change I verify both `lvs` and `df -h` and confirm application health."

# Q76. How do you reduce an LVM logical volume?

## Answer

**Reducing an LV is more dangerous than extending it.**

The filesystem must support shrinking.

For example, `ext4` can be reduced, while **XFS cannot be shrunk in place**.

### Example: ext4

Suppose:

```text
Current LV = 100G
Required LV = 80G
```

First check the filesystem:

```bash
df -Th /data
```

Unmount the filesystem:

```bash
umount /data
```

Check the filesystem:

```bash
e2fsck -f /dev/vg_data/lv_data
```

Resize the filesystem first:

```bash
resize2fs /dev/vg_data/lv_data 80G
```

Then reduce the LV:

```bash
lvreduce -L 80G /dev/vg_data/lv_data
```

Mount again:

```bash
mount /data
```

Verify:

```bash
df -h /data
lvs
```

### For XFS

XFS does **not** support shrinking an existing filesystem in place.

Typical approach:

```text
Backup data
   ↓
Create smaller filesystem
   ↓
Restore data
   ↓
Remove/recreate LV as required
```

### Interview Tip

> "I treat LV reduction as a high-risk operation. I first verify the filesystem supports shrinking, reduce the filesystem before reducing the LV, and always have a backup and recovery plan."

<a id="q77"></a>

# Q77. What happens if you reduce an LV incorrectly?

## Answer

If the LV is reduced below the actual filesystem/data size, filesystem metadata or user data can be destroyed.

Possible results:

* Filesystem corruption
* Data loss
* Filesystem mount failure
* Application failure
* Recovery requirement

For example, this is dangerous:

```bash
lvreduce -L 50G /dev/vg_data/lv_data
```

if the filesystem still requires more than 50 GB.

### Correct Principle

For filesystems that support shrinking:

```text
Filesystem
    ↓
Shrink filesystem first
    ↓
Shrink LV
```

**Never reverse the order.**

### Interview Tip

> "Reducing the LV first can cut off filesystem blocks and cause data loss. I always shrink the filesystem first, then reduce the logical volume."

<a id="q78"></a>

# Q78. How do you add a new disk to an existing LVM volume group?

## Answer

Suppose a new disk `/dev/sdc` is attached.

### Step 1: Verify Disk

```bash
lsblk
```

### Step 2: Create Physical Volume

If using the whole disk:

```bash
pvcreate /dev/sdc
```

Verify:

```bash
pvs
```

### Step 3: Add PV to Volume Group

```bash
vgextend vg_data /dev/sdc
```

Verify:

```bash
vgs
```

Now the VG has additional free space.

### Step 4: Extend LV

```bash
lvextend -r -L +50G /dev/vg_data/lv_data
```

### Step 5: Verify

```bash
pvs
vgs
lvs
df -h /data
```

### Flow

```text
New Disk
   ↓
/dev/sdc
   ↓
pvcreate
   ↓
Physical Volume
   ↓
vgextend
   ↓
Volume Group
   ↓
lvextend
   ↓
Filesystem
```

### Interview Tip

> "I first verify the newly presented disk, create a PV using `pvcreate`, add it to the VG with `vgextend`, and then allocate the required space to the LV."

# Q79. What do you do when a volume group has no free space?

## Answer

Check VG space:

```bash
vgs
```

Example:

```text
VG       VSize   VFree
vg_data  100G      0
```

If there is no free space, an LV cannot be extended from the existing VG.

### Option 1: Add a New Disk

```bash
pvcreate /dev/sdc
vgextend vg_data /dev/sdc
```

Then:

```bash
lvextend -r -L +20G /dev/vg_data/lv_data
```

### Option 2: Check Other LVs

```bash
lvs
```

Identify unused or unnecessary LVs.

### Option 3: Review Storage Allocation

Check whether other volumes can safely release space according to the storage design and filesystem capabilities.

### Important

Do not randomly remove an LV to create space.

Before modifying an LV, verify:

```bash
lsblk
lvs
df -h
mount
```

### Interview Tip

> "If a VG has no free extents, I normally add another PV and extend the VG. I don't reduce or remove another LV without confirming its purpose, filesystem support, backup, and change plan."

# Q80. How do you troubleshoot an LVM logical volume that is not available?

## Answer

First inspect the LVM configuration:

```bash
pvs
vgs
lvs
```

Check whether the LV exists:

```bash
lvdisplay
```

Check block devices:

```bash
lsblk
```

Check device mapper:

```bash
ls -l /dev/mapper/
```

Try activating the volume group:

```bash
vgchange -ay
```

Then verify:

```bash
lvs
lsblk
```

### Check for Disk/Storage Problems

```bash
dmesg | tail -50
```

```bash
lsblk
```

```bash
pvs
```

### Common Causes

* Volume group not activated
* Physical disk missing
* PV metadata problem
* Storage presentation issue
* Device mapper problem
* Filesystem problem
* Incorrect `/etc/fstab`
* Underlying disk failure

### If PV Is Missing

Check:

```bash
pvs
vgs
lvs
```

Look for missing PVs.

Do **not** immediately recreate or initialize the disk because that can destroy existing LVM metadata and data.

### Interview Tip

> "I first determine whether the problem is at the PV, VG, LV, or filesystem layer. I check `pvs`, `vgs`, `lvs`, `lsblk`, and kernel logs before attempting recovery."

# 📌 Important LVM Commands

| Command        | Purpose                             |
| -------------- | ----------------------------------- |
| `pvs`          | Display physical volumes            |
| `pvdisplay`    | Detailed PV information             |
| `pvcreate`     | Create a physical volume            |
| `vgs`          | Display volume groups               |
| `vgdisplay`    | Detailed VG information             |
| `vgcreate`     | Create a volume group               |
| `vgextend`     | Add PV to a VG                      |
| `vgreduce`     | Remove PV from a VG                 |
| `vgchange -ay` | Activate volume groups              |
| `lvs`          | Display logical volumes             |
| `lvdisplay`    | Detailed LV information             |
| `lvcreate`     | Create logical volume               |
| `lvextend`     | Extend logical volume               |
| `lvreduce`     | Reduce logical volume               |
| `lvremove`     | Remove logical volume               |
| `lsblk`        | Display block devices               |
| `blkid`        | Display filesystem/UUID information |

# 📌 LVM Troubleshooting Flow

```text
Storage Problem
      |
      v
    lsblk
      |
      v
     pvs
      |
      v
     vgs
      |
      v
     lvs
      |
      +------ PV problem?
      |         ↓
      |       Check disk/storage
      |
      +------ VG has free space?
      |         ↓
      |       lvextend
      |
      +------ VG full?
      |         ↓
      |       Add new PV
      |       vgextend
      |
      +------ LV exists but filesystem small?
                ↓
          Grow filesystem
          xfs_growfs / resize2fs
```

```text
PV → VG → LV → Filesystem → Mount Point
```

Remember the troubleshooting order:

```text
Disk
 ↓
PV
 ↓
VG
 ↓
LV
 ↓
Filesystem
 ↓
Mount Point
 ↓
Application
```
