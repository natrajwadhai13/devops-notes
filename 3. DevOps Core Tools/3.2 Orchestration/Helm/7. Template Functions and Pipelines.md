# 1. What are Template Functions?

Helm provides many built-in functions that can ****modify, format, convert, or process data**** inside templates.

Example:

{% raw %}
```yaml
name: {{ .Values.appName | quote }}
```
{% endraw %}

Here:

```text
.Values.appName
       ↓
     quote
       ↓
"myapp"
```

Functions are used to make Helm templates more flexible and reusable.

---

# 2. What is a Pipeline? ⭐⭐⭐⭐⭐

A ****pipeline**** passes the output of one operation into another function.

Syntax:

```text
value | function
```

Example:

{% raw %}
```yaml
name: {{ .Values.appName | quote }}
```
{% endraw %}

Multiple functions:

{% raw %}
```yaml
name: {{ .Values.appName | upper | quote }}
```
{% endraw %}

Flow:

```text
.Values.appName
       ↓
     upper
       ↓
     quote
       ↓
"MYAPP"
```

# 3. `quote` ⭐⭐⭐⭐⭐

Adds double quotes around a value.

{% raw %}
```yaml
value: {{ .Values.environment | quote }}
```
{% endraw %}

If:

```yaml
environment: production
```

Output:

```yaml
value: "production"
```

Very commonly used for Kubernetes environment variables.

Example:

{% raw %}
```yaml
env:
  - name: APP_ENV
    value: {{ .Values.environment | quote }}
```
{% endraw %}

---

# 4. `default` ⭐⭐⭐⭐⭐

Provides a fallback value if the input is empty.

{% raw %}
```yaml
replicas: {{ .Values.replicaCount | default 1 }}
```
{% endraw %}

If:

```yaml
replicaCount: 3
```

Output:

```yaml
replicas: 3
```

If the value is empty/not supplied:

```yaml
replicas: 1
```

### Important

`default` is useful when a value has a sensible fallback.

---

# 5. `required` ⭐⭐⭐⭐

`required` makes a value mandatory.

{% raw %}
```yaml
image: {{ required "image.repository is required" .Values.image.repository }}
```
{% endraw %}

If the value is missing, Helm stops rendering and displays an error.

Example error concept:

```text
Error: execution error:
image.repository is required
```

Use `required` for important configuration that must be provided.

---

# 6. `toYaml` ⭐⭐⭐⭐⭐

`toYaml` converts a value into YAML format.

Example `values.yaml`:

```yaml
resources:
  requests:
    cpu: 100m
    memory: 128Mi
  limits:
    cpu: 500m
    memory: 512Mi
```

Template:

{% raw %}
```yaml
resources:
{{- toYaml .Values.resources | nindent 2 }}
```
{% endraw %}

Output:

```yaml
resources:
  requests:
    cpu: 100m
    memory: 128Mi
  limits:
    cpu: 500m
    memory: 512Mi
```

This is ****extremely common in real Helm Charts****.

---

# 7. `nindent` ⭐⭐⭐⭐⭐

`nindent` adds a newline and indentation.

Example:

{% raw %}
```yaml
labels:
{{- toYaml .Values.labels | nindent 4 }}
```
{% endraw %}

If:

```yaml
labels:
  app: myapp
  environment: production
```

The generated YAML is correctly indented:

```yaml
labels:
    app: myapp
    environment: production
```

### Common combination

```text
toYaml | nindent
```

Remember:

```text
toYaml
   ↓
Convert object to YAML

nindent
   ↓
Indent the YAML correctly
```

---

# 8. `indent`

`indent` adds indentation but does not add the initial newline in the same way `nindent` does.

Example:

{% raw %}
```yaml
{{ .Values.config | toYaml | indent 4 }}
```
{% endraw %}

In practice, you will frequently see:

{% raw %}
```yaml
{{- toYaml .Values.config | nindent 4 }}
```
{% endraw %}

### Interview point

```text
indent → indentation
nindent → newline + indentation
```

---

# 9. `trim`

Removes whitespace from the beginning and end of a string.

Example:

{% raw %}
```yaml
name: {{ .Values.name | trim | quote }}
```
{% endraw %}

Useful when values may contain unwanted spaces.

---

# 10. `trimSuffix`

Removes a specific suffix.

Example:

{% raw %}
```yaml
{{ "myapp-" | trimSuffix "-" }}
```
{% endraw %}

Result:

```text
myapp
```

Useful when constructing names dynamically.

---

# 11. `trimPrefix`

Removes a specific prefix.

Example:

{% raw %}
```yaml
{{ "app-myapp" | trimPrefix "app-" }}
```
{% endraw %}

Result:

```text
myapp
```

---

# 12. `upper`

Converts text to uppercase.

{% raw %}
```yaml
{{ .Values.environment | upper }}
```
{% endraw %}

If:

```text
production
```

Result:

```text
PRODUCTION
```

---

# 13. `lower`

Converts text to lowercase.

{% raw %}
```yaml
{{ .Values.environment | lower }}
```
{% endraw %}

Example:

```text
PRODUCTION
```

becomes:

```text
production
```

---

# 14. `replace`

Replaces text inside a string.

Example:

{% raw %}
```yaml
{{ "my-app-prod" | replace "-" "_" }}
```
{% endraw %}

Result:

```text
my_app_prod
```

Useful when transforming names or configuration strings.

---

# 15. `printf` ⭐⭐⭐⭐

`printf` formats strings.

Example:

{% raw %}
```yaml
name: {{ printf "%s-%s" .Release.Name .Chart.Name }}
```
{% endraw %}

If:

```text
Release Name = myapp
Chart Name   = nginx
```

Output:

```yaml
name: myapp-nginx
```

This is useful for dynamically constructing resource names.

---

# 16. `list`

Creates a list.

Example:

{% raw %}
```yaml
{{ list "dev" "test" "prod" }}
```
{% endraw %}

Result conceptually:

```text
[dev test prod]
```

Can be useful when passing multiple values to templates/functions.

---

# 17. `dict`

Creates a dictionary/map.

Example:

{% raw %}
```yaml
{{ dict "name" "myapp" "environment" "prod" }}
```
{% endraw %}

Conceptually:

```text
name: myapp
environment: prod
```

`dict` is especially useful when working with reusable named templates.

---

# 18. `lookup` ⭐⭐⭐

`lookup` allows a Helm template to query an existing Kubernetes resource.

General syntax:

```text
lookup apiVersion kind namespace name
```

Example:

{% raw %}
```yaml
{{ lookup "v1" "ConfigMap" .Release.Namespace "my-config" }}
```
{% endraw %}

It can be useful when a template needs information from an existing Kubernetes resource.

### Important

`lookup` interacts with the Kubernetes cluster, unlike normal template functions that simply process local values.

For your initial Helm learning, understand the concept; deep usage can come later.

---

# 19. Combining Functions ⭐⭐⭐⭐⭐

The real power of Helm comes from combining functions.

Example:

{% raw %}
```yaml
name: {{ .Values.appName | lower | trim | quote }}
```
{% endraw %}

Flow:

```text
.Values.appName
       ↓
     lower
       ↓
     trim
       ↓
     quote
       ↓
"myapp"
```

# 20. Important Real-World Example

`values.yaml`:

```yaml
labels:
  app: myapp
  environment: production

resources:
  requests:
    cpu: 100m
    memory: 128Mi
```

Template:

{% raw %}
```yaml
metadata:
  labels:
{{- toYaml .Values.labels | nindent 4 }}

spec:
  containers:
    - name: myapp
      resources:
{{- toYaml .Values.resources | nindent 8 }}
```
{% endraw %}

Here:

```text
toYaml
```

converts the map to YAML.

Then:

```text
nindent
```

correctly positions the generated YAML.

This pattern is ****very common in production Helm Charts****.

# 21. Function vs Pipeline

### Function style

{% raw %}
```yaml
{{ quote .Values.appName }}
```
{% endraw %}

### Pipeline style

{% raw %}
```yaml
{{ .Values.appName | quote }}
```
{% endraw %}

Both can perform the same operation.

Pipeline style is generally easier to read when chaining multiple functions.

Example:

{% raw %}
```yaml
{{ .Values.appName | lower | trim | quote }}
```
{% endraw %}

# 23. Debugging Functions and Pipelines ⭐⭐⭐⭐⭐

When working with functions, always inspect the generated YAML.

```bash
helm template myapp ./mychart
```

For more debugging:

```bash
helm install myapp ./mychart --dry-run --debug
```

Validate:

```bash
helm lint ./mychart
```

A large number of Helm issues are actually ****YAML indentation or template rendering problems****.

# Quick Interview Revision

****Q: What is a Helm pipeline?****

→ A pipeline passes the output of one expression/function to another function.

{% raw %}
```yaml
{{ .Values.name | quote }}
```
{% endraw %}

****Q: What does `toYaml` do?****

→ Converts a Helm value/object into YAML.

****Q: Why is `nindent` commonly used with `toYaml`?****

→ To correctly indent the generated YAML.

{% raw %}
```yaml
{{- toYaml .Values.resources | nindent 8 }}
```
{% endraw %}

****Q: Difference between `indent` and `nindent`?****

→ `indent` adds indentation; `nindent` adds a newline and then indentation.

****Q: What does `default` do?****

→ Provides a fallback value.

{% raw %}
```yaml
{{ .Values.replicas | default 1 }}
```
{% endraw %}

****Q: What does `required` do?****

→ Forces a value to be provided and fails template rendering if it is missing.

****Q: Why use `quote`?****

→ To safely render a value as a quoted string, especially for Kubernetes environment variables.

****Q: How do you debug a template?****

```bash
helm template myapp ./mychart
helm lint ./mychart
helm install myapp ./mychart --dry-run --debug
```
