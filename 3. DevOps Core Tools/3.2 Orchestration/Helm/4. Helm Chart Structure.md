## 1. What is a Helm Chart?

A **Helm Chart** is a package containing all the files required to deploy an application to Kubernetes.

Create a new chart:

```bash
helm create myapp
```

Basic structure:

```text
myapp/
├── Chart.yaml
├── values.yaml
├── charts/
├── templates/
│   ├── deployment.yaml
│   ├── service.yaml
│   ├── ingress.yaml
│   ├── configmap.yaml
│   ├── serviceaccount.yaml
│   ├── _helpers.tpl
│   └── tests/
└── .helmignore
```

---

# 2. `Chart.yaml` ⭐⭐⭐⭐⭐

`Chart.yaml` contains the **metadata and information about the Helm Chart**.

Example:

```yaml
apiVersion: v2
name: myapp
description: A Helm chart for my application
type: application
version: 0.1.0
appVersion: "1.0.0"
```

### Important fields

| Field         | Purpose                    |
| ------------- | -------------------------- |
| `apiVersion`  | Helm Chart API version     |
| `name`        | Chart name                 |
| `description` | Description of chart       |
| `type`        | `application` or `library` |
| `version`     | Chart version              |
| `appVersion`  | Application version        |

### Important difference ⭐

```text
version
   ↓
Helm Chart version

appVersion
   ↓
Application version
```

For example:

```yaml
version: 1.2.0
appVersion: "5.6.1"
```

The Chart has version **1.2.0**, while the application deployed by the Chart is version **5.6.1**.

---

# 3. `values.yaml` ⭐⭐⭐⭐⭐

`values.yaml` contains the **default configuration values** for the Chart.

Example:

```yaml
replicaCount: 2

image:
  repository: nginx
  tag: "1.27"

service:
  type: ClusterIP
  port: 80
```

These values are accessed from templates using:

```yaml
{{ .Values.replicaCount }}
```

For example:

```yaml
spec:
  replicas: {{ .Values.replicaCount }}
```

Helm replaces the value:

```yaml
replicas: 2
```

---

# 4. `templates/` Directory ⭐⭐⭐⭐⭐

The `templates/` directory contains Kubernetes resource templates.

Example:

```text
templates/
├── deployment.yaml
├── service.yaml
├── ingress.yaml
├── configmap.yaml
├── serviceaccount.yaml
├── _helpers.tpl
└── tests/
```

Common Kubernetes resources:

```text
Deployment
Service
ConfigMap
Secret
Ingress
ServiceAccount
HPA
PVC
```

Helm processes these templates and generates normal Kubernetes YAML.

---

# 5. `templates/deployment.yaml`

Example:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "myapp.fullname" . }}
spec:
  replicas: {{ .Values.replicaCount }}
```

Here:

```text
.Values.replicaCount
```

comes from:

```yaml
values.yaml
```

So Helm combines:

```text
values.yaml
      +
deployment.yaml template
      ↓
Kubernetes Deployment YAML
```

---

# 6. `templates/service.yaml`

Defines the Kubernetes Service.

Example:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: {{ include "myapp.fullname" . }}
spec:
  type: {{ .Values.service.type }}
  ports:
    - port: {{ .Values.service.port }}
```

Values:

```yaml
service:
  type: ClusterIP
  port: 80
```

Generated YAML:

```yaml
type: ClusterIP
ports:
  - port: 80
```

---

# 7. `templates/_helpers.tpl` ⭐⭐⭐⭐

`_helpers.tpl` contains **reusable named templates**.

Example:

```yaml
{{- define "myapp.name" -}}
{{- default .Chart.Name .Values.nameOverride | trunc 63 | trimSuffix "-" }}
{{- end }}
```

You can use it in other templates:

```yaml
name: {{ include "myapp.name" . }}
```

### Why use `_helpers.tpl`?

* Avoid duplicate code
* Create reusable naming logic
* Create common labels
* Keep templates clean

The `_helpers.tpl` file itself does **not create a Kubernetes resource**.

---

# 8. `charts/` Directory ⭐⭐⭐

The `charts/` directory is used for **Chart dependencies**.

Example:

```text
myapp/
├── Chart.yaml
├── values.yaml
├── charts/
│   └── redis/
└── templates/
```

Here `redis` can be a dependency of `myapp`.

Dependencies can also be defined in `Chart.yaml`.

Example:

```yaml
dependencies:
  - name: redis
    version: "20.x.x"
    repository: "https://charts.bitnami.com/bitnami"
```

Then:

```bash
helm dependency update
```

---

# 9. `.helmignore`

`.helmignore` specifies files that should be excluded when packaging a Helm Chart.

Similar concept to:

```text
.gitignore
```

Example:

```text
.git/
.gitignore
README.md
*.tmp
```

When you run:

```bash
helm package myapp
```

ignored files are not included in the packaged chart.

---

# 10. `templates/tests/`

Helm can contain test templates.

Example:

```text
templates/
└── tests/
    └── test-connection.yaml
```

Run Helm tests:

```bash
helm test myapp
```

These tests can verify whether the deployed application is working as expected.

# 12. How Helm Chart Works ⭐⭐⭐⭐⭐

The most important concept is:

```text
                  Helm Chart
                      │
          ┌───────────┴───────────┐
          │                       │
     values.yaml              templates/
          │                       │
          └───────────┬───────────┘
                      ↓
                Helm Template Engine
                      ↓
             Kubernetes YAML
                      ↓
              Kubernetes API
                      ↓
               Kubernetes Cluster
```

Example:

`values.yaml`:

```yaml
replicaCount: 3
```

Template:

```yaml
replicas: {{ .Values.replicaCount }}
```

Helm generates:

```yaml
replicas: 3
```

# 13. Environment-Specific Values ⭐⭐⭐⭐⭐

One Chart can be used for multiple environments.

```text
myapp/
├── Chart.yaml
├── values.yaml
├── values-dev.yaml
├── values-test.yaml
├── values-prod.yaml
└── templates/
```

Example:

### `values-dev.yaml`

```yaml
replicaCount: 1
```

### `values-prod.yaml`

```yaml
replicaCount: 5
```

Deploy Dev:

```bash
helm install myapp ./myapp -f values-dev.yaml
```

Deploy Prod:

```bash
helm install myapp ./myapp -f values-prod.yaml
```

Same Chart, different configuration.

## Interview Questions ⭐

**Q: What is `Chart.yaml`?**
It contains metadata such as Chart name, Chart version, type, and application version.

**Q: What is `values.yaml`?**
It contains default configuration values used by Helm templates.

**Q: What is the purpose of `templates/`?**
It contains templated Kubernetes resource definitions.

**Q: What is `_helpers.tpl`?**
It contains reusable named templates and helper functions.

**Q: What is the difference between `Chart.yaml` and `values.yaml`?**

```text
Chart.yaml
    ↓
Chart metadata

values.yaml
    ↓
Chart configuration
```

**Q: What is the `charts/` directory?**
It contains dependent/sub-charts used by the parent Chart.

**Q: How do you create a Helm Chart?**

```bash
helm create myapp
```

**Q: How do you see the Kubernetes YAML generated by a Chart?**

```bash
helm template myapp ./myapp
```

### ⭐ Must Remember

```text
Chart.yaml    → What is this Chart?
values.yaml   → What configuration should it use?
templates/    → What Kubernetes resources should be created?
_helpers.tpl  → What reusable template logic should be used?
charts/       → What other Charts does it depend on?
```
