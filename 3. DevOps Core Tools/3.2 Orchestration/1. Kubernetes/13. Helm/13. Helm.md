# Helm

**Helm** is a **package manager for Kubernetes** used to install, upgrade, configure, and manage Kubernetes applications.

In simple words:

> **Helm = Package manager for Kubernetes.**

Just like:

```text
Linux        → apt / yum
Python       → pip
Node.js      → npm
Kubernetes   → Helm
```

---

## Why do we need Helm? ⭐

Without Helm, an application may require multiple Kubernetes YAML files:

```text
my-app/
├── deployment.yaml
├── service.yaml
├── configmap.yaml
├── secret.yaml
├── ingress.yaml
└── serviceaccount.yaml
```

You would need to manage these files separately.

With Helm:

```text
Helm Chart
    ↓
Deployment
Service
ConfigMap
Secret
Ingress
    ↓
Kubernetes
```

Helm packages these Kubernetes resources together.

---

# Helm Chart

A **Chart** is a package containing Kubernetes manifests and templates.

Typical structure:

```text
my-app/
├── Chart.yaml
├── values.yaml
├── templates/
│   ├── deployment.yaml
│   ├── service.yaml
│   ├── ingress.yaml
│   └── configmap.yaml
└── charts/
```

### Important files ⭐

**Chart.yaml**

Contains chart information:

```yaml
name: my-app
version: 1.0.0
```

**values.yaml**

Contains configurable values:

```yaml
replicaCount: 3

image:
  repository: nginx
  tag: "1.27"
```

**templates/**

Contains Kubernetes YAML templates.

---

# Helm Template Concept

Instead of hardcoding:

```yaml
replicas: 3
```

you can use:

```yaml
replicas: {{ .Values.replicaCount }}
```

Then `values.yaml` controls the value:

```yaml
replicaCount: 3
```

For another environment:

```yaml
replicaCount: 5
```

Same chart, different configuration.

```text
Same Helm Chart
      ↓
 ┌────┼─────┐
 ↓    ↓     ↓
Dev  QA    Prod
 2    3      5
Pods Pods   Pods
```

# Helm Release ⭐

When you install a Helm Chart, Helm creates a **Release**.

Example:

```bash
helm install my-app ./my-app
```

Here:

```text
my-app
  ↓
Release name
```

You can have the same chart installed multiple times:

```text
my-app-dev
my-app-qa
my-app-prod
```

---

# Important Helm Commands

### Install

```bash
helm install my-app ./my-app
```

### List Releases

```bash
helm list
```

### Upgrade

```bash
helm upgrade my-app ./my-app
```

### Rollback ⭐

```bash
helm rollback my-app 1
```

### Uninstall

```bash
helm uninstall my-app
```

### Check Release History

```bash
helm history my-app
```

# Helm Repository

A **Helm repository** stores Helm Charts.

```text
Helm Repository
      ↓
    Chart
      ↓
helm install
      ↓
Kubernetes
```

You can add a repository:

```bash
helm repo add <repo-name> <repo-url>
```

Update repository information:

```bash
helm repo update
```

Search:

```bash
helm search repo <chart-name>
```

# Helm in DevOps / CI-CD ⭐

Helm is commonly used in deployment pipelines.

Example:

```text
Developer
    ↓
Git
    ↓
CI Pipeline
    ↓
Build Docker Image
    ↓
Push Image to Registry
    ↓
Helm
    ↓
Kubernetes
    ↓
Application
```

For example:

```bash
helm upgrade --install my-app ./chart \
  --set image.tag=1.2.3
```

The pipeline can deploy a new image version without changing the whole Kubernetes YAML manually.

# Helm vs kubectl ⭐

| kubectl                               | Helm                          |
| ------------------------------------- | ----------------------------- |
| Kubernetes CLI                        | Kubernetes package manager    |
| Manages individual resources          | Manages applications/releases |
| Works directly with manifests         | Uses Charts/templates         |
| `kubectl apply`                       | `helm install/upgrade`        |
| No built-in release history like Helm | Release history & rollback    |

Think:

```text
kubectl
   ↓
Manage Kubernetes resources

Helm
   ↓
Package + Template + Deploy + Upgrade + Rollback
```

---

# Helm vs Docker

Another common interview question:

```text
Docker
  ↓
Packages application into container image

Helm
  ↓
Packages Kubernetes application resources into a Chart
```

So:

> **Docker packages the application. Helm packages the Kubernetes deployment configuration.**

---

# Real Example

Suppose your application requires:

```text
Deployment
Service
ConfigMap
Ingress
```

Without Helm:

```text
deployment.yaml
service.yaml
configmap.yaml
ingress.yaml
```

With Helm:

```text
my-app-chart/
├── Chart.yaml
├── values.yaml
└── templates/
    ├── deployment.yaml
    ├── service.yaml
    ├── configmap.yaml
    └── ingress.yaml
```

Then:

```bash
helm install my-app ./my-app-chart
```

Helm renders the templates and creates the Kubernetes resources.

---

## ⭐ Interview Answer

> **Helm is a package manager for Kubernetes. It uses Charts to package Kubernetes manifests and templates together. We can use Helm to install, configure, upgrade, and rollback applications. Helm uses `values.yaml` for environment-specific configuration, which allows us to use the same Chart across development, staging, and production environments.**

### Easy to remember

```text
Chart
  ↓
Templates + values
  ↓
Helm
  ↓
Release
  ↓
Kubernetes
```

> **Helm = Package + Configure + Deploy + Upgrade + Rollback Kubernetes applications.**
