# 2. Installation & Setup

## 1. kubectl

**kubectl** is the **command-line tool** used to communicate with and manage a Kubernetes cluster.

**What you can do with kubectl:**

* Create and manage Kubernetes resources
* Check Pods, Nodes, Services, Deployments
* View logs and troubleshoot applications
* Apply YAML configuration files

**Common commands:**

```bash
kubectl get nodes
kubectl get pods
kubectl get pods -A
kubectl get services
kubectl apply -f deployment.yaml
kubectl delete -f deployment.yaml
kubectl logs <pod-name>
kubectl describe pod <pod-name>
```

**Interview:**

> `kubectl` is the CLI tool used to interact with the Kubernetes API Server and manage cluster resources.

**Keywords:** `CLI` → `API Server` → `Manage Resources` → `kubectl get` → `kubectl apply`

## 2. Minikube

**Minikube** is a tool used to **run a Kubernetes cluster locally**, mainly for **learning, development, and testing**.

```text
Laptop
   ↓
Minikube
   ↓
Local Kubernetes Cluster
```

**Common commands:**

```bash
minikube start
minikube status
minikube stop
minikube delete
minikube dashboard
```

**Interview:**

> Minikube is used to run a Kubernetes cluster locally on a developer's machine for learning, development, and testing.

**Keywords:** `Local Cluster` → `Learning` → `Development` → `Testing`

---

## 3. Kind

**Kind (Kubernetes IN Docker)** is a tool for running **Kubernetes clusters using Docker containers as Kubernetes nodes**.

```text
Docker
  │
  ├── Control Plane Container
  ├── Worker Container
  └── Worker Container
          ↓
   Kubernetes Cluster
```

**Common commands:**

```bash
kind create cluster
kind get clusters
kind delete cluster
```

**Interview:**

> Kind is a Kubernetes tool that runs Kubernetes nodes as Docker containers, making it useful for local development and testing.

**Keywords:** `Kubernetes IN Docker` → `Docker Containers` → `Local Testing`

---

## 4. Kubeadm

**kubeadm** is a Kubernetes tool used to **bootstrap and configure a Kubernetes cluster** on servers or virtual machines.

It is commonly used when you want to build a **self-managed Kubernetes cluster**.

```text
VM 1 → Control Plane
VM 2 → Worker Node
VM 3 → Worker Node
        ↓
      kubeadm
        ↓
 Kubernetes Cluster
```

**Common commands:**

```bash
kubeadm init
kubeadm join
kubeadm reset
```

* `kubeadm init` → Initializes the **Control Plane**
* `kubeadm join` → Joins a **Worker Node** to the cluster
* `kubeadm reset` → Resets a node

**Interview:**

> kubeadm is a Kubernetes tool used to bootstrap a self-managed Kubernetes cluster by initializing the control plane and joining worker nodes.

**Keywords:** `Bootstrap` → `Self-managed Cluster` → `kubeadm init` → `kubeadm join`

### ⭐ Quick Interview Comparison

| Tool         | Main Purpose                           |

| **kubectl**  | Manage/interact with Kubernetes        |
| **Minikube** | Run Kubernetes locally                 |
| **Kind**     | Run Kubernetes using Docker containers |

**Easy way to remember:**

> **kubectl → Manage**

> **Kind → Docker-based K8s**
> **kubeadm → Build cluster**
