sudo dnf update -y

## 2. AWS CLI

AWS officially provides AWS CLI v2 for 64-bit Linux/CentOS. ([AWS Documentation][2])

```bash
curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip"

unzip awscliv2.zip

sudo ./aws/install
```

Verify:

```bash
aws --version
```

Expected:

```text
aws-cli/2.x.x ...
```

Configure AWS:

```bash
aws configure
```

It will ask:

```text
AWS Access Key ID:
AWS Secret Access Key:
Default region name:
Default output format:
```

For example:

```text
Default region name: ap-south-1
Default output format: json
```

# 3. Terraform

HashiCorp provides an RPM repository for RHEL/CentOS-based systems. ([HashiCorp Developer][3])

```bash
sudo dnf install -y yum-utils

sudo yum-config-manager \
    --add-repo \
    https://rpm.releases.hashicorp.com/RHEL/hashicorp.repo

sudo dnf install -y terraform
```

Verify:

```bash
terraform version
```

Example:

```text
Terraform v1.x.x
```

---

# 4. kubectl

Kubernetes officially provides the `kubectl` Linux binary. Make sure the kubectl version is within one minor version of your Kubernetes cluster. ([Kubernetes][4])

For **x86_64/AMD64**:

```bash
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
```

Make it executable:

```bash
chmod +x kubectl
```

Move it to PATH:

```bash
sudo mv kubectl /usr/local/bin/
```

Verify:

```bash
kubectl version --client
```

You should see something like:

```text
Client Version: v1.x.x
```

# 5. Docker

Docker officially supports **CentOS Stream 10**. The recommended method is to install Docker from Docker's RPM repository. ([Docker Documentation][1])

### Remove old/conflicting Docker packages

```bash
sudo dnf remove -y \
docker \
docker-client \
docker-client-latest \
docker-common \
docker-latest \
docker-latest-logrotate \
docker-logrotate \
docker-engine
```

If packages don't exist, that's okay.

### Add Docker repository

```bash
sudo dnf install -y dnf-plugins-core
```

```bash
sudo dnf config-manager \
    --add-repo \
    https://download.docker.com/linux/centos/docker-ce.repo
```

### Install Docker

```bash
sudo dnf install -y \
docker-ce \
docker-ce-cli \
containerd.io \
docker-buildx-plugin \
docker-compose-plugin
```

### Start Docker

```bash
sudo systemctl enable --now docker
```

Check:

```bash
sudo systemctl status docker
```

Verify:

```bash
docker --version
```

Test:

```bash
sudo docker run hello-world
```

Docker documents this exact CentOS Stream 10 installation path. ([Docker Documentation][1])

### Optional: Run Docker without sudo

```bash
sudo usermod -aG docker $USER
```

Then either log out and log back in, or run:

```bash
newgrp docker
```

Test:

```bash
docker ps
```

# 6. Helm

Helm provides official Linux binary releases and also supports installation through `dnf` on Fedora-family systems. For a CentOS Stream environment, the official binary installation is a straightforward option. ([Helm][5])

Download the latest Linux AMD64 release:

```bash
curl -LO https://get.helm.sh/helm-v4.0.0-linux-amd64.tar.gz
```

Extract:

```bash
tar -zxvf helm-v4.0.0-linux-amd64.tar.gz
```

Move binary:

```bash
sudo mv linux-amd64/helm /usr/local/bin/helm
```

Verify:

```bash
helm version
```

> If you want to pin a specific Helm version for your project, replace `v4.0.0` with the required version. Helm's official installation documentation provides the binary-installation method. ([Helm][5])

# 7. Git

Git is available through `dnf` on CentOS/RHEL-family systems. ([Git SCM][6])

```bash
sudo dnf install -y git
```

Verify:

```bash
git --version
```

Example:

```text
git version 2.x.x
```

Configure Git:

```bash
git config --global user.name "Your Name"
git config --global user.email "your-email@example.com"
```

Check:

```bash
git config --list
```

# 8. Final Verification

After installing everything, run:

```bash
aws --version
terraform version
kubectl version --client
docker --version
helm version
git --version
```

You should have:

```text
AWS CLI       → aws --version
Terraform     → terraform version
kubectl       → kubectl version --client
Docker        → docker --version
Helm          → helm version
Git           → git --version
```
