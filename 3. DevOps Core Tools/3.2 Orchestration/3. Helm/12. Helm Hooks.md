# Helm Hooks

## What are Hooks?

Hooks let a chart run Kubernetes resources at specific points in the Helm lifecycle.

Common hooks:

- `pre-install`
- `post-install`
- `pre-upgrade`
- `post-upgrade`
- `pre-delete`
- `post-delete`
- `pre-rollback`
- `post-rollback`

## Annotation

```yaml
metadata:
  annotations:
    "helm.sh/hook": pre-install
```

## Example Job

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: db-migration
  annotations:
    "helm.sh/hook": pre-upgrade
    "helm.sh/hook-delete-policy": hook-succeeded
```

## Hook Weight

Weights control ordering when multiple hooks run.

```yaml
"helm.sh/hook-weight": "0"
```

Lower weights run before higher weights for the same hook event.

## Delete Policy

Common values:

```text
before-hook-creation
hook-succeeded
hook-failed
```

## Typical Use Cases

- Database migrations
- Pre-deployment validation
- Post-deployment checks
- Cleanup tasks

## Important Warning

Hooks are powerful but should not be used for normal application resources. Keep hook jobs idempotent and make their cleanup behavior explicit.

## Debugging

```bash
helm get hooks <release>
kubectl get jobs
kubectl describe job <job>
kubectl logs job/<job>
```
