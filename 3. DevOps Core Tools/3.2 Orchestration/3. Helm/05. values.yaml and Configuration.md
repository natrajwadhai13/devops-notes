# values.yaml and Configuration

## Why values.yaml?

It separates **configuration** from **template logic**.

```yaml
replicaCount: 2

image:
  repository: nginx
  tag: "1.27"

service:
  port: 80
```

Use values inside templates:

```yaml
replicas: {{ .Values.replicaCount }}
image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
```

## Override with a Values File

```bash
helm install myapp ./mychart -f values-dev.yaml
helm upgrade myapp ./mychart -f values-prod.yaml
```

## Override with --set

```bash
helm install myapp ./mychart --set replicaCount=3
```

## Multiple Values Files

```bash
helm upgrade myapp ./mychart   -f values.yaml   -f values-prod.yaml
```

Later values override earlier values.

## Practical Precedence

A useful simplified rule is:

```text
chart defaults
   ↓
values files
   ↓
--set / command-line overrides
```

## Best Practices

- Keep sensible defaults in `values.yaml`
- Use environment-specific values files
- Avoid hardcoding environment configuration in templates
- Use meaningful value names
- Do not put production secrets in plain text

## Useful Commands

```bash
helm show values <chart>
helm get values <release>
helm get values <release> --all
```
