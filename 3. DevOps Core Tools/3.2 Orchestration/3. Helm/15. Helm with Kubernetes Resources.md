# Helm with Kubernetes Resources

Helm does not replace Kubernetes. Helm generates and manages Kubernetes resources.

## Common Resources

A typical application chart may contain:

```text
Deployment
Service
ConfigMap
Secret
Ingress
ServiceAccount
HPA
PVC
Job / CronJob
```

## Deployment

Usually controls replicas, container image, ports, resources, probes, and environment configuration.

```yaml
spec:
  replicas: {{ .Values.replicaCount }}
```

## Service

Exposes application Pods.

```yaml
spec:
  selector:
    app.kubernetes.io/name: {{ include "myapp.name" . }}
```

## ConfigMap and Secret

Use values to configure them, but keep sensitive source data out of Git.

## Ingress

Commonly enabled conditionally:

```yaml
{{- if .Values.ingress.enabled }}
...
{{- end }}
```

## Resource Requests and Limits

```yaml
resources:
{{- toYaml .Values.resources | nindent 2 }}
```

## HPA

Helm can template HPA configuration, while Kubernetes performs the actual autoscaling.

## Labels and Selectors

Keep labels and selectors consistent. `_helpers.tpl` is useful for centralized label generation.

## Complete Flow

```text
values.yaml
   ↓
Helm templates
   ↓
Rendered Kubernetes YAML
   ↓
Kubernetes API
   ↓
Deployment / Service / ConfigMap / etc.
```
