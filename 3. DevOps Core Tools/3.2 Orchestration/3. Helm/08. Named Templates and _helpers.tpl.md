# Named Templates and `_helpers.tpl`

## Why `_helpers.tpl`?

It keeps reusable template logic in one place and prevents duplication.

## Define

```yaml
{{- define "myapp.fullname" -}}
{{ .Release.Name }}-{{ .Chart.Name }}
{{- end }}
```

## Include

```yaml
metadata:
  name: {{ include "myapp.fullname" . }}
```

`include` returns rendered text, so it can be used in a pipeline:

```yaml
labels:
{{ include "myapp.labels" . | nindent 4 }}
```

## Common Helpers

- `name`
- `fullname`
- `labels`
- `selectorLabels`
- `serviceAccountName`

## `include` vs `template`

`include` is usually preferred because its output can be piped through functions.

## The Dot `.`

`.` represents the current context. Passing `.` to a helper gives the helper access to the current chart, release, and values context.

## Best Practices

- Keep helpers small and reusable
- Use consistent naming
- Keep naming/label logic centralized
- Avoid copying the same template logic into multiple manifests
