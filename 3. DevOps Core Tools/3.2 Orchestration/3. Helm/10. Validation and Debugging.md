# Validation and Debugging

## Recommended Workflow

```text
helm lint
   ↓
helm template
   ↓
helm install --dry-run --debug
   ↓
helm install / upgrade
   ↓
helm status
   ↓
kubectl get pods
   ↓
kubectl describe / logs / events
```

## helm lint

```bash
helm lint ./mychart
```

Checks chart structure and common chart problems.

## helm template

Render templates locally:

```bash
helm template myapp ./mychart
helm template myapp ./mychart -f values-prod.yaml
```

Useful when the problem is in Helm rendering.

## Dry Run

```bash
helm install myapp ./mychart --dry-run --debug
```

Previews an installation without actually creating the resources.

## Check Release

```bash
helm status myapp
helm history myapp
helm get manifest myapp
helm get all myapp
```

## Kubernetes Debugging

```bash
kubectl get pods
kubectl describe pod <pod>
kubectl logs <pod>
kubectl get events --sort-by=.lastTimestamp
kubectl get svc
kubectl get ingress
```

## Common Problems

### YAML Parse Error
Usually caused by bad indentation or invalid rendered YAML.

### nil pointer
Usually means a referenced value does not exist or the template path is wrong.

### ImagePullBackOff
Check image repository/tag and registry access.

### CrashLoopBackOff
Check pod logs, configuration, environment variables, and events.

### Service Not Working
Check service selector, endpoints, target port, and pod labels.

## Key Difference

`helm template` = render locally.

`helm install --dry-run --debug` = simulate an install and inspect the rendered output/context.
