# Helm Fundamentals

## What is Helm?

Helm is a package manager for Kubernetes. It packages Kubernetes manifests into reusable **Charts** and manages their deployments as **Releases**.

Instead of maintaining many almost-identical YAML files for dev, test, and prod, Helm lets us keep templates and change configuration through values.

## Why Helm?

- Reusable Kubernetes configurations
- Environment-specific configuration
- Versioned application packages
- Easy install, upgrade, rollback, and uninstall
- Supports dependencies and hooks
- Works well with CI/CD and GitOps

## Important Terminology

| Term         | Meaning                                                 |
| ------------ | ------------------------------------------------------- |
| Chart        | Package containing templates and metadata               |
| values.yaml  | Default configuration for a chart                       |
| Template     | Kubernetes YAML containing Go-template expressions      |
| Release      | A deployed instance of a chart                          |
| Repository   | Location from which charts can be discovered/downloaded |
| OCI Registry | Container registry that can store Helm charts           |

## Helm vs Kubernetes YAML

**Kubernetes YAML:** describes one desired resource configuration.

**Helm:** generates Kubernetes YAML from reusable templates and values, then manages the resulting release.

## Helm 3 Architecture

Helm 3 is client-side. There is no Tiller.

Typical flow:

`helm command → chart + values → template rendering → Kubernetes API → resources`

Helm stores release information in the Kubernetes cluster.

## Interview Answer

> Helm is the package manager for Kubernetes. It uses reusable charts and templates with configurable values, and manages application releases through install, upgrade, rollback, and uninstall operations.
