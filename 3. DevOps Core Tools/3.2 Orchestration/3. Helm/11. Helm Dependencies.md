# 11. Helm Dependencies

# 1. What are Helm Dependencies?

A **Helm Dependency** is another Helm Chart that your Chart needs.

For example, your application may require:

```text
myapp
 ├── application
 ├── PostgreSQL
 └── Redis
```

Instead of creating PostgreSQL and Redis Charts yourself, your Chart can use existing Charts as dependencies.

```text id="6v3j4a"
Parent Chart
     │
     ├── Redis Chart
     └── PostgreSQL Chart
```

---

# 2. Parent Chart and Subchart ⭐⭐⭐⭐⭐

The main Chart is called the **Parent Chart**.

A dependent Chart is commonly called a **Subchart**.

Example:

```text id="8v9d4c"
myapp/
├── Chart.yaml
├── values.yaml
├── charts/
│   ├── redis/
│   └── postgresql/
└── templates/
```

Here:

```text id="q2k7f8"
myapp
 ↓
Parent Chart

redis
 ↓
Subchart

postgresql
 ↓
Subchart
```

---

# 3. Why Helm Dependencies are Used ⭐⭐⭐⭐⭐

Dependencies help you:

- Reuse existing Helm Charts
- Avoid writing everything from scratch
- Package related applications together
- Manage third-party components
- Maintain versioned dependencies
- Simplify application deployment

For example, a web application might require:

```text
Application
   +
Redis
   +
PostgreSQL
```

A parent Helm Chart can manage these components together.

---

# 4. Define Dependencies in `Chart.yaml` ⭐⭐⭐⭐⭐

Dependencies are defined in the parent Chart's `Chart.yaml`.

Example:

```yaml id="d9m0mx"
apiVersion: v2
name: myapp
version: 1.0.0

dependencies:
  - name: redis
    version: "20.x.x"
    repository: "https://charts.bitnami.com/bitnami"
```

Important fields:

```text id="g9t5b6"
name
   ↓
Dependency Chart name

version
   ↓
Dependency Chart version

repository
   ↓
Where the Chart is located
```

---

# 5. Multiple Dependencies ⭐⭐⭐⭐⭐

You can define multiple dependencies.

```yaml id="1otfcm"
dependencies:
  - name: redis
    version: "20.x.x"
    repository: "https://charts.bitnami.com/bitnami"

  - name: postgresql
    version: "16.x.x"
    repository: "https://charts.bitnami.com/bitnami"
```

Architecture:

```text id="v4m8q1"
                 myapp
                   │
          ┌────────┴────────┐
          ↓                 ↓
        Redis           PostgreSQL
```

---

# 6. `helm dependency update` ⭐⭐⭐⭐⭐

This is one of the most important dependency commands.

Run:

```bash id="qj8n8b"
helm dependency update
```

Helm:

1. Reads dependencies from `Chart.yaml`
2. Finds the required Chart versions
3. Downloads the dependencies
4. Stores them under `charts/`
5. Updates dependency information

Example:

```text id="g3b1x0"
myapp/
├── Chart.yaml
├── values.yaml
├── charts/
│   ├── redis-20.x.x.tgz
│   └── postgresql-16.x.x.tgz
└── templates/
```

---

# 7. `helm dependency build` ⭐⭐⭐⭐

`helm dependency build` builds the dependency directory from the existing lock information.

```bash id="w4c7u1"
helm dependency build
```

It is useful when dependencies are already defined/locked and you want to recreate the `charts/` directory.

### Easy difference

```text id="w0y6m8"
helm dependency update
        ↓
Resolve/update dependency versions
        ↓
Download dependencies

helm dependency build
        ↓
Build dependencies using existing lock information
```

---

# 8. `helm dependency list` ⭐⭐⭐⭐

Shows dependencies of the current Chart.

```bash id="z5u6e7"
helm dependency list
```

Example:

```text id="m9n1d5"
NAME        VERSION    REPOSITORY
redis       20.x.x     https://charts.bitnami.com/bitnami
postgresql  16.x.x     https://charts.bitnami.com/bitnami
```

---

# 9. `charts/` Directory ⭐⭐⭐⭐⭐

Downloaded dependencies are stored in:

```text id="0w5t5v"
charts/
```

Example:

```text id="xy5j4p"
myapp/
├── Chart.yaml
├── values.yaml
├── charts/
│   ├── redis-20.x.x.tgz
│   └── postgresql-16.x.x.tgz
└── templates/
```

You generally should not manually edit downloaded dependency packages.

Manage them through:

```text id="v7z7gj"
Chart.yaml
+
helm dependency update
```

---

# 10. Dependency Versions ⭐⭐⭐⭐⭐

You can specify a dependency version.

Example:

```yaml id="w7j6s5"
dependencies:
  - name: redis
    version: "20.6.0"
    repository: "https://charts.bitnami.com/bitnami"
```

Or a version range:

```yaml id="l3p5a9"
version: "20.x.x"
```

Version control is important because dependency upgrades can change application behavior.

---

# 11. Repository

The repository tells Helm where to download the dependency.

Example:

```yaml id="5n2q9b"
repository: "https://charts.bitnami.com/bitnami"
```

The repository must contain the requested Chart/version.

---

# 12. Dependency Values ⭐⭐⭐⭐⭐

One important concept is that the parent Chart can provide configuration for a subchart.

Suppose the dependency is:

```text id="1w4y3z"
redis
```

You can configure it in the parent's `values.yaml`.

Example:

```yaml id="o8u6l2"
redis:
  architecture: standalone
  auth:
    enabled: false
```

The parent Chart can therefore control the dependency's configuration.

---

# 13. Subchart Configuration

Suppose:

```yaml id="5b4w1m"
dependencies:
  - name: redis
    version: "20.x.x"
    repository: "https://charts.bitnami.com/bitnami"
```

Then:

```yaml id="f3c8j2"
redis:
  architecture: standalone
```

The `redis` key corresponds to the dependency name.

Conceptually:

```text id="2o4f9p"
Parent values.yaml
        ↓
     redis:
        ↓
Redis subchart values
```

---

# 14. Parent → Subchart Communication ⭐⭐⭐⭐⭐

A parent Chart can provide values to a subchart.

However, a subchart is generally designed to be **standalone** and cannot directly access arbitrary parent values.

For example:

```yaml id="g7w8p2"
redis:
  auth:
    enabled: false
```

The parent passes these values into the Redis dependency.

This is an important Helm concept for interviews.

---

# 15. `condition` ⭐⭐⭐⭐

You can conditionally enable or disable a dependency.

Example:

```yaml id="g4v2p7"
dependencies:
  - name: redis
    version: "20.x.x"
    repository: "https://charts.bitnami.com/bitnami"
    condition: redis.enabled
```

Then in `values.yaml`:

```yaml id="3q9r8x"
redis:
  enabled: true
```

If:

```yaml id="0n6m7k"
redis:
  enabled: false
```

the Redis dependency can be disabled.

Flow:

```text id="j7y2h5"
redis.enabled = true
       ↓
Redis enabled

redis.enabled = false
       ↓
Redis disabled
```

---

# 16. Tags ⭐⭐⭐

Tags can also be used to enable or disable groups of dependencies.

Example:

```yaml id="8l5k1m"
dependencies:
  - name: redis
    version: "20.x.x"
    repository: "https://charts.bitnami.com/bitnami"
    tags:
      - caching
```

Values:

```yaml id="8k0q7p"
tags:
  caching: true
```

This is useful when several dependencies need to be controlled together.

For basic Helm learning, understand the concept; deep usage can come later.

---

# 17. Alias ⭐⭐⭐

An alias allows you to use the same dependency Chart more than once with different names/configurations.

Conceptually:

```text id="p3x5k8"
Redis Chart
   ├── redis-cache
   └── redis-session
```

Example:

```yaml id="i9z5q2"
dependencies:
  - name: redis
    version: "20.x.x"
    repository: "https://charts.bitnami.com/bitnami"
    alias: redis-cache
```

This is an advanced dependency feature.

---

# 18. `Chart.lock` ⭐⭐⭐⭐⭐

When dependency versions are resolved, Helm can create a lock file:

```text id="4t7k8y"
Chart.lock
```

Example structure:

```text id="m2x9q1"
myapp/
├── Chart.yaml
├── Chart.lock
├── values.yaml
├── charts/
└── templates/
```

`Chart.lock` helps maintain **reproducible dependency versions**.

This is important in CI/CD and production environments.

---

# 19. `helm dependency update` and `Chart.lock`

When you run:

```bash id="c2s6k8"
helm dependency update
```

Helm resolves the dependencies and updates the lock information.

Conceptually:

```text id="5j6n9m"
Chart.yaml
    ↓
Dependency definitions
    ↓
helm dependency update
    ↓
Chart.lock
    ↓
charts/
```

---

# 20. Dependency Installation Flow ⭐⭐⭐⭐⭐

When you install a parent Chart:

```bash id="q8r3t1"
helm install myapp ./mychart
```

Helm uses the dependency information and packages available in:

```text id="5n0c6a"
charts/
```

Conceptually:

```text id="d7r8k2"
Parent Chart
     ↓
Dependencies
     ↓
Templates + Values
     ↓
Rendered Kubernetes Manifests
     ↓
Kubernetes
```

---

# 21. Complete Example ⭐⭐⭐⭐⭐

### `Chart.yaml`

```yaml id="8r5p1x"
apiVersion: v2
name: myapp
description: My application
type: application
version: 1.0.0
appVersion: "1.0"

dependencies:
  - name: redis
    version: "20.x.x"
    repository: "https://charts.bitnami.com/bitnami"
```

### `values.yaml`

```yaml id="1s4k8q"
replicaCount: 2

redis:
  architecture: standalone
  auth:
    enabled: false
```

Run:

```bash id="3c7v5n"
helm dependency update
```

Then:

```bash id="5y8r2w"
helm dependency list
```

Then install:

```bash id="4x6p9z"
helm install myapp ./myapp
```

Architecture:

```text id="p2c7m9"
                 myapp
                   │
          ┌────────┴────────┐
          ↓                 ↓
   Application          Redis
    templates          subchart
          │                 │
          └────────┬────────┘
                   ↓
              Kubernetes
```

# 22. Common Dependency Problems ⭐⭐⭐⭐

### Dependency not found

Possible causes:

- Incorrect repository URL
- Wrong Chart name
- Wrong version
- Repository unavailable

Check:

```bash id="8j3k5x"
helm repo list
```

---

### Dependency not downloaded

Run:

```bash id="6q8x3v"
helm dependency update
```

Then:

```bash id="2v7p9m"
ls charts/
```

---

### Wrong dependency version

Check:

```bash id="n4r6s1"
helm dependency list
```

Review:

```yaml id="2k5h8p"
version: "20.x.x"
```

---

### Subchart configuration not working

Check the structure in `values.yaml`.

Correct:

```yaml id="6f7g8h"
redis:
  auth:
    enabled: false
```

Not:

```yaml id="7k2m4n"
auth:
  enabled: false
```

The values need to be under the dependency's name.

# 24. Important Commands ⭐⭐⭐⭐⭐

| Command                  | Purpose                                  |
| ------------------------ | ---------------------------------------- |
| `helm dependency update` | Resolve/download dependencies            |
| `helm dependency build`  | Build dependencies from lock information |
| `helm dependency list`   | List Chart dependencies                  |
| `helm install`           | Install parent Chart and dependencies    |
| `helm package`           | Package Chart with dependencies          |
