# Helm Dependencies

## What is a Dependency?

A parent chart can depend on another chart (subchart).

Example:

```text
myapp
 ├── application
 ├── redis
 └── postgresql
```

## Define in Chart.yaml

```yaml
dependencies:
  - name: redis
    version: "20.x.x"
    repository: "https://charts.bitnami.com/bitnami"
```

## Commands

```bash
helm dependency update ./myapp
helm dependency build ./myapp
helm dependency list ./myapp
```

## `update` vs `build`

- `helm dependency update` resolves dependencies and updates the lock information.
- `helm dependency build` builds dependencies from the lock file when possible.

## charts/

Downloaded dependency charts are placed under:

```text
charts/
```

## Chart.lock

Locks dependency versions so builds are more reproducible.

## condition

A dependency can be conditionally enabled:

```yaml
dependencies:
  - name: redis
    condition: redis.enabled
```

## Tags and Alias

Tags can group optional dependencies. An alias can allow the same chart to be used more than once with different names/configuration.

## Parent → Subchart Values

Subchart values are commonly configured under the subchart name:

```yaml
redis:
  architecture: standalone
```

## Interview Summary

> Helm dependencies let a parent chart package and configure subcharts such as Redis or PostgreSQL. `helm dependency update`, `build`, `list`, and `Chart.lock` are the key concepts.
