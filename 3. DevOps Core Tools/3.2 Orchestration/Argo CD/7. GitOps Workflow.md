# 7. GitOps Workflow

## 1. Basic Flow

```text
Developer
    ↓
GitHub / GitLab
    ↓
   Argo CD
    ↓
Kubernetes Cluster
    ↓
Application
```

## 2. Step-by-Step

### Step 1 — Developer makes a change

Developer modifies Kubernetes configuration, for example:

```yaml
replicas: 3
```

### Step 2 — Push to Git

```bash
git add .
git commit -m "Update replicas"
git push
```

Git becomes the **single source of truth**.

### Step 3 — Argo CD detects change

Argo CD compares:

```text
Desired State → Git
Live State    → Kubernetes
```

If different:

```text
Status: OutOfSync
```

### Step 4 — Synchronization

Argo CD applies the Git configuration to Kubernetes.

```text
Git
 ↓
Argo CD
 ↓
Kubernetes
```

With **Auto-Sync**, this happens automatically.

### Step 5 — Kubernetes updates application

Kubernetes creates/updates the required resources:

```text
Deployment → ReplicaSet → Pods
```

## 3. Drift Detection

Example:

```text
Git:         replicas = 3
Kubernetes:  replicas = 2
```

Argo CD detects the difference:

```text
OutOfSync → Drift detected
```

If `selfHeal: true` is enabled:

```text
Argo CD → restores replicas = 3
```

## 4. Rollback

Because configuration is stored in Git, you can revert a previous commit:

```text
Git commit A → Version 1
Git commit B → Version 2
Git commit C → Version 3
                    ↓
              Rollback to B
```

Argo CD then synchronizes the reverted configuration.

## 5. Key Benefits

* Git is the **Single Source of Truth**
* Automated deployment
* Version control
* Audit history
* Drift detection
* Self-healing
* Easy rollback

### Interview Point

> In a GitOps workflow, developers make changes in Git, Argo CD detects the difference between the desired and live state, and synchronizes the desired state from Git to Kubernetes.
