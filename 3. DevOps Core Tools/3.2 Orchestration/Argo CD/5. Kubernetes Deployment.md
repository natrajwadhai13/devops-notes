# 5. Kubernetes Deployment with Argo CD

## 1. What is it?

Argo CD deploys Kubernetes resources from a **Git repository** into a Kubernetes cluster.

```text
GitHub / GitLab
      ↓
 Kubernetes YAML
      ↓
    Argo CD
      ↓
Kubernetes Cluster
      ↓
 Deployment → Pods → Service
```

## 2. Basic Workflow

1. Create Kubernetes YAML files.
2. Push YAML files to Git.
3. Connect Git repository with Argo CD.
4. Create an Argo CD Application.
5. Argo CD reads the YAML files.
6. Argo CD creates/updates Kubernetes resources.
7. Argo CD continuously monitors the application.

## 3. Example Git Repository

```text
my-app/
├── deployment.yaml
├── service.yaml
├── configmap.yaml
└── namespace.yaml
```

Argo CD Application points to:

```yaml
source:
  repoURL: https://github.com/user/my-app.git
  targetRevision: main
  path: kubernetes
```

## 4. Deployment

Example:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx
spec:
  replicas: 2
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
        - name: nginx
          image: nginx:latest
```

Argo CD takes this configuration from Git and deploys it to Kubernetes.

## 5. Important Argo CD Status

| Status        | Meaning                             |
| ------------- | ----------------------------------- |
| **Synced**    | Git and Kubernetes match            |
| **OutOfSync** | Difference exists                   |
| **Healthy**   | Application is running properly     |
| **Degraded**  | Application has a problem           |
| **Missing**   | Resource expected by Git is missing |

## 6. Self-Healing

If someone manually changes or deletes a resource in Kubernetes:

```text
Git = Desired State
Kubernetes = Changed State
          ↓
       Argo CD
          ↓
   Detects Drift
          ↓
 Restores Desired State
```

With:

```yaml
syncPolicy:
  automated:
    selfHeal: true
```

Argo CD can automatically restore the desired state.

### Interview Point

> Argo CD deploys Kubernetes manifests stored in Git and continuously compares the desired state in Git with the live state in Kubernetes. It can detect drift and, when configured for automated sync and self-healing, automatically correct it.
