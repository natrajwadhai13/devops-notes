## 3. Git Repository

* Argo CD uses a **Git repository as the source of truth**.
* GitHub / GitLab can be used as the repository.
* Repository contains Kubernetes manifests, Helm charts, or Kustomize files.

Example:

```text
GitHub Repository
├── deployment.yaml
├── service.yaml
└── configmap.yaml
```

Important concepts:

* Repository URL
* Branch / Revision
* Path
* Authentication
* Public vs Private repository

**Flow:**

```text
GitHub/GitLab → Argo CD → Kubernetes
```

## 4. Application Management

An **Argo CD Application** connects:

**Git Repository → Kubernetes Cluster**

It defines:

* Where is the Git repository?
* Which branch/revision?
* Which directory/path?
* Which Kubernetes cluster?
* Which namespace?

### Important Commands

```bash
argocd app list
argocd app get <app-name>
argocd app sync <app-name>
argocd app delete <app-name>
```

### Important Application States

* **Synced** → Git and Kubernetes are matching.
* **OutOfSync** → Difference exists.
* **Healthy** → Application is running correctly.
* **Degraded** → Application has a problem.

## 5. Kubernetes Deployment with Argo CD

Argo CD can deploy Kubernetes resources from Git.

Example:

```text
Git
 |
 | deployment.yaml
 | service.yaml
 |
 v
Argo CD
 |
 v
Kubernetes
 |
 +-- Deployment
 +-- Pod
 +-- Service
```

### Basic Process

1. Store Kubernetes YAML in Git.
2. Connect repository to Argo CD.
3. Create an Argo CD Application.
4. Argo CD reads the YAML.
5. Argo CD creates/updates resources in Kubernetes.
6. Argo CD continuously monitors the application.

### Key Concept

**Manual deployment:**

```text
kubectl apply → Kubernetes
```

**GitOps deployment:**

```text
Git → Argo CD → Kubernetes
```

**Interview Point:**

> Argo CD Application defines the relationship between a Git repository and a Kubernetes cluster, while Argo CD continuously synchronizes the desired state from Git with the cluster.
