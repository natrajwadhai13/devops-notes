# 9. Production & Troubleshooting

## 1. Application Status

Check application status:

```bash
argocd app get my-app
```

Important statuses:

- **Synced** → Git and Kubernetes match
- **OutOfSync** → Difference exists
- **Healthy** → Application is running correctly
- **Degraded** → Application has a problem
- **Missing** → Resource is missing

---

## 2. Sync Failure

If synchronization fails:

```bash
argocd app sync my-app
```

Check:

```bash
argocd app get my-app
kubectl get pods -n <namespace>
kubectl describe pod <pod-name> -n <namespace>
kubectl logs <pod-name> -n <namespace>
```

Common causes:

- Invalid YAML
- Wrong image
- Missing Secret/ConfigMap
- Insufficient permissions
- Resource already exists
- Wrong namespace

---

## 3. Application Not Healthy

Check Kubernetes resources:

```bash
kubectl get all -n <namespace>
```

Check Pod:

```bash
kubectl get pods -n <namespace>
kubectl describe pod <pod-name> -n <namespace>
kubectl logs <pod-name> -n <namespace>
```

Common issues:

- `CrashLoopBackOff`
- `ImagePullBackOff`
- `Pending`
- Failed probes
- Application configuration issue

---

## 4. OutOfSync / Drift

Example:

```text
Git:         replicas = 3
Kubernetes:  replicas = 2
```

Argo CD shows:

```text
OutOfSync
```

If self-healing is enabled:

```yaml
syncPolicy:
  automated:
    selfHeal: true
```

Argo CD automatically restores the desired state.

---

## 5. Rollback

If a deployment causes problems:

```bash
argocd app history my-app
```

Then rollback:

```bash
argocd app rollback my-app <ID>
```

**Git-based rollback** is also recommended by reverting the Git commit.

---

## 6. Argo CD Component Troubleshooting

Check Argo CD pods:

```bash
kubectl get pods -n argocd
```

Check logs:

```bash
kubectl logs deployment/argocd-server -n argocd
kubectl logs deployment/argocd-repo-server -n argocd
kubectl logs deployment/argocd-application-controller -n argocd
```

### Important Components

- `argocd-server` → UI/API issues
- `argocd-repo-server` → Git/repository issues
- `argocd-application-controller` → Sync/reconciliation issues

---

## 7. Production Best Practices

- Use **RBAC**
- Use private Git repositories
- Secure Git credentials
- Enable **automated sync** carefully
- Use `selfHeal` where appropriate
- Use separate Dev/QA/Prod environments
- Monitor Argo CD health
- Keep Git history for auditing and rollback
- Avoid storing secrets directly in Git

### Interview Point

> For Argo CD troubleshooting, first check the Application status, then inspect Kubernetes resources and Argo CD component logs. Most issues are related to Git configuration, Kubernetes manifests, permissions, networking, or application health.
