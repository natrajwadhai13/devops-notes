# 1. What are Helm Templates? ⭐⭐⭐⭐⭐

Helm Templates are **Kubernetes YAML files containing dynamic expressions**.

Instead of hardcoding values:

```yaml
replicas: 3
```

Helm allows:

```yaml
replicas: {{ .Values.replicaCount }}
```

If `values.yaml` contains:

```yaml
replicaCount: 3
```

Helm renders:

```yaml
replicas: 3
```

So the basic concept is:

```text
values.yaml
     ↓
Helm Template
     ↓
Rendered Kubernetes YAML
```

---

# 2. Go Template Syntax ⭐⭐⭐⭐⭐

Helm uses the **Go template language**.

The most common syntax is:

```text
{{ ... }}
```

Example:

```yaml
name: {{ .Values.name }}
```

If:

```yaml
name: myapp
```

The output becomes:

```yaml
name: myapp
```

---

# 3. `{{ }}` Template Expressions

Anything inside:

```text
{{ }}
```

is interpreted by Helm's template engine.

Example:

```yaml
replicas: {{ .Values.replicaCount }}
```

Another example:

```yaml
image: {{ .Values.image.repository }}:{{ .Values.image.tag }}
```

Given:

```yaml
image:
  repository: nginx
  tag: "1.27"
```

Output:

```yaml
image: nginx:1.27
```

---

# 4. `.Values` ⭐⭐⭐⭐⭐

`.Values` is used to access values from `values.yaml` or other supplied values.

Example:

```yaml
replicaCount: 3

image:
  repository: nginx
  tag: "1.27"
```

Template:

```yaml
replicas: {{ .Values.replicaCount }}
```

```yaml
image: {{ .Values.image.repository }}:{{ .Values.image.tag }}
```

Output:

```yaml
replicas: 3
image: nginx:1.27
```

---

# 5. `.Release` ⭐⭐⭐⭐⭐

`.Release` provides information about the current Helm **Release**.

Important fields include:

```text
.Release.Name
.Release.Namespace
.Release.Revision
.Release.IsInstall
.Release.IsUpgrade
```

Example:

```yaml
metadata:
  name: {{ .Release.Name }}
```

If installed using:

```bash
helm install production-app ./mychart
```

Then:

```yaml
name: production-app
```

Namespace:

```yaml
metadata:
  namespace: {{ .Release.Namespace }}
```

---

# 6. `.Chart`

`.Chart` provides information from `Chart.yaml`.

Example `Chart.yaml`:

```yaml
name: myapp
version: 1.0.0
appVersion: "2.0.0"
```

You can access:

```yaml
{{ .Chart.Name }}
```

```yaml
{{ .Chart.Version }}
```

```yaml
{{ .Chart.AppVersion }}
```

Example:

```yaml
labels:
  chart: {{ .Chart.Name }}
```

---

# 7. `.Capabilities`

`.Capabilities` provides information about the Kubernetes cluster and supported APIs.

Examples:

```text
.Capabilities.KubeVersion
.Capabilities.APIVersions
```

For example:

```yaml
{{ .Capabilities.KubeVersion.Version }}
```

This can be useful when templates need to behave differently depending on Kubernetes capabilities.

---

# 8. Variables ⭐⭐⭐⭐

Helm allows you to define variables.

Syntax:

```text
$variable := value
```

Example:

```yaml
{{- $appName := .Values.name }}
```

Use it:

```yaml
name: {{ $appName }}
```

Variables are especially useful when the same value is needed multiple times inside a template.

---

# 9. `if / else` Conditions ⭐⭐⭐⭐⭐

You can conditionally create configuration.

`values.yaml`:

```yaml
ingress:
  enabled: true
```

Template:

```yaml
{{- if .Values.ingress.enabled }}
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: myapp
{{- end }}
```

If:

```yaml
enabled: true
```

the Ingress is generated.

If:

```yaml
enabled: false
```

the Ingress is not generated.

### `if / else`

```yaml
{{- if .Values.ingress.enabled }}
enabled: true
{{- else }}
enabled: false
{{- end }}
```

# 10. `range` Loop ⭐⭐⭐⭐⭐

`range` is used to iterate over lists or maps.

Example `values.yaml`:

```yaml
ports:
  - 8080
  - 8081
  - 8082
```

Template:

```yaml
ports:
{{- range .Values.ports }}
  - port: {{ . }}
{{- end }}
```

Output:

```yaml
ports:
  - port: 8080
  - port: 8081
  - port: 8082
```

This is useful when you have multiple:

* Ports
* Environment variables
* Volumes
* Hosts
* Configurations

---

# 11. `range` with Objects

Example:

```yaml
env:
  APP_ENV: production
  LOG_LEVEL: info
```

Template:

```yaml
env:
{{- range $key, $value := .Values.env }}
  - name: {{ $key }}
    value: {{ $value | quote }}
{{- end }}
```

Output:

```yaml
env:
  - name: APP_ENV
    value: "production"
  - name: LOG_LEVEL
    value: "info"
```

---

# 12. `with` ⭐⭐⭐⭐

`with` changes the current context to a particular value.

Example:

```yaml
image:
  repository: nginx
  tag: "1.27"
```

Instead of:

```yaml
{{ .Values.image.repository }}
{{ .Values.image.tag }}
```

You can use:

```yaml
{{- with .Values.image }}
repository: {{ .repository }}
tag: {{ .tag }}
{{- end }}
```

Inside the `with` block:

```text
.
```

refers to:

```text
.Values.image
```

---

# 13. Whitespace Control ⭐⭐⭐⭐

Helm templates often use:

```text
{{-
-}}
```

The `-` controls whitespace/newlines.

Example:

```yaml
{{- if .Values.enabled }}
```

and:

```yaml
{{- end }}
```

This helps produce clean YAML.

Be careful with whitespace because incorrect indentation can create invalid Kubernetes YAML.

---

# 14. Pipelines ⭐⭐⭐⭐⭐

A pipeline passes the output of one function to another.

Syntax:

```text
value | function
```

Example:

```yaml
name: {{ .Values.name | quote }}
```

If:

```yaml
name: myapp
```

Output:

```yaml
name: "myapp"
```

Another common example:

```yaml
{{ .Values.labels | toYaml | nindent 4 }}
```

This is extremely common in real Helm Charts.

---

# 15. `include` ⭐⭐⭐⭐⭐

`include` is used to call a named template, usually defined in `_helpers.tpl`.

Example `_helpers.tpl`:

```yaml
{{- define "myapp.name" -}}
{{- .Chart.Name -}}
{{- end -}}
```

Use it:

```yaml
name: {{ include "myapp.name" . }}
```

This helps create reusable template logic.

---

# 16. `default` ⭐⭐⭐⭐

`default` provides a fallback value.

Example:

```yaml
replicas: {{ .Values.replicaCount | default 1 }}
```

If `replicaCount` is not provided, Helm uses:

```text
1
```

Another example:

```yaml
image:
  tag: {{ .Values.image.tag | default "latest" }}
```

---

# 17. `required` ⭐⭐⭐⭐

`required` forces a value to be provided.

Example:

```yaml
image: {{ required "image.repository is required" .Values.image.repository }}
```

If the value is missing, Helm returns an error instead of generating an invalid manifest.

This is useful for mandatory configuration.

---

# 18. `quote`

`quote` adds quotes around a value.

Example:

```yaml
value: {{ .Values.environment | quote }}
```

If:

```yaml
environment: production
```

Output:

```yaml
value: "production"
```

This is commonly used for environment variables.

---

# 19. `toYaml` ⭐⭐⭐⭐⭐

`toYaml` converts a value into YAML format.

Example:

```yaml
resources:
{{- toYaml .Values.resources | nindent 2 }}
```

Values:

```yaml
resources:
  requests:
    cpu: 100m
    memory: 128Mi
```

Output:

```yaml
resources:
  requests:
    cpu: 100m
    memory: 128Mi
```

`toYaml` is one of the most frequently used Helm template functions.

---

# 20. `nindent` ⭐⭐⭐⭐⭐

`nindent` adds indentation and a newline.

Example:

```yaml
labels:
{{- toYaml .Values.labels | nindent 4 }}
```

This is commonly combined with:

```text
toYaml
```

Remember:

```text
toYaml
   ↓
Convert object to YAML

nindent
   ↓
Indent the generated YAML
```

---

# 21. Template Debugging ⭐⭐⭐⭐⭐

Before installing a Chart, render it:

```bash
helm template myapp ./mychart
```

Check the generated Kubernetes YAML.

Validate the Chart:

```bash
helm lint ./mychart
```

Dry-run:

```bash
helm install myapp ./mychart --dry-run --debug
```

These commands are extremely important when troubleshooting templates.

# 22. Complete Example ⭐⭐⭐⭐⭐

### `values.yaml`

```yaml
replicaCount: 3

image:
  repository: nginx
  tag: "1.27"

service:
  port: 80
```

### `templates/deployment.yaml`

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ .Release.Name }}
spec:
  replicas: {{ .Values.replicaCount }}
  selector:
    matchLabels:
      app: {{ .Chart.Name }}
  template:
    metadata:
      labels:
        app: {{ .Chart.Name }}
    spec:
      containers:
        - name: {{ .Chart.Name }}
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
          ports:
            - containerPort: {{ .Values.service.port }}
```

Install:

```bash
helm install myapp ./mychart
```

Helm converts the template into normal Kubernetes YAML.

# 23. Helm Template Flow ⭐⭐⭐⭐⭐

```text
                Chart.yaml
                    │
                values.yaml
                    │
                    ↓
              Helm Templates
                    │
          ┌─────────┴─────────┐
          │                   │
      .Values              .Release
          │                   │
          └─────────┬─────────┘
                    ↓
             Template Engine
                    ↓
          Rendered Kubernetes YAML
                    ↓
             Kubernetes API
```

# Quick Interview Revision ⭐⭐⭐⭐⭐

**Q: What templating language does Helm use?**
→ Go templates.

**Q: How do you access `values.yaml` values?**

```yaml
{{ .Values.replicaCount }}
```

**Q: How do you access the Release name?**

```yaml
{{ .Release.Name }}
```

**Q: How do you access Chart information?**

```yaml
{{ .Chart.Name }}
{{ .Chart.Version }}
```

**Q: How do you conditionally create a resource?**

```yaml
{{- if .Values.ingress.enabled }}
...
{{- end }}
```

**Q: How do you loop over a list?**

```yaml
{{- range .Values.ports }}
...
{{- end }}
```

**Q: What is `include`?**
→ It calls a reusable named template, commonly defined in `_helpers.tpl`.

**Q: What is `toYaml` used for?**
→ Converts a value/object into YAML.

**Q: Why is `nindent` commonly used with `toYaml`?**
→ To correctly indent the generated YAML.

**Q: How do you see the final YAML generated by Helm?**

```bash
helm template myapp ./mychart
```
